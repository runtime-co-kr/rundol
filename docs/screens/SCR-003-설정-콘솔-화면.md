# 설정 콘솔 화면

## 진입

머리말의 설정 단추로 들어온다. 프로젝트가 선택되어 있으면 세 범위가 모두 보이고, 선택되지 않았으면 작업공간 범위만 보인다. 처음 열면 내 브라우저의 모양 항목이 선택되어 있다 — 기록이 남지 않는 항목이므로 실수로 눌러도 되돌릴 것이 없다.

## 사용자 흐름

1. 왼쪽 레일에서 범위와 항목을 고른다. 레일은 항목마다 정책 층인지 표시 층인지를 표시한다.
2. 오른쪽 패널에서 그 항목의 값을 본다. 값마다 어느 계층에서 왔는지가 함께 보인다.
3. 상속받은 값이면 덮는 조작이, 이 범위가 명시한 값이면 되돌리는 조작이 제시된다.
4. 값을 바꾸면 패널 아래 저장 띠가 층에 맞게 바뀐다. 표시 층이면 조용한 띠에 저장, 정책 층이면 강조된 띠에 결정과 함께 저장이다.
5. 표시 층 저장은 그 자리에서 끝난다.
6. 정책 층 저장은 결정을 요구한다. 사유를 적을 자리가 없으므로 결정 화면으로 넘어간다.

## 바인딩

| 화면 요소 | 값의 출처 | 비고 |
|---|---|---|
| 범위 묶음 | 병합 결과의 범위 구분 | 프로젝트 미선택 시 프로젝트 묶음을 감춘다 |
| 범위 저장 성격 표시 | 범위의 기록 여부 | 내 브라우저는 기록 없음, 나머지는 결정으로 남음 |
| 항목 층 표시 | 항목별 층 구분 | 정책과 표시를 형태로 구분한다 |
| 출처 표시기 | 값 단위 출처 정보 | 내장·작업공간·프로젝트 세 단계를 형태와 색 둘로 구분 |
| 덮기·되돌리기 조작 | 계층별 원본의 키 존재 | 값 비교가 아니라 키 존재로 정한다 |
| 저장 띠 | 항목 층 구분과 변경 여부 | 층에 따라 문구와 강조가 다르다 |
| 경계 층 설명 구역 | 경계 층 목록과 사유 | 읽기 전용. 조작 요소를 두지 않는다 |
| 잠긴 선택지 | 상위 계층이 정한 바닥 | 푸는 방향의 선택지를 비활성으로 보인다 |
| 유형별 제약 목록 | 병합된 유형 정의의 제약 종류와 값 | 값을 사람이 읽는 말로 옮긴다 |
| 유형 파생 범위 안내 | 제약 종류 목록과 면제 가능 게이트 목록 | 코드가 가진 목록을 그대로 받는다 |

### 유형 정의에서 화면이 파생되는 범위

유형을 더하면 목록·필터·입력·연결까지는 정의에서 파생된다. 그 이상은 파생되지 않으며, 화면이 그 선을 함께 보인다.

| 파생됨 | 근거가 되는 제약 |
|---|---|
| 목록의 유형 필터 | 유형 정의의 존재 |
| 선언한 필드의 입력 칸 | `fields` |
| 연결 요구에 맞는 문서 선택기 | `requiresLink` |
| 조건부 필수 안내 | `requiredWhen` |

| 파생되지 않음 | 왜 |
|---|---|
| 유형 전용 집계 화면 | 유형의 의미를 알아야 만들 수 있다 |
| 유형별 통계와 차수 회차 표 | 같은 이유 |

이 선을 화면에 적는 이유는 기대를 미리 자르기 위해서다. 적지 않으면 "유형만 추가하면 다 된다"는 기대가 생기고, 그 기대가 깨지는 지점이 사람마다 다르게 나타나 매번 결함으로 신고된다.

제약 종류 목록과 면제 가능 게이트 목록은 화면이 따로 들지 않고 서버가 실어 보낸 것을 쓴다. 화면이 목록을 들면 종류가 늘어날 때 한쪽만 늘고, 그때 사용자는 화면을 믿는다.

## 상태

| 상태 | 뜻 | 진입 조건 |
|---|---|---|
| 항목 선택됨 | 한 항목의 값을 보고 있다 | 레일에서 항목을 골랐다 |
| 편집 중 | 값을 바꿨고 아직 저장하지 않았다 | 값 조작이 있었다 |
| 저장 대기 | 표시 층 저장이 진행 중이다 | 조용한 띠의 저장을 눌렀다 |
| 결정 필요 | 정책 층 저장이 결정을 기다린다 | 강조된 띠의 저장을 눌렀다 |
| 잠김 안내 | 푸는 방향이라 고를 수 없음을 알린다 | 상위 계층 바닥 아래를 골랐다 |

패널을 바꾸는 것은 상태다. 같은 화면이 무엇을 보여줄지가 바뀔 뿐 다른 화면으로 가지 않는다.

## 전이

| 출발 상태 | 무엇이 결정하는가 | 도착 화면 |
|---|---|---|
| 결정 필요 | 정책 층 저장이 계약 변경 결정을 요구함 | SCR-002 |

이 화면을 떠나는 이동은 하나뿐이다. 항목을 고르고 패널이 바뀌는 것은 상태이므로 여기 없다.

## 접근성과 반응형

- 출처 표시기는 세 칸 막대의 채움 개수로 계층을 나타내고 색을 함께 쓴다. 색을 지워도 채움 개수로 읽힌다.
- 레일과 패널은 좁은 폭에서 위아래로 쌓인다. 레일이 먼저 오고 패널이 뒤에 온다.
- 잠긴 선택지는 흐리게만 두지 않고 왜 잠겼는지를 곁에 적는다.
- 저장 띠의 층 구분은 색과 문구 둘로 표현한다. 강조된 띠라도 문구가 무엇이 기록되는지 말한다.
- 표와 파이프 목록은 자기 안에서 가로로 스크롤하며 본문이 가로로 밀리지 않는다.

## 디자인에 없는 것

- 경계 층 항목의 조작. 비활성 항목으로도 두지 않는다.
- 위임 부여와 취소. 되돌릴 수 없는 권한이라 이 화면의 대상이 아니다.
- 정책 변경의 사유 입력. 결정 화면이 갖는다.
- 업무 유형을 편집하는 조작. 정의를 보이기만 하고 고치지 않는다 — 고치는 것은 정책 변경이라 결정 흐름을 함께 태워야 하고, 그 흐름은 저장 띠가 이미 갖고 있으므로 편집 입력이 붙는 시점에 이어 붙인다.
- 유형 전용 집계 화면. 유형의 의미를 알아야 만들 수 있으므로 정의에서 파생되지 않는다.
- 변경 이력 조회. 형상 관리와 결정 원장이 갖는다.

## 기능별 설계 계약

### REQ-060#FN-001

#### 사용자와 진입 조건

- 이 작업공간을 읽을 수 있는 사람이 머리말의 설정 단추로 들어온다.
- 프로젝트 선택 여부가 노출되는 범위 수를 정한다.
- 처음 진입 시 선택 항목은 기록이 남지 않는 항목이다.

#### 표시와 입력

- 표시: 범위 묶음과 그 저장 성격, 항목 목록과 층 구분, 값과 출처 표시기, 층에 맞는 저장 띠, 경계 층 설명 구역, 유형별 제약 목록과 파생 범위 안내.
- 입력: 항목 선택, 값 조작, 덮기, 되돌리기, 저장.
- 출처 표시기는 세 단계를 채움 개수로 나타낸다. 한 칸은 내장, 두 칸은 작업공간, 세 칸은 이 프로젝트다.

#### 상호작용

- 항목을 고르면 패널만 바뀌고 화면은 그대로다.
- 상속받은 값에는 덮기가, 명시한 값에는 되돌리기가 나온다. 두 조작은 결과가 다르므로 같은 자리에 같은 이름으로 두지 않는다.
- 상위 계층이 정한 바닥 아래의 선택지는 누를 수 없고, 곁에 잠긴 이유를 적는다.
- 값이 바뀌면 저장 띠가 층에 맞게 바뀐다. 바뀌지 않았으면 저장 띠를 활성화하지 않는다.

#### 화면 상태와 전이

- 상태는 항목 선택됨, 편집 중, 저장 대기, 결정 필요, 잠김 안내 다섯이다.
- 결정 필요에서만 다른 화면으로 나간다. 나가는 곳은 SCR-002 하나다.
- 저장 대기에서 실패하면 편집 중으로 돌아가고 조작한 값이 남는다. 값을 버리지 않는다.

#### 검증·오류·취소

- 경계 층 값이 파일에 있어 설정 읽기가 거부되면 그 사실과 파일 위치를 알린다. 빈 화면을 보이지 않는다.
- 출처 정보가 없는 항목은 감추지 않고 출처 미상으로 보인다. 감추면 설정이 사라진 것으로 읽힌다.
- 편집 중에 화면을 떠나려 하면 저장하지 않은 값이 있음을 알린다.
- 결정 필요 상태에서 결정을 내지 않고 돌아오면 편집 중으로 복귀하고 값이 남는다.

#### 권한과 접근성

- 노출에는 권한 판정이 없다. 저장 시점에 행위자와 결정 권한을 판정한다.
- 위임받은 클라이언트가 정책 저장을 시도하면 결정 화면이 위임 근거를 함께 보인다.
- 출처 구분과 층 구분과 잠김 표시가 모두 색 외의 단서를 함께 갖는다.
- 좁은 폭에서 레일이 패널 위로 쌓이며 항목 선택이 먼저 읽힌다.

#### 수용 기준

- [ ] 항목이 세 범위로 묶여 보이고 프로젝트 미선택 시 프로젝트 묶음이 감춰진다.
- [ ] 출처 표시기가 색 없이 채움 개수만으로 계층을 구분한다.
- [ ] 상속받은 값과 명시한 값이 서로 다른 조작을 제시한다.
- [ ] 정책 저장이 결정 필요 상태를 거쳐 SCR-002로 나간다.
- [ ] 경계 층 항목이 조작 가능한 형태로 존재하지 않는다.
- [ ] 유형 정의에서 파생되는 것과 파생되지 않는 것이 화면에 함께 적힌다.
