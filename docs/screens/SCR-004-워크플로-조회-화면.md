# 워크플로 조회 화면

## 진입

설정 콘솔의 업무 유형 항목에서 그 유형이 타는 흐름의 이름을 눌러 들어온다. 프로젝트가 선택되어 있어야 하며, 선택되지 않았으면 이 화면으로 오는 길이 없다 — 흐름은 프로젝트가 정의하는 것이라 작업공간 범위에는 볼 것이 없다.

대상 종류와 항목 유형이 진입할 때 정해진다. 한 화면이 한 흐름을 보인다. 여러 흐름을 한 화면에 겹쳐 보이지 않는 이유는 흐름끼리 노드 이름이 겹칠 수 있고, 겹친 이름을 한 그림에 두면 어느 흐름의 노드인지 사람이 되짚어야 하기 때문이다.

읽을 수 있는 사람은 스냅숏을 읽을 수 있는 사람과 같다. 이 화면에 권한 축이 따로 없다.

## 사용자 흐름

1. 설정 콘솔에서 유형을 고르고 그 유형이 타는 흐름의 이름을 누른다.
2. 노드 표와 전이 그림이 함께 보인다. 그림은 표에서 파생한 보조 뷰이고 정본은 표다.
3. 노드 하나를 고르면 그 노드가 서는 스텝과 요구하는 필드와 그 노드로 들어오고 나가는 전환이 곁에 모인다. 고르는 것은 화면을 떠나지 않는다.
4. 전환 하나를 고르면 제목과 사람 승인 여부가 보인다. 왜 승인이 필요한지는 여기서 답하지 않는다 — 그 말은 전환을 실제로 밟을 때 판정이 낸다.
5. 값을 고치려면 정의를 고쳐야 한다. 이 화면은 고치는 자리를 알려 주고 설정 콘솔로 넘긴다.

## 바인딩

| 화면 요소 | 값의 출처 | 비고 |
|---|---|---|
| 흐름 이름과 대상 종류 | 카탈로그의 라벨과 대상 종류 | 라벨이 없으면 식별자를 보인다 |
| 노드 표 | 카탈로그의 노드 표 | 정본. 그림은 여기서 파생한다 |
| 노드의 스텝 | 노드의 `step` | 닫힌 다섯 중 하나. 팀이 달라도 같다 |
| 노드의 완료 유효성 | 노드의 `validity` | 완료 스텝의 노드에서만 보인다 |
| 노드가 요구하는 것 | 노드의 `requires` | 노드 이름을 묻지 않고 이 값으로 보인다 |
| 전이 표와 전이 그림 | 카탈로그의 전환 목록 | 표가 정본이고 그림이 파생이다 |
| 사람 승인 표식 | 전환의 승인 여부 | 참·거짓 하나. 사유는 싣지 않는다 |
| 모든 노드에서 오는 전환 | 전환의 출발 표식 | 노드로 펼치지 않고 그 뜻으로 보인다 |
| 스텝 눈금 | 카탈로그의 스텝 목록 넷 | 화면이 파생하지 않고 받은 것을 쓴다 |
| 출처 표시기 | 카탈로그의 출처 층 | 설정 콘솔과 같은 세 단계 |
| 정의를 고치는 자리 안내 | 출처 층과 정의 파일 이름 | 조작이 아니라 안내다 |

### 이 화면이 답하지 않는 것

노드 표와 전이 그림은 "무엇이 허용되는가"를 보인다. "지금 이 태스크가 갈 수 있는가"는 다른 물음이고 이 화면이 답하지 않는다. 앞엣것은 흐름의 성질이라 항목을 보지 않고 답하지만, 뒤엣것은 항목마다 다르고 막는 규칙을 함께 말해야 한다.

둘을 한 화면에 접으면 흐름을 보러 온 사람이 어느 태스크의 사정을 보게 된다. 그래서 전환에 걸린 규칙은 이 화면에 그리지 않고, 규칙이 있다는 사실도 표식으로 두지 않는다 — 표식만 두면 무엇에 막히는지를 묻게 되고 그 물음의 답이 여기 없다.

## 상태

| 상태 | 뜻 | 진입 조건 |
|---|---|---|
| 불러오는 중 | 스냅숏을 아직 받지 못했다 | 화면에 들어왔다 |
| 노드 선택됨 | 한 노드의 스텝·요구·연결된 전환을 보고 있다 | 표나 그림에서 노드를 골랐다 |
| 전환 선택됨 | 한 전환의 제목과 승인 여부를 보고 있다 | 전이 표나 그림의 간선을 골랐다 |
| 전환 미선언 | 노드만 있고 잇는 선이 없다고 알린다 | 카탈로그에 전환 자리가 비어 있다 |
| 나갈 곳 없음 | 전환 목록이 비어 있다고 알린다 | 카탈로그의 전환 목록이 빈 목록이다 |
| 내장으로 떨어짐 | 이 유형에 배정이 없어 내장을 보고 있다고 알린다 | 카탈로그의 출처가 내장이다 |
| 읽지 못함 | 정의를 읽지 못해 내장을 보고 있다고 알린다 | 카탈로그가 읽기 실패를 함께 실었다 |

노드나 전환을 고르는 것은 상태다. 곁에 붙는 내용이 바뀔 뿐 다른 화면으로 가지 않는다.

전환 미선언과 나갈 곳 없음을 한 상태로 접지 않는다. 앞은 아직 아무 흐름도 선언하지 않은 것이고 뒤는 선언한 결과 나갈 곳이 없는 것이다. 접으면 노드에 이름만 붙여 둔 프로젝트가 자기 태스크가 막혔다고 읽는다.

내장으로 떨어짐과 읽지 못함도 가른다. 앞은 정상이고 뒤는 결함이다. 둘 다 같은 그림을 보이므로, 말로 가르지 않으면 설정을 고쳐 놓고 반영되지 않는 이유를 사람이 알 수 없다.

## 접근성과 반응형

- 전이 그림은 표에서 파생한 보조 뷰이므로 그림을 보지 못해도 표만으로 흐름 전체가 읽힌다. 그림에만 있는 정보를 두지 않는다.
- 스텝은 색만으로 구분하지 않는다. 다섯 스텝은 색과 함께 이름을 적고, 완료의 유효성은 색이 아니라 말로 적는다.
- 사람 승인 표식은 아이콘 하나로 두지 않고 곁에 말을 붙인다.
- 출처 표시기는 세 칸 막대의 채움 개수로 계층을 나타내고 색을 함께 쓴다. 설정 콘솔과 같은 형태를 쓰는 이유는 같은 축이기 때문이다.
- 노드 표와 전이 표는 자기 안에서 가로로 스크롤하며 본문이 가로로 밀리지 않는다.
- 좁은 폭에서는 그림이 표 아래로 내려가고 표가 먼저 온다.

## 디자인에 없는 것

- 워크플로를 편집하는 조작. 비활성 요소로도 두지 않는다 — 정의 변경은 정책 층이라 계약 변경 결정 흐름을 함께 태워야 하는데 Board에 그 자리가 없다. 업무 유형 편집을 뺀 것과 같은 이유이며, 편집 화면은 별도 SCR로 남긴다.
- 노드를 더하거나 지우는 조작. 위와 같다.
- 전환을 밟는 조작. 상태를 바꾸는 것은 항목의 일이라 태스크가 사는 화면이 갖는다.
- 어느 전환이 무엇에 막히는지의 표시. 항목을 보아야 답하는 물음이라 이 화면이 답하지 않는다.
- 진단 코드 목록. 코드는 카탈로그에 실리지 않는다.
- 사람 승인이 필요한 사유 문구. 밟을 때 판정이 내는 말이며 목록에 미리 앉히지 않는다.
- 여러 흐름의 비교. 한 화면이 한 흐름을 보인다.
- 흐름 정의의 변경 이력. 형상 관리와 결정 원장이 갖는다.

## 기능별 설계 계약

### REQ-069#FN-001

#### 사용자와 진입 조건

- 이 작업공간을 읽을 수 있는 사람이 설정 콘솔의 업무 유형 항목에서 흐름 이름을 눌러 들어온다.
- 프로젝트가 선택되어 있어야 한다. 선택되지 않았으면 이 화면으로 오는 길이 없다.
- 대상 종류와 항목 유형이 진입할 때 정해지고, 그 둘이 어느 카탈로그를 볼지를 정한다.

#### 표시와 입력

- 표시: 흐름 이름과 대상 종류, 노드 표, 전이 표, 전이 그림, 고른 노드의 스텝·유효성·요구 필드, 고른 전환의 제목과 승인 여부, 스텝 눈금, 출처 표시기, 정의를 고치는 자리 안내.
- 입력: 노드 고르기, 전환 고르기, 설정 콘솔로 가기. 값을 바꾸는 입력은 없다.
- 노드 이름이 화면 코드에 리터럴로 들어가지 않는다. 노드가 무엇을 요구하는지는 `requires`로 묻는다.

#### 상호작용

- 노드를 고르면 곁의 내용만 바뀌고 화면은 그대로다.
- 표에서 고른 노드는 그림에서도 함께 강조되고 그 반대도 같다. 두 표현이 같은 값을 보이므로 고른 자리가 갈리면 사람은 둘이 다른 것이라고 읽는다.
- 전이 그림의 간선을 고르는 것과 전이 표의 줄을 고르는 것이 같은 상태로 간다.

#### 화면 상태와 전이

- 상태는 일곱이며 표에 적힌 것이 전부다.
- 이 화면을 떠나는 이동은 설정 콘솔로 가는 하나뿐이다.
- 워크플로 revision이 바뀌면 노드 표와 전이를 다시 그린다. 고른 노드가 사라졌으면 선택을 놓는다.
- 태스크만 바뀐 스냅숏에서는 다시 그리지 않는다.

#### 검증·오류·취소

- 이 화면에 입력이 없으므로 검증도 없다.
- 정의를 읽지 못한 경우 화면은 비지 않는다. 내장을 그리고 읽지 못했다는 사실을 함께 말한다 — 비우면 고칠 자리로 가는 길까지 사라진다.
- 스냅숏을 받지 못한 경우 불러오는 중에서 오류로 가고, 다시 읽는 것 말고 다른 조작을 내주지 않는다.
- 취소할 것이 없다.

#### 권한과 접근성

- 스냅숏을 읽을 수 있으면 같은 카탈로그를 본다. 이 화면에 권한 축이 없다.
- 정의를 고칠 권한이 있는 사람과 없는 사람에게 같은 화면을 보인다. 고치는 조작이 여기 없으므로 권한으로 갈릴 것도 없다.
- 그림 없이 표만으로 흐름 전체가 읽힌다.

#### 수용 기준

- [ ] 화면 코드에 노드 이름 리터럴이 없다.
- [ ] 노드 표와 전이 그림이 같은 값을 보이고 고른 자리가 함께 움직인다.
- [ ] 전환 미선언과 나갈 곳 없음이 다른 말로 보인다.
- [ ] 내장으로 떨어짐과 읽지 못함이 다른 말로 보인다.
- [ ] 편집 조작이 비활성 요소로도 존재하지 않는다.
- [ ] 워크플로 revision이 그대로인 스냅숏에서 다시 그리지 않는다.
