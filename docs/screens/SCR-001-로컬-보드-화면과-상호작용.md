# 로컬 보드 화면과 상호작용

## 사용자 목표

사용자는 저장소 파일 구조와 Git 명령을 모두 알지 않아도 오늘 확인할 작업, 프로젝트 문서와 태스크, 책임자, 검토 요청, 임대와 동기화 상태를 한곳에서 파악한다. Board에서 수행한 변경은 canonical file에 반영되고 strict 검증을 통과해야 하며, stale revision이나 다른 Client의 유효 임대가 있을 때 묵시적으로 덮어쓰지 않는다.

## 진입

- CLI에서 `rdl board --project <project-key>`를 실행해 localhost URL로 진입한다.
- 서버는 `127.0.0.1`에만 bind하며 외부 network interface 노출은 지원하지 않는다.
- GET 조회는 local session에서 가능하고 변경 요청은 page에 주입된 `X-Rundol-Token`을 사용한다.
- 첫 snapshot을 읽기 전에 Workspace와 선택 project가 유효해야 한다.
- URL hash는 `project`, `view`, `scope`, `entity`를 보존해 새로고침 후 현재 위치를 복원한다.

## 정보 구조

| 영역 | 주요 화면 | 목적 |
|---|---|---|
| 상단 bar | project switcher, 현재 사용자, 상태, refresh, 설정 | 전역 context와 빠른 상태 이동 |
| 좌측 탐색 | 검색, 문서 유형, 최근 문서, 사람·운영·설정 | entity 탐색과 관리 화면 진입 |
| 중앙 본문 | 홈, 문서, 태스크, 사람, 운영, 설정 | 선택한 업무의 조회·편집 |
| 우측 Context | 속성, 연결 task, revision, task 빠른 편집 | 현재 entity의 보조 정보와 안전한 변경 |
| 알림 | 우측 하단 live status | 저장·동기화·오류 결과 피드백 |

## 핵심 사용자 흐름

### 프로젝트 현황 확인

1. 사용자가 Board에 진입하면 project 목록과 선택 project의 snapshot을 읽는다.
2. 홈은 상태별 task metric, Needs Attention과 최근 문서를 표시한다.
3. 상태 버튼은 Operations로 이동해 sync와 lease 상세를 보여준다.
4. 3초 polling에서 snapshot 영역 revision이 바뀐 경우에만 화면을 다시 렌더링한다.

### 문서 탐색과 편집

1. 사용자가 문서 유형·검색 또는 최근 문서에서 대상을 선택한다.
2. 화면은 title, description, ID, kind, state, owner와 Markdown 본문을 표시한다.
3. Mermaid block은 strict security level로 렌더링하며 실패해도 원문 탐색은 유지한다.
4. 편집을 선택하면 frontmatter를 제외한 본문을 textarea에 연다.
5. 저장 시 조회한 revision과 새 body를 전송한다.
6. 성공하면 최신 snapshot과 revision을 반영한다. `409`이면 최신 내용을 다시 읽고 사용자가 병합 여부를 판단한다.

### 태스크 조회와 변경

1. 사용자는 전체 태스크, 내 작업 또는 내 검토 scope를 선택한다.
2. 내 작업·검토는 상단의 현재 Member가 없으면 선택 안내를 표시한다.
3. 검색, owner와 priority filter를 적용하고 목록 또는 상태 Board로 본다.
4. task 상세에서 완료 조건, 연결 문서, dependency, blocker, 외부 참조와 시간을 확인한다.
5. Context의 status·priority·owner 변경은 debounce 후 revision과 함께 저장한다.
6. 완료 조건 toggle과 새 task 생성도 canonical shard에 저장되며 실패하면 최신 snapshot으로 되돌린다.

### 운영과 동기화

1. 사용자가 상태 또는 Operations를 선택한다.
2. 현재 sync state, ahead·behind, HEAD, Needs Attention 수와 유효 lease를 표시한다.
3. sync 실행 전 진행 메시지를 표시하고 완료 후 snapshot을 새로 읽는다.
4. 실패 시 오류를 표시하며 자동 반복하거나 local change를 숨기지 않는다.
5. remote와 push를 세밀하게 제어해야 할 때 CLI 사용을 안내한다.

## 화면 상태

| 상태 | 진입 조건 | 표시 내용 | 허용 행동 |
|---|---|---|---|
| loading | 최초 project·snapshot 요청 중 | 화면 골격과 상태 확인 문구 | 중복 저장·sync 금지 |
| empty | 문서·task·Client·lease 또는 검색 결과 0건 | 대상별 명확한 빈 상태 문구 | filter 해제, 생성 가능한 영역은 생성 |
| ready | snapshot을 정상 수신 | 최신 entity와 영역별 revision | 조회·편집·sync |
| editing | 문서 editor 또는 task form 활성 | 원본 기준과 저장·취소 action | 입력, 저장, 취소 |
| pending | task Context 변경 debounce·저장 중 | `파일 반영 대기` 상태 | 추가 변경은 병합하고 중복 전송 금지 |
| stale | server revision이 base revision과 다름 | 최신 변경 존재와 재조회 안내 | 최신 내용 확인 후 재적용 |
| validation-error | 입력 또는 strict 검사 실패 | 수정 가능한 구체적 message | 입력 수정, 취소 |
| network-error | localhost request 실패 | 연결·server 상태 오류 | Board process 확인 후 수동 재시도 |
| sync-error | Git 인증·충돌·검증 실패 | 원인을 숨기지 않은 실패 message | Operations 확인, CLI 복구 절차 이동 |
| unauthorized | token 누락·불일치 | local session 오류 | 현재 Board page를 다시 열기 |

## 화면별 빈 상태와 오류 문구

| 화면 | 빈 상태 | 대표 오류 대응 |
|---|---|---|
| 홈 | 조치 필요 항목 또는 최근 문서 없음 | snapshot 실패 시 기존 수치를 최신으로 오인하지 않게 오류 표시 |
| 문서 | 조건에 맞는 문서가 없음 | 저장 실패 시 원문 복원 후 검증 message 표시 |
| 태스크 | 조건에 맞는 태스크가 없음 | 개인 scope에서 Member 미선택이면 선택 안내 |
| 연결 문서·dependency | 연결된 대상이 없음 | missing link는 strict 검사 대상으로 안내 |
| 사람과 역할 | 해당 유형의 등록 정보 없음 | Project Charter 수정 경로 안내 |
| Operations | 유효 임대가 없음 | sync 실패 후 자동 재시도하지 않고 런북 안내 |
| Settings | 등록 Client가 없음 | Client 등록 권한·입력 검증 오류 표시 |

## 동시 수정과 임대

- 모든 문서·task 쓰기는 최신 조회의 base revision을 사용한다.
- `409 Conflict` 응답의 current entity를 표시하고 사용자의 미저장 입력을 즉시 폐기하지 않는다.
- 유효 Lease가 다른 Client에 있으면 소유자와 만료 시각을 보여주고 편집 시작 전 경고한다.
- 임대는 만료 가능한 협업 신호이며 보안 권한으로 표현하지 않는다.
- polling으로 최신 snapshot을 받더라도 현재 입력 중인 form을 묵시적으로 덮어쓰지 않는다.

## 접근성

- 문서의 기본 언어는 한국어이며 구조적 `header`, `nav`, `aside`, `main`, `section`, `dialog`를 사용한다.
- 모든 icon-only button, search, project와 사용자 selector, editor, 완료 조건 toggle에 접근 가능한 이름을 제공한다.
- 저장·오류 message는 `role="status"`와 `aria-live="polite"`로 전달한다.
- dialog가 열리면 focus를 내부 첫 입력으로 이동하고 닫힐 때 실행 button으로 돌려보낸다.
- keyboard만으로 전역 탐색, 문서·task 선택, form 입력, 저장·취소와 Context 닫기가 가능해야 한다.
- 색상만으로 정상·경고·오류를 구분하지 않고 text와 count를 함께 제공한다.
- `aria-pressed`와 native control 상태를 실제 값과 동기화한다.
- Markdown heading·table·link의 읽기 순서를 유지하고 Mermaid 실패 시 대체 원문 또는 설명을 제공한다.

|---|---|---|
| 1051px 이상 | 좌측 탐색·중앙 본문·우측 Context 3열 | 탐색과 Context를 독립적으로 접을 수 있다. |
| 721~1050px | 좌측 탐색·중앙 본문, Context overlay | Context button으로 열고 닫으며 desktop collapse 상태를 제거한다. |
| 720px 이하 | 중앙 단일 열 | 탐색은 왼쪽 drawer, Context는 오른쪽 overlay, table row는 카드형 단일 열이다. |

resize 시 mobile의 열린 Context와 desktop의 접힘 상태가 서로 남아 화면을 가리지 않도록 class를 정리한다. scrim 선택과 Escape key는 열린 drawer·dialog를 닫아야 한다.

## 보안과 안전한 렌더링

- 사용자 text는 HTML escape 후 렌더링하며 Markdown raw HTML과 위험 URL을 실행하지 않는다.
- Mermaid는 `securityLevel: strict`로 실행한다.
- CSP는 self resource만 허용하고 object·frame·base injection을 금지한다.
- session token은 UI에 표시하거나 log·URL·localStorage에 저장하지 않는다.
- server 내부 경로, credential과 Git secret을 일반 사용자 오류에 노출하지 않는다.
- sync는 장시간 걸릴 수 있으므로 진행 상태를 표시하고 동일 요청의 중복 제출을 막는다.

## 디자인에 없는 것

- 원격 다중 사용자 Board와 강한 인증·권한 체계는 제공하지 않는다.
- 실시간 문자 단위 공동 편집, drag-and-drop task status 변경과 offline mutation queue는 현재 범위가 아니다.
- watch process 상태는 현재 snapshot과 완전히 연결되지 않아 `외부 CLI` 안내를 표시한다.
- 64KiB transport limit 때문에 큰 문서는 Board editor 저장이 실패할 수 있으며 CLI 편집 또는 문서 분할이 필요하다.
- delete, force push, tag 변경과 unmanaged skill 강제 교체 같은 파괴적 작업은 Board에서 제공하지 않는다.

## 수용 기준

- [ ] 모든 주요 화면을 mouse와 keyboard만으로 탐색할 수 있다.
- [ ] project 변경과 hash 복원 후 올바른 snapshot을 표시한다.
- [ ] 빈 결과와 오류를 빈 화면이나 성공 상태로 오인하지 않는다.
- [ ] stale revision에서 문서·task를 덮어쓰지 않는다.
- [ ] 문서 저장 실패 시 canonical file을 원본으로 복원한다.
- [ ] task scope, filter, 목록·Board 전환과 현재 Member 기준이 일관된다.
- [ ] 1051px, 1050px, 720px 경계에서 탐색·Context가 본문을 영구히 가리지 않는다.
- [ ] user content가 HTML·Markdown·Mermaid 경로에서 script를 실행하지 않는다.
- [ ] sync·Lease·Needs Attention 상태가 최신 snapshot과 일치한다.
- [ ] light, dark와 system theme에서 text·focus·상태 contrast를 확인한다.
