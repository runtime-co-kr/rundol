# 설치 진단과 복구 런북

## 대상과 책임

| 대상 | 소유자 | 연락·에스컬레이션 |
|---|---|---|
| 로컬 CLI와 PATH | 프로젝트 책임자 | OS·Node 배포판 문제는 환경 관리자 |
| npm package 무결성 | 프로젝트 책임자 | tarball 누락·registry 장애는 릴리스 관리자 |
| Git 원격 접근 | 프로젝트 책임자 | 권한·VPN·CA 문제는 저장소 또는 네트워크 관리자 |
| AI Client 스킬 | 프로젝트 책임자 | unmanaged 파일 교체는 해당 사용자 승인 필요 |

## 사전 확인

1. 현재 shell에서 `where.exe rdl`(Windows) 또는 `command -v rdl`을 실행한다.
2. `node --version`, `npm --version`, `git --version`을 기록한다.
3. CLI가 실행되면 `rdl doctor --json`을 실행하고 JSON 결과를 보존한다.
4. 원격 설치 문제면 credential이 없는 URL 형태로 `rdl doctor --git-url <url> --json`을 실행한다.

정상 최소 버전은 Node.js 14, npm 6, Git 2.20이다. `doctor.summary.errors`가 0이어야 정상이며 warning은 항목별로 판단한다.

## 진단 항목

| check ID | 정상 | 경고·오류 조건 | 확인 위치 |
|---|---|---|---|
| `node` | major 14 이상 | 구버전 또는 실행 불가 | Node 배포판 |
| `npm` | 6.0.0 이상 | 실행 불가·구버전 | npm PATH |
| `git` | 2.20.0 이상 | 실행 불가·구버전 | Git PATH |
| `package` | 필수 package, bin, src, skill 파일 존재 | global package 손상 | `packageRoot` |
| `postinstall` | 선언 없음 | 핵심 설치가 선택 기능과 결합 | package manifest |
| `path` | `rdl` 또는 `rundol` 후보 존재 | 현재 PATH에서 찾지 못함 | global npm prefix |
| `skills` | Codex·Claude·Copilot managed skill hash가 source와 일치 | missing·unmanaged·stale | 각 AI client skill root |
| `workspace` | 현재 경로에서 Workspace 발견 | Workspace 밖이면 info | `workspace.yaml` 탐색 |
| `git-remote` | `git ls-remote --heads` 성공 | auth, HTTP reset, DNS, TLS, not-found | 전달 URL |

## 장애 대응

| 증상 | 확인 | 완화·복구 | 에스컬레이션 |
|---|---|---|---|
| `rdl` 명령 없음 | `npm prefix --global`, global package 파일 | global bin 경로를 PATH에 추가하고 새 shell 시작 | PATH 정책이 잠겨 있으면 환경 관리자 |
| package check error | `doctor.packageRoot`의 누락 파일 | 깨진 package를 제거하고 검증된 tarball/registry에서 clean install | 동일 tarball 재현 시 릴리스 관리자 |
| Node/npm/Git 버전 오류 | 각 `--version` | 공식 배포판으로 최소 버전 이상 설치 | 조직 표준과 충돌 시 환경 관리자 |
| skill missing/stale | `checks.skills.targets` | `rdl skill install` 실행 | unmanaged 대상은 자동 덮어쓰지 말고 사용자와 검토 |
| Git authentication | credential helper, SSH 공개키, repository 권한 | HTTPS PAT/GCM 또는 SSH 권한 복구 | 저장소 관리자 |
| HTTP/2 reset | 같은 URL `git ls-remote` 재현 | 명령 범위에만 `git -c http.version=HTTP/1.1 ...` 사용 | 반복 시 proxy 관리자 |
| DNS | hostname, VPN, proxy | 올바른 네트워크 연결 후 재시도 | 네트워크 관리자 |
| TLS | 인증서 chain과 사내 CA | 신뢰 저장소에 CA 설치 | SSL 검증은 끄지 말고 보안 관리자 |
| repository not found | URL·namespace·읽기 권한 | URL과 권한 수정 | 저장소 관리자 |

Doctor는 URL의 user/password와 알려진 Git token 형태를 `***`로 치환한다. 그래도 출력 공유 전 조직 경로·사용자 이름 등 민감 정보를 검토한다.

## 복구 검증

```powershell
rdl doctor --json
rdl --version
rdl check --strict --project <project-key> --json
```

성공 조건은 doctor errors 0, CLI version 출력 성공, 연결된 프로젝트 strict check errors 0이다. 설치 package 검증에서는 `rdl`, `rundol`, `rundol-node` 세 entry point가 같은 version을 반환해야 한다.

## 롤백

새 package 설치 후 오류가 생기면 마지막으로 검증된 version을 새 clean prefix 또는 기존 global prefix에 다시 설치한다. 사용자 관리 skill 디렉터리는 삭제하거나 강제 교체하지 않는다. Workspace branch나 프로젝트 문서는 설치 복구 대상이 아니므로 reset·삭제하지 않는다.
