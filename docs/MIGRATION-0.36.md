# Rundol 0.36 마이그레이션

이 문서는 `0.35.x`에서 `0.36.0`으로 올릴 때 필요한 작업을 다룬다. **저장 파일을 바꾸는 마이그레이션 명령은 없다.** 바뀌는 것은 없어진 명령과 엔드포인트, 그리고 태스크가 저장하던 필드 하나다.

## 변경 요약

| 항목 | 0.35.0까지 | 0.36.0 |
|---|---|---|
| `rdl lease acquire\|renew\|release\|list` | 동작 | **폐기.** 부르면 근거와 대체 수단을 알리고 중단 |
| `POST/GET /api/projects/:key/leases…` | 동작 | **제거.** `404` |
| 보드 스냅샷의 `leases`·`revision.leases` | 있음 | **제거** |
| 보드 문서 저장 응답의 `leaseNotice` | 겹치면 포함 | **제거** |
| `rdl --help`의 명령 목록 | 전체 | 사람 표면만. 나머지는 `rdl advanced` |
| `rdl advanced` | 없음 | **추가.** 실행 원장·어댑터·검증·결정·위임 등 내부 명령 |
| `rdl task set --link/--unlink` | 없음 | **추가.** 생성 이후 문서 링크 편집 |
| 태스크의 `implementationReadiness` | 생성 시 저장 | **저장하지 않음.** 링크와 문서 계약에서 계산. 남은 값은 읽지 않고 보존 |
| 행위 계측 | `--debug`일 때만 | **항상.** 로그 상한 2MB, 넘치면 오래된 줄부터 버림 |
| 진단 `RDL-IMPL-023` | 있음 | **제거** (저장 필드가 사라져 판정 대상이 없음) |

문서, 태스크, 이벤트 파일은 이 판올림으로 바뀌지 않는다. 이미 쌓인 임대 이벤트도 지우지 않는다.

## 실행할 명령

없다. 다만 아래 둘은 확인이 필요하다.

### 1. 임대를 부르던 자동화가 있으면 고친다

`rdl lease`를 쓰던 스크립트는 실패한다. 실패 메시지가 근거 문서와 대체 수단을 가리킨다.

```
rdl: rdl lease는 폐기되었습니다. 문서 동시 편집은 Git 병합이 판정하며,
     겹치는 작업은 할당 발급 시점에 수정 가능 경로로 걸러집니다. 근거는 ADR-015입니다.
```

보드 임대 엔드포인트를 부르던 외부 도구도 `404`를 받는다. 대체는 저장 시점의 `baseRevision` 비교다 — 낡은 revision으로 저장하면 `409`와 함께 최신 내용이 돌아온다.

### 2. 조용히 건너뛰던 준비도 위반이 드러날 수 있다

`implementationReadiness`는 태스크를 **만들 때 한 번** 저장되고 그 뒤 링크가 바뀌어도 갱신되지 않았다. 그래서 생성 이후 링크를 붙인 태스크는 준비도 게이트가 아예 돌지 않았고, 요구 문서 없이도 완료될 수 있었다.

계산으로 바뀌면서 그 태스크들이 이제 판정을 받는다. `rdl check --strict`가 `RDL-IMPL-020`·`021`·`022`를 새로 낼 수 있다.

**한 번에 여럿이 걸리면 서로를 막을 수 있다.** 태스크 하나를 고치려면 작업공간 검증을 통과해야 하는데, 여러 태스크가 동시에 위반이면 어느 것도 고칠 수 없다. 그때는 이 순서를 따른다.

1. `rdl check --project <key> --strict --json`으로 걸린 태스크를 모두 뽑는다.
2. 진단 메시지가 **어느 문서가 그 기능을 덮는지** 함께 알려준다. 그 문서를 링크에 더한다.
3. 여럿이 서로를 막으면 `--task-enforcement advisory`로 잠시 내리고 고친 뒤 되돌린다.

게이트는 **연결된 문서가 실제로 원자 계약(`implementationContract: atomic-v1`)을 선언했을 때만** 돈다. 그 계약을 쓰지 않는 프로젝트는 0.35.0과 똑같이 동작한다.

## 왜 바뀌었나

### 임대

만료 시각에 기대는 배타는 세 가지가 있어야 성립한다. 참여자가 합의하는 공통 시계, 즉시 관측 가능한 공유 상태, 만료를 판정하는 단일 권위. 중앙 서버 없는 Git 기반 구조에는 셋 다 없다.

그래서 이 기능이 준 것은 보장이 아니라 조언이었는데 명령과 화면은 잠금처럼 보였다. 실사용 이벤트도 한 건에 그쳤고, 그동안 잠금 자체를 관리하다 생긴 결함이 이어졌다. 근거는 [[ADR-015]]에 있다.

문서 동시 편집은 이제 Git 병합이 판정한다. 문서 하나가 파일 하나라 서로 다른 문서를 고치는 편집은 충돌하지 않고, 같은 줄을 동시에 고쳤을 때만 사람이 병합한다. 태스크는 원격 ref 갱신의 성패로 판정하는 push 경합을 그대로 쓴다.

### 명령 표면

사람이 매일 쓰는 명령과 내부 실행 개념이 한 목록에 있으면 사람은 제품이 아니라 구현을 배워야 한다. 이름이나 인수에 실행 식별자·임대·클라이언트 식별자·어댑터·렌즈가 드러나는 명령군을 `rdl advanced`로 내렸다.

**삭제가 아니라 은닉이다.** 내린 명령은 그대로 동작하고 `rdl help --json`은 사람 표면과 고급 표면을 합쳐 돌려준다 — 사람에게 숨기는 것과 에이전트에게 숨기는 것은 다른 판단이다.

### 저장하지 않고 계산하기

`implementationReadiness`는 링크에서 결정되는 값이었다. 저장하면 원본이 바뀌어도 사본이 따라가지 않아 어긋나고, 그때 게이트는 낡은 값으로 판정한다. `REQ-047`이 "저장된 값 중 다른 저장된 값에서 계산되는 것을 없앤다"고 요구한 자리다.

### 계측

재려고 만든 계측이 `--debug`일 때만 돌아서, 평상시 사용은 집계되지 않았다. 기본으로 켜되 로그에 상한을 뒀다 — 로그는 진단이지 정본이 아니므로 오래된 줄부터 버려도 된다.

## 되돌리기

`0.35.x`로 되돌려도 데이터는 그대로다. 이 판올림은 파일 형식을 바꾸지 않는다.

되돌린 뒤 준비도 게이트는 다시 저장된 필드를 보므로, `0.36.0`에서 새로 만든 태스크는 그 필드가 없어 게이트가 돌지 않는다. 게이트가 조용히 꺼지는 상태이지 데이터가 깨지는 것은 아니다.
