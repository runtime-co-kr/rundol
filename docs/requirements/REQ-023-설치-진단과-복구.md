# 설치 진단과 복구

## 배경

전역 설치와 여러 AI 클라이언트 환경에서는 실행 파일, 배포 내용, PATH, 스킬 복사본과 Git 네트워크 문제가 서로 다른 원인으로 실패하므로 분류 가능한 진단이 필요하다.

## 요구사항

- `rdl doctor`는 Node.js, npm, Git, 패키지 필수 파일, postinstall 부재, PATH, 관리 스킬, Workspace를 개별 check로 진단해야 한다.
- 선택한 Git URL은 비대화형 `ls-remote`로 검사하고 인증·HTTP reset·DNS·TLS·not-found를 분류해 복구 지침을 제공해야 한다.
- 스킬 설치는 postinstall과 분리된 명시적 명령이어야 하며 Codex·Claude Code·GitHub Copilot 대상에 관리 표식을 남겨야 한다.

## 사전조건

- doctor를 실행할 Node.js 프로세스와 패키지 루트가 존재해야 한다.
- 원격 진단 시 접근할 Git URL을 명시한다.

## 동작 규칙

1. 최소 버전은 Node.js 14, npm 6, Git 2.20이다.
2. 패키지는 `package.json`, CLI 진입점, 핵심 source와 governance skill 파일을 포함해야 한다.
3. 어떤 package에도 핵심 설치를 막는 `postinstall`을 두지 않고 스킬은 `rdl skill install`로 설치한다.
4. 관리 marker가 없는 기존 스킬은 사용자 관리 대상으로 보존하며 `--force`도 이를 덮어쓰지 않는다.
5. Git HTTP/2 reset은 명령 범위의 HTTP/1.1 fallback을 한 번 시도하고 성공하면 warn으로 보고한다.
6. 결과는 check 배열과 ok/warnings/errors/info 합계를 제공하며 error가 있으면 CLI가 실패 종료한다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 모든 필수 조건 충족 | doctor | errors 0, 정상 요약 |
| 필수 배포 파일 누락 | doctor | package error와 clean install 안내 |
| 스킬 missing/stale/unmanaged | doctor | skills warn와 명시적 설치 안내 |
| Workspace 밖 | doctor | workspace info, 전체 진단은 계속 |
| Git HTTP reset 후 fallback 성공 | remote check | warn과 HTTP/1.1 적용 안내 |
| 인증/DNS/TLS/not-found | remote check | error, 분류별 복구 지침 |

## 수용 기준

- [ ] 정상 fixture의 doctor summary errors가 0이고 package·postinstall·workspace check가 ok다.
- [ ] 설치된 핵심 파일 하나를 제거하면 doctor 자체는 실행되어 package error를 JSON으로 반환한다.
- [ ] 스킬 설치 후 세 클라이언트에 SKILL.md·참조 문서·관리 marker가 존재하고 unmanaged 스킬은 보존된다.
- [ ] 대표 Git 오류 문자열이 지정된 오류 종류로 분류된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 안전성 | 인증 prompt 비활성화, TLS 검증 해제 금지 | remoteCheck 환경·메시지 검사 |
| 진단 독립성 | 일반 명령 모듈 손상 시에도 doctor 실행 가능 | 설치 tarball 손상 테스트 |
| 비파괴성 | unmanaged 사용자 스킬을 덮어쓰지 않음 | 반복 강제 설치 테스트 |

## 기능별 설계 계약

### FN-001

#### 입력

- 선택적 시작 경로와 `gitUrl`; 스킬 설치에는 `force` 옵션과 클라이언트별 환경 경로가 사용된다.

#### 출력

- doctor는 `{ version, platform, arch, home, packageRoot, checks, summary }`; 스킬 설치는 source와 Client별 target 결과를 반환한다.

#### 업무 규칙

- 각 check는 `ok|warn|error|info` 상태와 메시지를 가지며 실패 시 가능한 경우 `required`, `kind`, `detail`, `remediation`을 포함한다.

#### 상태와 전이

- 설치 대상 스킬은 missing/stale → current로 전이할 수 있고 unmanaged는 보존된다. 진단은 외부 상태를 변경하지 않는다.

#### 권한과 승인

- 스킬 대상은 각 Client의 개인 `skills/rundol-project-governance` 경로로 제한하고 경로 이탈을 거절한다.

#### 정상·오류·취소

- 진단 check 실패는 나머지 check를 계속 수집한다. Git reset만 안전한 fallback을 시도하며 그 외 오류는 분류해 반환한다.

#### 감사 기록

- doctor JSON과 설치된 `.rundol-managed.json`의 managedBy·client·skill이 실행 및 관리 근거다.

#### 수용 기준

- `test/doctor.test.js`, `test/install.test.js`, `test/skill-install.test.js`의 환경·손상·명시적 설치·보존 시나리오가 통과한다.
