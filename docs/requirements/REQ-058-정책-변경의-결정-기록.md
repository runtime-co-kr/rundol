# 정책 변경의 결정 기록

## 배경

ADR-020은 정책 층을 자유롭게 열되 익명으로는 못 풀게 하기로 했다. 되돌릴 수 있는 값이므로 막을 근거는 없지만, 누가 언제 무엇을 왜 바꿨는지가 복원되지 않으면 사고 뒤에 남는 것이 없다.

지금 표시 설정 파일은 아무 기록 없이 편집된다. 표시 문구만 담고 있었으므로 그것으로 충분했다. 같은 파일이 정책 값을 담기 시작하면 더는 충분하지 않다.

동시에 모든 변경에 결정을 요구하면 안 된다. 라벨의 오타를 고치는 데도 결정이 필요해지면 결정은 곧 형식이 되고, 형식이 된 결정은 그 안에 담긴 정책 변경까지 함께 가린다. 층을 나눈 이유가 여기서 쓰인다 — 표시 층 변경은 판정에 쓰이지 않으므로 기록을 요구하지 않는다.

## 요구사항

- 정책 필드를 바꾸는 저장은 계약 변경 결정을 요구해야 한다.
- 표시 필드만 바뀌는 저장은 결정을 요구하지 않아야 한다.
- 결정에는 이전 값과 새 값이 함께 담겨야 한다.
- 결정 없이 정책 값을 바꾸는 저장은 거부되어야 한다.

## 사전조건

- 저장하려는 내용과 현재 저장된 내용을 모두 읽을 수 있다.
- 결정 원장이 이 프로젝트에 대해 사용 가능하다.
- 행위 클라이언트가 등록되어 있고 그 소유 구성원을 알 수 있다.

## 동작 규칙

1. 저장 직전에 이전 내용과 새 내용을 필드 단위로 견준다. 정책 필드에 차이가 하나라도 있으면 계약 변경 결정을 요구한다.
2. 차이가 표시 필드에만 있으면 결정을 요구하지 않는다.
3. 결정에는 바뀐 필드마다 이전 값과 새 값을 담는다. "바꿨다"만 남기면 복원할 수 없고, 복원할 수 없는 기록은 기록이 아니다.
4. 결정 없이 정책 값을 바꾸려 하면 저장을 거부하고 어떤 필드가 결정을 요구하는지 알린다.
5. 조이는 변경과 푸는 변경을 모두 기록한다. 방향으로 면제하지 않는다 — 무엇이 조이는 것인지는 값의 의미를 알아야 정할 수 있고, 그 판정을 기록 요구의 조건으로 삼으면 판정이 틀리는 순간 기록이 조용히 사라진다.
6. 계약 변경은 위임할 수 있는 결정 종류다. 위임된 클라이언트가 낸 결정은 행위자와 결정자를 다르게 기록하고, 근거가 된 위임을 함께 가리킨다.
7. 값이 실제로 같으면 차이가 아니다. 같은 값을 다시 적는 저장은 결정을 요구하지 않는다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 표시 필드만 바뀜 | 저장 | 결정 없이 저장된다 |
| 정책 필드가 바뀜, 결정 있음 | 저장 | 저장되고 결정이 원장에 남는다 |
| 정책 필드가 바뀜, 결정 없음 | 저장 | 거부. 결정을 요구하는 필드를 알린다 |
| 정책 필드를 조이는 변경 | 저장 | 푸는 변경과 같이 결정을 요구한다 |
| 같은 값을 다시 적음 | 저장 | 차이가 아니므로 결정을 요구하지 않는다 |
| 위임받은 클라이언트가 결정 | 저장 | 저장된다. 행위자와 결정자가 다르게 기록된다 |
| 위임 없이 다른 구성원 명의로 결정 | 저장 | 거부. 근거가 된 위임이 필요하다 |

## 수용 기준

- [ ] 정책 필드 변경이 결정 없이는 저장되지 않는다.
- [ ] 표시 필드만 바뀌면 결정 없이 저장된다.
- [ ] 결정에 이전 값과 새 값이 함께 담긴다.
- [ ] 조이는 변경도 기록을 요구한다.
- [ ] 같은 값을 다시 적으면 결정을 요구하지 않는다.
- [ ] 위임 없는 대리 결정이 거부된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 실패 방향 | 차이 판정이 애매하면 결정을 요구한다 | 판정 불능 입력에 대한 동작 확인 |
| 기록 완전성 | 기록만으로 이전 상태를 복원할 수 있다 | 기록에서 이전 값을 되읽어 대조 |
| 결정성 | 같은 두 내용이면 언제나 같은 차이 판정 | 반복 호출 결과 비교 |

## 제외 범위

- 결정 종류 카탈로그에 무엇이 있는지는 이 문서가 정하지 않는다. 계약 변경이라는 기존 종류를 쓴다.
- 정책 값 자체의 형태는 PLC-01이 다룬다.
- 병합 결과가 어떻게 계산되는지는 PLC-02가 다룬다. 이 판정은 병합 전의 계층별 내용을 견준다.
- 경계 층 값은 애초에 저장되지 않으므로 이 판정의 대상이 아니다.

## 기능별 설계 계약

### PLC-04

#### 입력

- 저장 전 내용과 저장하려는 내용. 둘 다 같은 계층의 것이다.
- 그룹별 필드 목록. 표시 필드와 정책 필드의 구분을 담는다.
- 행위 클라이언트와 그 소유 구성원, 그리고 제시된 결정이 있으면 그 결정.

#### 출력

- 결정이 필요한지 여부와, 필요하다면 바뀐 필드 목록과 각각의 이전 값과 새 값.
- 결정이 필요한데 없으면 예외.

#### 업무 규칙

- 차이 판정은 정규화된 값끼리 견준다. 키 순서나 공백 차이가 변경으로 보이면 아무것도 바꾸지 않은 저장이 결정을 요구한다.
- 표시 필드와 정책 필드가 함께 바뀌면 정책 쪽만으로 결정 요구를 정한다. 표시 변경이 정책 변경에 묻어가는 것은 문제가 아니다 — 둘 다 같은 저장에 담기고 기록에는 정책 차이가 남는다.
- 결정의 대상은 계층과 그룹까지 특정한다. 어느 계층의 어느 그룹이 바뀌었는지가 기록에 없으면 같은 이름의 항목이 여러 계층에 있을 때 복원이 어긋난다.

#### 상태와 전이

- 차이 판정 자체는 상태를 갖지 않는다.
- 결정 원장에 기록하는 것은 상태를 바꾸며, 그 기록은 되돌리지 않고 새 기록으로만 덮는다.

#### 권한과 승인

- 계약 변경 결정을 낼 수 있는 것은 사람이다. 위임받은 클라이언트는 위임 범위 안에서 대신 낼 수 있고, 그 사실이 기록에 남는다.
- 행위자와 결정자가 다르면 근거가 된 위임이 필요하다. 위임 없는 대리 기록은 형태만으로 거부한다.

#### 정상·오류·취소

- 정상: 결정 불필요이거나, 결정과 함께 저장 성공.
- 오류: 결정이 필요한데 없음. 위임 없는 대리 결정. 둘을 구분해 알린다.
- 취소: 저장 전에 멈추면 아무것도 바뀌지 않는다. 결정만 남고 저장이 안 되는 상태를 만들지 않는다.

#### 감사 기록

- 계약 변경 결정이 원장에 남는다. 바뀐 필드와 이전 값과 새 값과 사유와 결정자와 시각을 담는다.
- 결정이 필요 없던 저장은 기록을 남기지 않는다. 표시 변경의 이력은 형상 관리가 갖는다.

#### 수용 기준

- [ ] 정책 차이가 있으면 결정 요구가 참이다.
- [ ] 표시 차이만 있으면 결정 요구가 거짓이다.
- [ ] 기록에 이전 값과 새 값이 함께 담긴다.
