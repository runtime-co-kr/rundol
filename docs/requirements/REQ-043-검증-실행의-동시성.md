# 검증 실행의 동시성

## 배경

검증은 현재 완전히 순차다. 렌즈 목록과 validator slot을 중첩 루프로 돌면서 각 호출을 기다린다. 저장소 전체에 동시 실행을 쓰는 곳이 하나도 없다.

그래서 판정자를 늘리면 시간이 선형으로 늘어난다. 렌즈 셋에 validator 둘이면 호출이 여섯 번이고, 호출 하나가 수십 초 걸리는 판정자라면 검증 한 번이 분 단위가 된다. [[REQ-042-검증-판정의-독립성|REQ-042]]가 요구하는 독립성은 판정자를 늘려야 얻어지므로, 두 요구는 정면으로 충돌한다. 신뢰를 올리는 대가로 속도를 잃고, 느려진 통제는 꺼진다.

순차로 짜인 것은 게으름이 아니라 재개 설계다. invocation 단계와 살아 있는 프로세스 확인, 결과 재사용 경로가 모두 "어디까지 했는지"가 자명한 순서를 전제로 한다.

다만 기반은 이미 동시 실행을 받는다. 자식 요청 식별자는 순서와 무관한 결정론적 키이고, 이벤트 append는 파일 락으로 이미 직렬화되며, 어댑터 실행은 이미 비동기 spawn이다. 렌즈와 slot은 서로의 결과를 읽지 않는다. 막고 있는 것은 설계가 아니라 루프 하나다.

## 요구사항

- 한 검증 안의 판정 호출은 동시에 실행할 수 있다.
- 동시 실행 수에는 설정 가능한 상한이 있다.
- 일부 호출이 실패해도 나머지 결과는 보존되고, 실패한 것만 다시 시도한다.
- 재개했을 때의 결과가 순차 실행과 같다.
- 리비전 결박은 동시 실행에서도 유지된다.

## 사전조건

- 검증 스텝이 절차에 고정되어 있고 대상 커밋이 pin되어 있다.
- 판정 호출들이 서로의 결과를 입력으로 쓰지 않는다.

## 동작 규칙

- 동시 실행 상한은 설정값이며 기본값을 갖는다. 상한이 없으면 판정자 제공자의 호출 한도와 메모리를 넘긴다.
- 실패를 모아서 받는다. 하나가 실패해도 나머지 호출을 중단하지 않는다.
- 재시도 단위는 자식 요청 키다. 이미 결과가 있는 키는 다시 부르지 않는다.
- 리비전 결박 검사는 읽기이므로 동시에 수행해도 안전하다. 실행 중 대상 커밋이 바뀌면 그 검증 전체가 무효인 것이 계약이며, 동시 실행이 이 성질을 바꾸지 않는다.
- 동시 실행은 판정의 내용을 바꾸지 않는다. 같은 입력에 같은 판정이 나와야 한다.

## 상태와 예외

- 상한을 넘는 요청은 대기하며 순서 보장은 하지 않는다.
- 일부 호출이 실패하면 검증은 미완이며, 성공한 판정은 남아 다음 시도에서 재사용된다.
- 실행 도중 대상 커밋이 바뀌면 검증을 무효로 하고 멈춘다.

## 수용 기준

- 기존 검증 시험이 변경 없이 통과한다.
- 렌즈 셋을 동시에 실행했을 때 총 소요가 순차 합이 아니라 최대치에 가깝다.
- 하나의 호출을 실패시키고 다시 실행하면 성공했던 판정은 다시 호출되지 않는다.
- 동시 실행과 순차 실행의 판정 결과가 같다.

## 비기능 요구

- 동시 실행 상한의 기본값은 보수적이어야 한다. 빠르게 만드는 것보다 호출 한도를 넘지 않는 것이 우선이다.
- 이 문서는 실행 방식만 바꾸며 정족수·pin·재개 계약을 건드리지 않는다. 되돌리기 쉬운 상태를 유지한다.

## 제외 범위

- 저작 병렬. 다른 대상 문서를 동시에 저작하는 것은 [[REQ-044-저작-병렬-실행|REQ-044]]가 나른다.
- 판정자 독립성 정책.

## 기능별 설계 계약

### FN-001

#### 입력

- 실행할 판정 호출 목록과 동시 실행 상한
- 이미 결과가 있는 자식 요청 키 집합

#### 출력

- 판정별 성공·실패 결과와 실패 사유
- 재시도가 필요한 키 목록

#### 업무 규칙

- 동시 실행 수는 상한을 넘지 않는다.
- 이미 결과가 있는 키는 다시 호출하지 않는다.
- 실패는 모아서 반환하며 나머지를 중단하지 않는다.

#### 상태와 전이

- 모든 필수 판정이 결과를 얻으면 검증이 집계 단계로 넘어간다.
- 일부가 실패하면 검증은 미완으로 남고 다음 실행이 실패분만 재시도한다.

#### 권한과 승인

- 동시 실행 상한은 설정에서 정하며 실행 시점 인수로 올릴 수 없다.

#### 정상·오류·취소

- 정상: 모든 호출이 결과를 내고 집계로 넘어간다.
- 오류: 실패한 호출은 사유와 함께 남고 성공분은 보존된다.
- 취소: 취소 신호는 진행 중인 호출 전체에 전달되고, 이미 받은 결과는 버리지 않는다.

#### 감사 기록

- 각 판정은 기존과 동일하게 원장에 남는다. 동시 실행이 기록의 내용을 바꾸지 않는다.

#### 수용 기준

- 위 수용 기준 네 항목이 모두 통과한다.
