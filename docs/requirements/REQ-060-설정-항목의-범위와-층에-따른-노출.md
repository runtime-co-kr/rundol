# 설정 항목의 범위와 층에 따른 노출

## 배경

설정 화면은 지금 세 범위로 나뉘어 있다. 내 브라우저와 이 프로젝트와 작업공간이다. 그 안에 든 항목은 표시 문구와 멤버와 클라이언트뿐이고, 표시 설정 파일이 이미 정의하고 있는 일곱 그룹 중 화면이 붙은 것은 프로필 하나다. 나머지는 파일을 손으로 열어야 바꾼다.

정책 층이 열리면서 이 상태가 문제가 된다. 값이 세 계층에서 합쳐지므로, 합쳐진 결과만 보여주면 사용자는 자기가 무엇을 바꾸는지 알 수 없다. 같은 값이라도 이 범위가 명시한 것과 위에서 내려온 것은 다르게 행동한다 — 앞엣것은 위가 바뀌어도 남고 뒤엣것은 따라 바뀐다. 화면이 둘을 구분해 보이지 않으면 "되돌리기"라는 조작 자체가 성립하지 않는다.

경계 층은 반대 문제다. ADR-020은 그것을 화면에 두지 않기로 했다. 잠긴 항목으로 두면 언젠가 잠금을 푸는 요청을 부르지만, 없는 항목은 그런 요청의 대상이 되지 않기 때문이다. 다만 아무 설명 없이 없으면 사용자는 그것을 결함으로 읽는다.

## 요구사항

- 설정 항목은 범위별로 묶여 노출되어야 한다.
- 항목마다 값의 출처 계층이 함께 제시되어야 한다.
- 이 범위가 명시한 값과 상속받은 값이 구분되어야 한다.
- 경계 층 항목은 목록에 나타나지 않아야 하며, 없는 이유가 화면 어딘가에서 설명되어야 한다.
- 항목이 정책 층인지 표시 층인지가 조작 전에 드러나야 한다.

## 사전조건

- 병합된 설정과 계층별 원본과 출처 정보를 함께 받을 수 있다.
- 현재 프로젝트가 선택되어 있다. 선택되지 않으면 작업공간 범위만 노출한다.

## 동작 규칙

1. 항목을 범위로 묶어 노출한다. 범위는 내 브라우저와 이 프로젝트와 작업공간 셋이다.
2. 각 범위에 그 범위의 저장 성격을 한 번 표시한다. 내 브라우저는 기록이 남지 않고, 나머지 둘은 정책 변경이 결정으로 남는다.
3. 항목마다 값의 출처 계층을 제시한다. 내장 기본값과 작업공간과 프로젝트 셋을 서로 구분되게 보인다.
4. 이 범위가 값을 명시했으면 되돌리는 조작을, 상속받았으면 덮는 조작을 제시한다. 같은 값을 명시하는 것과 상속받는 것을 같은 조작으로 다루지 않는다.
5. 항목이 정책 층인지 표시 층인지를 목록에서 구분한다. 정책 항목의 저장 조작은 결정이 함께 남는다는 것을 누르기 전에 알린다.
6. 경계 층 항목은 어느 범위에도 넣지 않는다. 비활성 상태로도 넣지 않는다.
7. 화면 안에 경계 층 목록과 그것이 설정이 아닌 이유를 읽기 전용으로 둔다. 조작 대상이 아님이 형태로 드러나야 한다.
8. 사용 가능한 범위가 하나뿐이면 나머지 범위는 빈 묶음으로 남기지 않고 감춘다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 항목이 내장 값을 그대로 씀 | 노출 | 출처가 내장. 덮는 조작을 제시 |
| 항목을 작업공간이 덮음 | 노출 | 출처가 작업공간. 프로젝트 범위에서는 덮는 조작을 제시 |
| 항목을 이 범위가 명시함 | 노출 | 출처가 이 범위. 되돌리는 조작을 제시 |
| 항목이 경계 층 | 노출 | 목록에 없음. 읽기 전용 설명 구역에만 이름이 있음 |
| 항목이 정책 층 | 저장 조작 제시 | 결정이 함께 남는다는 것을 조작 전에 표시 |
| 항목이 표시 층 | 저장 조작 제시 | 결정 없이 저장된다는 것을 표시 |
| 프로젝트가 선택되지 않음 | 노출 | 프로젝트 범위를 감추고 작업공간 범위만 노출 |

## 수용 기준

- [ ] 항목이 세 범위로 묶여 노출된다.
- [ ] 항목마다 출처 계층이 구분되어 보인다.
- [ ] 명시한 값과 상속받은 값이 서로 다른 조작을 제시한다.
- [ ] 경계 층 항목이 목록에 없다.
- [ ] 경계 층이 없는 이유가 화면에서 읽힌다.
- [ ] 정책 항목과 표시 항목의 저장 성격이 조작 전에 구분된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 판정 순수성 | 병합 결과와 출처를 값으로 받아 그리며 파일을 읽지 않는다 | 전이 의존 검사 |
| 결정성 | 같은 병합 결과와 출처면 같은 화면 구성 | 반복 렌더 결과 비교 |
| 접근성 | 출처 구분이 색에만 기대지 않는다 | 흑백 렌더에서 구분 가능 여부 확인 |

## 제외 범위

- 정책 값이 어떤 모양으로 저장되는지는 PLC-01이 다룬다.
- 값이 어떻게 합쳐지는지는 PLC-02가 다룬다.
- 저장이 결정을 요구하는 판정은 PLC-04가 다룬다. 이 문서는 그 사실을 조작 전에 알리는 것까지만 다룬다.
- 업무 유형 정의에서 입력 폼이 파생되는 규칙은 업무 유형 엔진이 다룬다.

## 기능별 설계 계약

### CFG-01

#### 입력

- 병합된 설정과 계층별 원본과 값 단위 출처 정보.
- 항목별 층 구분. 어느 항목이 정책이고 어느 항목이 표시인지.
- 경계 층 항목 목록과 각각이 설정이 아닌 이유.
- 현재 선택된 프로젝트. 없을 수 있다.

#### 출력

- 범위별로 묶인 항목 목록. 항목마다 출처 계층과 층 구분과 제시할 조작을 담는다.
- 읽기 전용 경계 층 설명 구역의 내용.

#### 업무 규칙

- 경계 층 목록은 노출 목록을 만들 때 빼는 것이 아니라 애초에 후보에 넣지 않는다. 빼는 방식은 빼기를 잊는 경로를 남긴다.
- 출처 구분은 색과 형태 둘 다로 표현한다. 색만 쓰면 흑백 인쇄와 색각 차이에서 정보가 사라진다.
- 명시 여부는 값 비교가 아니라 계층별 원본의 키 존재로 판정한다. 값 비교로 하면 상위와 같은 값을 명시한 경우를 상속으로 잘못 읽는다.

#### 상태와 전이

- 구성 계산은 상태를 갖지 않는다. 같은 입력이면 같은 목록이다.
- 어떤 범위와 항목이 선택되어 있는지는 화면 상태이며 SCR-003이 다룬다.

#### 권한과 승인

- 노출 자체에 권한 판정이 없다. 저장 시점의 권한과 결정 요구는 PLC-04가 판정한다.

#### 정상·오류·취소

- 정상: 범위별 항목 목록.
- 오류: 출처 정보가 없는 항목이 있으면 그 항목을 감추지 않고 출처 미상으로 표시한다. 감추면 설정이 사라진 것으로 보인다.
- 취소: 없음.

#### 감사 기록

- 노출은 기록을 남기지 않는다. 저장이 남긴다.

#### 수용 기준

- [ ] 경계 층 항목이 후보 목록에서부터 제외된다.
- [ ] 출처 구분이 색 없이도 읽힌다.
- [ ] 상위와 같은 값을 명시한 항목이 상속으로 표시되지 않는다.
