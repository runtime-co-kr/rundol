# 태스크 생성과 샤드 저장

## 배경

태스크는 project branch의 canonical state이며, 복수 client가 작업할 때 단일 파일 충돌을 줄이기 위해 client·segment 샤드로 저장할 수 있다. UI와 CLI는 통합 projection을 읽되 canonical 원본과 동기해야 한다.

## 요구사항

- 새 태스크는 충돌 가능성이 낮은 `TASK-<time><random>` ID와 필수 필드 기본값을 갖는다.
- 다중 project Workspace에서 project 선택은 명시적이어야 한다.
- sharded storage는 정규화된 client ID 경로에 최대 500개씩 저장하고 통합 projection을 생성한다.
- REQ/TST link가 있는 태스크는 `implementationReadiness: atomic-v1`을 갖는다.

## 사전조건

- 대상 Workspace와 project state branch/worktree가 연결되어 있어야 한다.
- CLI 생성은 하나 이상의 수용조건을 제공하고, 다중 project이면 project key를 지정해야 한다.

## 동작 규칙

1. 기본 상태는 `todo`, 우선순위는 `mid`, owner/blocker는 null, 배열과 수용조건은 빈 구조로 초기화한다.
2. `createdAt`, `updatedAt`, `statusChangedAt`은 생성 시점의 같은 ISO 시각으로 시작한다.
3. client ID는 영문 소문자·숫자·하이픈 64자 이하로 정규화하고, 미지정 시 로컬 state에 생성·재사용한다.
4. 샤드는 `<clientId>/<6-digit-segment>.json`으로 정렬하고 현 segment가 가득 차면 다음 segment를 생성한다.
5. canonical 쓰기 후 projection과 strict 구조를 검증하고, 실패하면 원본과 projection을 복원한다.
6. 성공한 생성은 pending operation JSON과 `rdl: create <taskId>` commit을 남긴다.

## 상태와 예외

| 상황 | 사건 | 기대 동작 |
|---|---|---|
| 단일 파일 storage | 생성 | 기존 JSON에 태스크 추가 |
| sharded storage, segment 여유 | 생성 | 마지막 segment에 추가 |
| segment 500개 | 생성 | 다음 6자 segment 생성 |
| 중복 태스크 ID | 읽기/생성 | 오류, 샤드 보존 |
| 검증 실패 | 쓰기 후 | canonical·projection rollback, commit 없음 |

## 수용 기준

- [x] CLI로 생성한 태스크는 규격 ID, project, owner, reviewer, stakeholder, priority, acceptance 필드를 보존한다.
- [x] 1,001개 태스크를 500개 한도로 저장하면 3개 샤드와 1,001개 통합 태스크를 읽을 수 있다.
- [x] 다중 project에서 project 미지정 생성은 실패하고, 지정 시 해당 project에만 저장한다.
- [x] REQ/TST를 연결한 태스크에 atomic-v1 준비도가 자동 설정된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 확장성 | 샤드당 기본 500개, 초과 시 순차 segment | 1,001개 생성 테스트 |
| 원자성 | 검증 실패 시 canonical·projection 원상 복구 | 오류 주입 후 파일 비교 |
| 일관성 | 샤드 통합과 projection의 태스크 집합 일치 | ID 집합 deep equality |

## 제외 범위

- 기존 태스크 상태·owner·acceptance 변경
- legacy single-file store의 명시적 migration 작업

## 기능별 설계 계약

### FN-001

#### 입력

- project key, title, summary, owner, reviewers, stakeholders, priority, links, deps, acceptanceCriteria, blocker, externalRefs, 선택 clientId

#### 출력

- changed, taskId, 완전한 task, commit, 로컬 projection 경로

#### 업무 규칙

- 필수 필드 기본값과 시각을 채우고 project 경계·atomic link를 확정한 뒤 canonical store에 한 번만 추가한다.

#### 상태와 전이

- 미존재에서 초기 작업 대기 상태의 태스크로 생성되며, 생성 중 오류에서는 미존재 상태로 rollback한다.

#### 권한과 승인

- project state branch 쓰기 권한이 필요하고 owner·reviewer·stakeholder ID는 project charter 등록 대상을 참조해야 한다.

#### 정상·오류·취소

- 정상은 샤드·projection·operation·commit을 생성하고, 잘못된 client/project/참조/검증은 모든 파일 변경을 복원한 뒤 실패한다.

#### 감사 기록

- pending operation에 operationId, taskId, baseRevision, op, before, after, createdAt을 남기고 생성 commit으로 고정한다.

#### 수용 기준

- `test/git.test.js`, `test/init.test.js`, `test/features.test.js`의 CLI 필드, project 격리, 1,001개 shard 단언이 통과한다.
