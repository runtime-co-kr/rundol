# 클라이언트 등록과 문서 임대

## 배경

한 사람이 여러 장치나 AI Agent를 사용하고 자동화 Service도 문서와 태스크를 변경할 수 있다. 사람 ID만 기록하면 어떤 실행 주체가 변경을 시작했는지 구분하기 어렵고, 서로 다른 Client가 같은 문서를 동시에 편집하면 Git 병합 단계에서 뒤늦게 충돌을 발견한다.

Workspace에는 사람과 분리된 Client Registry가 필요하다. Client는 등록된 프로젝트 멤버에게 귀속되고, 문서 편집 의도를 짧은 수명의 이벤트로 공유해야 한다. 이 임대는 Git-only 환경에서 충돌 가능성을 줄이는 협업 신호이며 인증·권한이나 강한 잠금을 대체하지 않는다.

## 요구사항

- REQ-006-FR-01: 사용자는 device, agent 또는 service 유형의 Client를 Workspace에 등록할 수 있어야 한다.
- REQ-006-FR-02: 사용자는 등록 Client 목록과 단일 Client의 이름·유형·owner·정책 상태를 조회할 수 있어야 한다.
- REQ-006-FR-03: 사용자는 Client를 활성화하거나 비활성화해 향후 임대 변경 가능 여부를 제어할 수 있어야 한다.
- REQ-006-FR-04: 활성 Client는 등록 owner가 참여하는 프로젝트의 기존 문서에 대해 소프트 임대를 획득·갱신·해제할 수 있어야 한다.
- REQ-006-FR-05: 시스템은 프로젝트별 현재 유효한 문서 임대를 계산해 CLI와 Board에 제공해야 한다.
- REQ-006-FR-06: 임대 변경은 원본 이벤트를 수정하지 않는 append-only Workspace 이벤트로 기록하고 Git commit으로 추적해야 한다.
- REQ-006-FR-07: 시스템은 동일 문서의 중복 임대와 다른 Client의 임대 갱신·해제를 방지해야 한다.
- REQ-006-FR-08: Client Registry와 임대 이벤트의 파일명·필드·참조 무결성을 Workspace 검사에서 검증해야 한다.

## 사전조건

- Client와 임대 기능을 사용하려면 schemaVersion 6 Workspace가 연결되어 있어야 한다.
- Client ID는 영문 소문자, 숫자와 하이픈으로 구성된 유효한 고유 ID여야 한다.
- Client 등록 시 비어 있지 않은 이름, `device|agent|service` 유형과 `MEMBER-###` owner를 제공해야 한다.
- 임대 대상 프로젝트가 Registry에 등록되고 로컬 worktree로 연결되어 있어야 한다.
- Client는 `active` 상태여야 하며 그 owner가 대상 프로젝트의 `project.md`에 등록된 멤버여야 한다.
- 임대 대상 document ID가 프로젝트 헌장 또는 정규 문서에 실제로 존재해야 한다.

## 동작 규칙

1. Client는 사람 자체가 아니라 장치·Agent·Service 실행 주체이며 owner 멤버와 별개의 ID를 가진다.
2. Client 등록 파일은 `projects/workspace/clients/client-<client-id>.yaml`에 저장한다.
3. Client 등록 파일은 schemaVersion, revision, id, name, type, owner, status, registeredAt, registeredBy를 유지해야 한다.
4. 신규 Client의 revision은 1, status는 `active`, registeredBy는 owner로 설정한다.
5. Client 유형은 `device`, `agent`, `service`만 허용하고 상태 검증은 `active`, `disabled`, `retired`를 허용한다.
6. 현재 활성화·비활성화 명령은 status를 `active` 또는 `disabled`로 변경하고 변경 시 revision을 1 증가시킨다.
7. 동일 상태를 다시 설정하면 revision과 Git commit을 변경하지 않는다.
8. Client ID는 인증 수단이나 온라인 presence가 아니며 `active`는 등록 정책상 사용 가능하다는 뜻이다.
9. 임대 이벤트는 project, document, client, member, lease, base revision과 발생·만료 시각을 포함해야 한다.
10. 신규 임대는 5분 후 만료되며 갱신은 같은 lease ID의 만료 시각을 현재로부터 다시 5분 연장한다.
11. release 이벤트는 expiresAt을 null로 기록하고 같은 lease ID의 현재 임대를 종료한다.
12. acquire는 대상 문서에 유효한 임대가 없어야 한다. renew와 release는 요청 Client가 보유한 유효 임대가 있어야 한다.
13. 만료 시각이 현재 이하인 임대는 목록과 충돌 판단에서 활성으로 취급하지 않는다.
14. 이벤트 재생은 occurredAt과 eventId의 결정적 순서로 수행하고 acquire·renew·release 계열 이벤트에서 현재 lease 상태를 계산한다.
15. 임대 이벤트는 `projects/workspace/events/lease-<project>-<client>-<6자리 segment>.jsonl`에 Client별로 append한다.
16. 이벤트 segment는 최대 500건 또는 1MiB 미만까지 사용하고 한도를 넘으면 다음 segment를 만든다.
17. 각 임대 이벤트 저장 후 `rundol/workspace` 브랜치에 commit하며 프로젝트 문서 브랜치에는 임대 상태를 기록하지 않는다.
18. 임대는 편집 충돌 가능성을 알리는 소프트 신호이며 파일 쓰기를 강제로 막거나 소유권을 부여하지 않는다.
19. 실제 로컬·원격 쓰기 권한은 운영체제 권한, Board 세션 토큰과 Git 자격 증명으로 통제한다.
20. Client 등록 파일명과 id, 이벤트 파일명과 project·client 필드가 불일치하면 Workspace 검증 오류로 처리한다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 유효한 신규 Client 입력 | client register | revision 1·active 상태 파일과 Workspace commit을 만든다. |
| 동일 Client ID가 존재함 | client register | 기존 파일을 변경하지 않고 중복 오류를 반환한다. |
| 유형·owner·이름이 잘못됨 | client register | 파일과 commit을 만들지 않고 입력 오류를 반환한다. |
| 등록 Client 존재 | client list·show | 정렬된 목록 또는 단일 Client의 canonical 필드를 반환한다. |
| active Client | disable | status를 disabled로, revision을 1 증가시키고 commit한다. |
| disabled Client | enable | status를 active로, revision을 1 증가시키고 commit한다. |
| 현재와 같은 상태 | enable·disable | changed false를 반환하고 commit을 만들지 않는다. |
| active Client와 유효한 문서 | lease acquire | 새 lease·event ID, base revision과 5분 만료 이벤트를 기록한다. |
| 문서에 다른 활성 임대 존재 | lease acquire | 보유 Client와 만료 시각을 포함한 오류를 반환한다. |
| 같은 Client가 유효 임대 보유 | lease renew | lease ID를 유지하고 새 만료 시각의 renew 이벤트를 기록한다. |
| 다른 Client 또는 만료된 임대 | renew·release | 유효 임대 없음 오류를 반환하고 이벤트를 추가하지 않는다. |
| 같은 Client가 유효 임대 보유 | lease release | release 이벤트를 기록하고 활성 임대 목록에서 제거한다. |
| disabled·retired Client | 임대 변경 | 비활성 Client 오류를 반환하고 이벤트를 추가하지 않는다. |
| Client owner가 프로젝트 멤버가 아님 | 임대 변경 | 프로젝트 멤버 참조 오류를 반환한다. |
| 대상 문서가 없음 | 임대 변경 | document ID를 포함한 오류를 반환한다. |
| 임대 만료 시각 경과 | lease list | 만료 임대를 반환하지 않고 새 acquire를 허용한다. |
| segment 500건 또는 1MiB 도달 | 새 임대 이벤트 | 다음 6자리 segment 파일에 append한다. |
| Client·이벤트 파일 계약 위반 | workspace check | 구조화된 Workspace 오류를 반환한다. |

## 수용 기준

- [ ] device, agent, service Client가 각각 표준 파일명과 필수 필드로 등록된다.
- [ ] 잘못된 ID·유형·owner·빈 이름과 중복 ID가 Workspace 파일을 남기지 않는다.
- [ ] Client list가 파일 열거 순서와 무관하게 ID 순으로 동일한 결과를 반환한다.
- [ ] enable·disable이 revision과 status를 정확히 변경하고 동일 상태 재요청은 새 commit을 만들지 않는다.
- [ ] active 상태가 온라인 또는 인증 성공 상태로 표시되지 않는다.
- [ ] owner가 대상 프로젝트 멤버인 active Client만 실제 문서를 임대할 수 있다.
- [ ] acquire 이벤트가 고유 event·lease ID, 현재 project HEAD와 정확히 5분 후 만료 시각을 기록한다.
- [ ] 동일 문서의 두 번째 활성 임대가 거부되고 기존 임대 이벤트가 보존된다.
- [ ] renew가 같은 lease ID를 유지하고 만료 시각을 갱신한다.
- [ ] release 후 해당 문서가 활성 임대 목록에서 사라지고 다른 Client가 acquire할 수 있다.
- [ ] 다른 Client, disabled Client, 존재하지 않는 Client·문서의 renew·release가 이벤트를 추가하지 않는다.
- [ ] 만료 이벤트가 파일에는 보존되지만 활성 임대 목록과 충돌 판단에서는 제외된다.
- [ ] 이벤트 파일 순서가 달라도 occurredAt·eventId 정렬 후 같은 활성 임대 결과를 만든다.
- [ ] 501번째 이벤트 또는 1MiB를 넘는 이벤트가 다음 segment에 기록된다.
- [ ] 이벤트 append와 Client 상태 변경이 `rundol/workspace` commit으로 추적되고 프로젝트 branch HEAD는 변하지 않는다.
- [ ] Client 파일명·id, type·owner·status와 이벤트 파일명·필드 불일치가 workspace check에서 탐지된다.
- [ ] CLI와 Board가 동일한 Client 및 활성 임대 목록을 반환한다.
- [ ] 임대가 없어도 유효한 OS·Git 권한을 가진 사용자의 파일 읽기는 차단되지 않는다.
- [ ] JSON 결과에서 client, lease, event, expiry, file과 commit 정보를 파싱할 수 있다.
- [ ] Workspace sync 후 다른 환경에서 같은 Registry와 활성 임대 상태를 재구성한다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 일관성 | 이벤트 재생 결과가 파일 시스템 열거 순서와 무관하다. | event 파일·line 입력 순서를 바꾼 fixture 결과를 비교한다. |
| 동시성 안전성 | 동일 문서의 활성 임대가 논리적으로 하나만 계산된다. | 두 Client acquire 이벤트의 순서·동시성 fixture를 검사한다. |
| 추적성 | Client 상태와 임대 수명주기를 Workspace Git 이력에서 재구성할 수 있다. | 임의 시점 commit의 Registry·event replay 결과를 검증한다. |
| 확장성 | 프로젝트당 1만 임대 이벤트의 활성 목록 계산이 일반 환경 2초 이내다. | 20개 이상 segment fixture의 95백분위 시간을 측정한다. |
| 보안 | Client ID와 active status가 인증·권한으로 사용되지 않고 비밀을 저장하지 않는다. | API·CLI 권한 테스트와 Registry·event secret scan을 수행한다. |
| 복구성 | 중간 쓰기 실패가 기존 Client 파일을 손상시키지 않고 append 완료 이벤트만 재생한다. | 원자적 rename·append·commit 실패를 주입하고 이전 hash와 replay를 확인한다. |
| 시간 정확성 | 만료 판단은 ISO 8601 UTC 시각으로 일관되며 경계 시각을 활성으로 보지 않는다. | 고정 clock으로 만료 직전·동일·직후 테스트를 수행한다. |

## 제외 범위

- 사용자 로그인, Client 인증서, API key 발급과 권한 부여를 제공하지 않는다.
- Client의 실시간 온라인 presence, heartbeat, 실행 상태와 원격 제어를 제공하지 않는다.
- 강한 분산 잠금, 문자 단위 공동 편집과 파일 쓰기 차단을 제공하지 않는다.
- 임대만으로 Git push·Board 쓰기 권한을 부여하지 않는다.
- 임대 이벤트의 중앙 서버 합의와 네트워크 partition 중 단일 소유권을 보장하지 않는다.
- 임의 임대 기간 설정, 자동 무한 갱신과 사용자별 우선순위 정책은 현재 제공하지 않는다.
- Client owner 멤버의 조직 계정·고용 상태 관리는 프로젝트 거버넌스 책임으로 둔다.
