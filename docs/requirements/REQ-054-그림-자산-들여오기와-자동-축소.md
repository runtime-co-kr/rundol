# 그림 자산 들여오기와 자동 축소

## 배경

큰 그림을 사람이 매번 줄여서 넣으라고 하면 아무도 그 기능을 안 쓴다. 4000×3000 화면 갈무리를 그대로 넣으면 문서 브랜치가 곧 뒤집히고, 줄이라고만 알리면 사람은 도구를 찾아 나갔다가 돌아오지 않는다.

정본을 자동으로 고치지 않는다는 원칙은 여기서도 유효하다. 이 절차가 손대는 것은 저장소 밖에서 가져오는 파일이며, 이미 정본에 들어간 자산을 뒤에서 바꾸지 않는다. 들여오는 순간이 사람이 그 그림을 정하는 순간이므로, 그때 줄이는 것은 변조가 아니라 들여오기의 일부다.

## 요구사항

- 저장소 밖의 그림을 프로젝트 자산으로 들여올 수 있어야 한다.
- 긴 변이 한계를 넘으면 비율을 지켜 줄여야 한다.
- 줄이지 못하는 형식은 줄인 척하지 않고 왜 못 줄이는지를 알려야 한다.
- 문서에 붙여 넣을 수 있는 형태를 함께 돌려주어야 한다.

## 사전조건

- 들여올 파일이 존재하고 자산 확장자를 가진다.
- 프로젝트가 선택되어 있다.

## 동작 규칙

1. PNG는 내장 zlib으로 디코드·축소·재인코드한다. 외부 의존성을 쓰지 않는다.
2. JPEG는 순수 JavaScript 코덱으로 같은 일을 한다.
3. SVG는 벡터라 줄이지 않는다.
4. GIF와 WebP는 한계를 넘으면 거절한다. LZW와 VP8은 zlib이 닿지 않고, 순수 JavaScript로 감당할 크기가 아니다.
5. 한계 안이면 원본 바이트를 그대로 쓴다. 다시 인코딩하면 손대지 않아도 될 파일이 매번 다른 바이트가 되어 diff가 무의미해진다.
6. 파일명은 소문자·붙임표로 정규화한다. 공백과 대문자가 섞이면 embed와 URL 인코딩에서 갈리고 그 차이는 눈에 안 보인다.
7. 같은 이름이 있으면 덮지 않고 번호를 붙인다. 덮으면 다른 문서가 가리키던 그림이 말없이 바뀐다.
8. 줄인 뒤에도 용량 한계를 넘으면 그 사실과 다음 수를 함께 알린다 — 차원을 줄여도 용량이 준다는 보장은 없다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| PNG가 한계 초과 | 들여오기 | 비율을 지켜 줄이고 저장. `resized: true` |
| JPEG가 한계 초과 | 들여오기 | 같은 처리 |
| 한계 이하 | 들여오기 | 원본 바이트 그대로 저장. `resized: false` |
| GIF·WebP가 한계 초과 | 들여오기 | 거절하고 아무것도 쓰지 않음 |
| 같은 이름이 이미 있음 | 들여오기 | 번호를 붙여 저장 |
| 이미지가 아님 | 들여오기 | 거절하고 무엇을 넣을 수 있는지 알림 |

## 수용 기준

- [ ] 3200×1800 PNG가 긴 변 1600으로 들어가고 비율이 지켜진다.
- [ ] JPEG도 같은 결과를 얻는다.
- [ ] 한계 이하 파일이 재인코딩되지 않는다.
- [ ] 이름이 정규화되고 충돌 시 덮지 않는다.
- [ ] 돌려주는 embed 문자열을 그대로 붙여 넣으면 검사를 통과한다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 의존성 | 네이티브 의존성과 설치 스크립트를 늘리지 않는다 | 릴리즈 검사의 설치 회귀와 네 OS 매트릭스 |
| 축소 시간 | 4K 한 장이 수 초 안에 끝난다 | 3840×2160 기준 측정 |
| 화질 | 상자 필터로 줄여 글자가 뭉개지지 않는다 | 대비가 큰 무늬로 육안 확인 |

## 제외 범위

- 이미 들어온 자산을 나중에 줄이는 일은 하지 않는다. 정본을 뒤에서 바꾸지 않는다는 원칙 때문이다.
- 형식 변환은 하지 않는다. 손실 변환은 사람이 정할 일이다.
- GIF와 WebP의 축소는 이 판에서 다루지 않는다.

## 기능별 설계 계약

### FN-001

#### 입력

- 들여올 파일 경로.
- 프로젝트 키, 쓸 이름(선택), 긴 변 한계(선택, 기본 1600).

#### 출력

- 저장 경로와 이름, 형식, 최종 차원과 바이트, 줄였는지 여부, 원본 차원과 바이트.
- 문서에 붙여 넣을 embed 문자열.
- 줄인 뒤에도 한계를 넘으면 다음 수를 담은 안내.

#### 업무 규칙

- 거절할 때는 아무것도 쓰지 않는다. 반쯤 들여온 상태를 남기면 다음에 다시 넣을 때 이름이 하나 늘어난다.
- 자산은 문서 디렉터리 아래 `assets/` 한 곳에 모인다. 흩어지면 무엇이 쓰이는지 셀 수 없다.

#### 상태와 전이

- 들여오기는 한 번의 쓰기로 끝난다. 중간 상태가 없다.

#### 권한과 승인

- 프로젝트를 고를 수 있는 사람이면 들여올 수 있다. 자산은 문서의 일부이고 문서 편집과 같은 경계를 쓴다.

#### 정상·오류·취소

- 정상: 파일이 만들어지고 embed 문자열이 돌아온다.
- 오류: 형식을 못 줄이거나 이미지가 아니면 예외. 파일은 만들어지지 않는다.
- 취소: 없다.

#### 감사 기록

- 들여오기는 문서 편집 행위로 계측에 기록한다. 자산은 문서의 일부이므로 문서 작업으로 센다.

#### 수용 기준

- [ ] 줄인 결과의 차원이 헤더로 다시 읽어 확인된다.
- [ ] 거절 시 자산 디렉터리에 파일이 생기지 않는다.
- [ ] 계측에 문서 편집으로 남는다.
