# 보드 문서 계획과 표시 설정 요구사항

## 배경

문서 계획 계약은 문서 유형의 상태뿐 아니라 AI가 참고하면 좋은 문맥, 생략 시 흡수 대상과 반드시 남길 구성요소를 제시한다. 추천 문맥을 강제 선행 관계로 모델링하면 작은 프로젝트와 바이브 코딩의 자유도를 해치고 약한 AI가 불필요하게 작업을 중단할 수 있다. 필수 구성요소는 실제 템플릿을 기반으로 추천하되 프로젝트 고유 항목을 자유롭게 추가·삭제할 수 있어야 한다. 문서 유형과 상태의 표시 문구도 화면별로 일관되어야 한다.

## 요구사항

- 모든 정규 문서 유형은 실제 템플릿 Markdown의 2단계 제목에서 파생한 구성요소 카탈로그를 가진다.
- 계약 조회 결과는 UI가 추천값을 구성할 수 있도록 문서 유형, 정책 상태와 템플릿 구성요소 카탈로그를 제공한다.
- 보드 계약 편집기는 AI 추천 문맥을 읽기 전용 안내로 표시하고 강제 선행 그래프를 노출하지 않는다.
- 비활성 문서만 흡수 대상과 필수 구성요소를 편집하며, 사용자는 템플릿 추천 항목을 추가하거나 임의 항목을 입력하고 기존 항목을 삭제할 수 있다.
- 활성 문서에는 허위 placeholder나 불필요한 omission 입력을 표시하지 않는다.
- 문서 유형과 문서 상태의 표시 설정은 내장 기본값, Workspace `board.json`, 프로젝트 `board.json` 순으로 상속한다.
- 표시 설정은 문구, 설명과 정렬 순서만 바꾸며 문서 ID, kind, 저장 경로와 계약 의미를 바꾸지 않는다.
- Rundol 자체 Workspace와 `rundol` 프로젝트가 상속 가능한 `board.json`을 실제로 사용한다.
- Rundol 스킬은 범용 `DESIGN.md`를 정본으로 생성하지 않고 설계 책임을 REQ, SCR, ARC, ADR과 연결 태스크로 분류한다.
- CLI는 기존 `DESIGN.md`를 자동 삭제하지 않고 수동 이전이 필요한 비정본 문서로 경고한다.

## 사전조건

- Workspace와 대상 프로젝트가 정상적으로 연결돼 있어야 한다.
- 프로젝트는 schemaVersion 2 `documentProfile`을 가져야 한다.
- 정규 문서 유형은 PRD, REQ, ARC, SCR, MOD, API, ADR, TST, RUN, GLS로 한정한다.
- 표시 설정 JSON은 schemaVersion 1을 사용하고 알 수 없는 필드는 무시하지 않고 진단한다.

## 동작 규칙

1. 문서 유형별 카탈로그는 대응하는 `docs/templates/<TYPE>.template.md`의 2단계 제목을 순서대로 반영한다.
2. `after`는 비차단 AI 추천 문맥으로만 사용하며 누락이나 순환 때문에 생성·저장·동기화를 막지 않는다.
3. 상태가 `disabled`로 바뀌면 기본 흡수 대상과 구성요소를 자동 제안하되 사용자가 템플릿 추천값 밖의 항목도 추가하고 모든 항목을 삭제·재선택할 수 있다.
4. 상태가 활성으로 바뀌면 omission 편집기는 비활성화하고 저장 payload에서 해당 omission을 제거한다.
5. Workspace 설정은 공통 표시 문구와 순서를 정의하고 프로젝트 설정은 필요한 키만 덮어쓴다.
6. 설정 파일이 없으면 내장 기본값으로 동작하며 잘못된 JSON 또는 지원하지 않는 값은 보드 시작이나 snapshot 조회에서 명확히 실패한다.
7. 계약 저장은 기존 baseRevision과 409 충돌 계약을 유지한다.

## 사용자 흐름

1. 사용자는 보드 설정에서 현재 profile과 강제 수준을 확인한다.
2. 문서 유형의 상태와 읽기 전용 AI 추천 문맥을 확인한다.
3. 문서를 비활성화하면 흡수 대상, 현재 필수 구성요소, 템플릿 추천값과 자유 입력 항목이 나타나며 필요한 내용을 추가·삭제한다.
4. 저장 전 계약 요약과 revision을 확인하고 저장한다.
5. 보드의 사이드바, 최근 문서, 카드와 상세 화면에서 같은 표시 문구를 확인한다.

## 화면 상태

| 상태 | 표시 |
|---|---|
| 활성 문서 유형 | 상태와 비차단 AI 추천 문맥을 표시하고 생략 설정은 숨김 |
| 비활성 문서 유형 | 흡수 대상, 삭제 가능한 구성요소 chips, 자유 입력과 템플릿 추천 buttons 활성 |
| 상속된 표시 설정 | 현재 값과 Workspace/프로젝트 출처를 구분해 표시 |
| 저장 중 | 중복 제출 방지와 진행 메시지 표시 |
| 계약 충돌 | 최신 revision을 다시 읽고 사용자 변경을 덮어쓰지 않음 |
| 설정 오류 | 파일과 잘못된 필드를 포함한 오류 메시지 표시 |

## 입력과 검증

- 정책 상태는 required, recommended, onDemand, disabled 중 하나만 선택한다.
- AI 추천 문맥과 흡수 대상은 정규 문서 유형만 참조한다.
- 필수 구성요소는 비어 있지 않은 문자열이며 중복 없이 저장한다. 템플릿 카탈로그 밖의 프로젝트 고유 항목도 허용한다.
- disabled 문서는 흡수 대상과 한 개 이상의 필수 구성요소 또는 명시적 적용 제외 사유를 가져야 한다.
- `board.json`의 label과 description은 비어 있지 않은 문자열, order는 정수여야 한다.

## 접근성

- 모든 선택 컨트롤은 문서 유형과 목적을 포함한 label을 가진다.
- 추천 button, 추가 입력과 삭제 button은 키보드로 조작 가능하고 현재 선택 상태를 텍스트와 상태 속성으로 함께 전달한다.
- disabled 컨트롤은 비활성 이유를 텍스트로 설명한다.
- 저장 성공과 오류는 기존 `aria-live` 메시지 영역으로 알린다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 활성 유형 | disabled 선택 | 기본 흡수 대상과 템플릿 기반 구성요소를 제안한다. |
| disabled 유형 | 활성 상태 선택 | omission을 payload에서 제거한다. |
| 프로젝트 override 없음 | snapshot 조회 | Workspace 값을 상속한다. |
| Workspace 설정 없음 | snapshot 조회 | 내장 기본값을 사용한다. |
| 잘못된 설정 JSON | snapshot 조회 | 파일 경로와 원인을 포함해 실패한다. |
| stale baseRevision | 계약 저장 | HTTP 409와 현재 계약을 반환한다. |

- [x] 모든 정규 문서 유형에 실제 템플릿 기반 구성요소 카탈로그가 정의된다.
- [x] 보드 계약 편집기에서 AI 추천 문맥을 비차단 안내로 보여주고 흡수 대상과 필수 구성요소를 자유롭게 편집한다.
- [x] 활성 유형에는 실제 값처럼 보이는 placeholder가 나타나지 않는다.
- [x] Workspace와 프로젝트 `board.json`이 결정적으로 병합되고 snapshot에 유효값과 출처가 포함된다.
- [x] 사이드바, 최근 문서, 카드와 상세 화면이 같은 표시 문구를 사용한다.
- [x] Rundol 자체 문서와 태스크가 이 요구사항과 검증 문서로 추적된다.
- [x] 스킬과 CLI가 `DESIGN.md` 비정본 규칙을 안내하고 기존 파일을 안전하게 보존한다.

## 제외 범위

- 문서 계약 자체를 Workspace에서 프로젝트로 상속하는 기능
- 임의 사용자 정의 문서 kind 추가
- 범용 그래프 편집기와 자동 문서 본문 생성

## 기능별 설계 계약

### BRD-01

#### 입력

- 정규 문서 유형과 대응하는 Markdown 템플릿

#### 출력

- 유형별 2단계 제목을 보존한 구성요소 추천 카탈로그

#### 업무 규칙

- 추천값은 템플릿에서 결정적으로 파생하며 프로젝트 사용자는 임의 항목을 추가·삭제할 수 있다.

#### 상태와 전이

- 템플릿이 바뀌면 다음 snapshot부터 추천 카탈로그가 갱신되지만 저장된 omission은 자동 변경하지 않는다.

#### 권한과 승인

- 카탈로그는 읽기 전용이고 omission 저장은 프로젝트 계약 revision 권한을 따른다.

#### 정상·오류·취소

- 존재하는 템플릿은 제목을 반환하고 누락 템플릿은 내장 섹션 기본값을 사용한다.

#### 감사 기록

- 선택된 구성요소는 project.md revision에, 템플릿 변화는 코드 Git 이력에 남는다.

#### 수용 기준

- 모든 정규 유형이 빈 placeholder가 아닌 실제 추천 구성요소 목록을 제공한다.

### BRD-02

#### 입력

- 현재 계약, baseRevision, 정책 상태와 omission 편집값

#### 출력

- 저장된 새 계약 또는 stale revision 409 응답

#### 업무 규칙

- AI 추천 문맥은 읽기 전용이며 disabled 유형에서만 흡수 대상과 구성요소 편집을 활성화한다.

#### 상태와 전이

- 활성↔disabled 전환에 따라 omission 컨트롤을 즉시 활성·비활성화하고 저장 후 snapshot을 다시 읽는다.

#### 권한과 승인

- 모든 POST는 Board session token과 현재 baseRevision을 요구한다.

#### 정상·오류·취소

- 유효 편집은 저장하고 중복·빈 구성요소·stale 요청은 원본을 보존하며 오류를 표시한다.

#### 감사 기록

- 계약 revision과 Git 커밋이 변경 주체의 결과를 보존한다.

#### 수용 기준

- 키보드만으로 상태 선택, 구성요소 추가·삭제와 저장을 수행하고 결과를 aria-live로 확인한다.

### BRD-03

#### 입력

- 내장 기본값, Workspace board.json과 프로젝트 board.json

#### 출력

- 문서 유형·상태별 유효 label, description, order와 각 값의 출처

#### 업무 규칙

- 내장값보다 Workspace, Workspace보다 프로젝트 override를 우선하며 식별자·kind·경로는 바꾸지 않는다.

#### 상태와 전이

- 설정 파일 추가·수정·삭제는 다음 snapshot에서 즉시 유효 설정을 재계산한다.

#### 권한과 승인

- Workspace 설정은 workspace 브랜치, 프로젝트 설정은 해당 프로젝트 브랜치의 소유 경계를 따른다.

#### 정상·오류·취소

- 파일이 없으면 상위 기본값을 사용하고 잘못된 JSON·필드는 파일 경로를 포함해 실패한다.

#### 감사 기록

- 원본 JSON과 병합 출처가 snapshot 및 각 브랜치 Git 이력에 남는다.

#### 수용 기준

- 사이드바, 최근 문서, 카드와 상세 화면이 동일한 유효 표시 문구를 사용한다.

### BRD-04

#### 입력

- 프로젝트 Vault의 DESIGN.md 존재 여부와 documentProfile omission 설정

#### 출력

- 비정본 경고와 수동 이전 후보 또는 정상 구조 결과

#### 업무 규칙

- DESIGN.md를 자동 삭제·이동하지 않고 내용을 REQ·SCR·ARC·ADR·태스크 책임으로 라우팅한다.

#### 상태와 전이

- 사용자가 검토해 정본으로 이전한 뒤 원본을 명시적으로 정리하면 후보가 해소된다.

#### 권한과 승인

- 원본 제거와 내용 분할은 프로젝트 책임자의 수동 승인 대상이다.

#### 정상·오류·취소

- 발견 시 경고만 반환하며 cleanup 무승인 실행으로 파일을 제거하지 않는다.

#### 감사 기록

- 이전 결과는 정본 문서·태스크 링크와 프로젝트 Git 이력으로 추적한다.

#### 수용 기준

- Rundol 스킬과 structure 검사가 DESIGN.md를 새 정본으로 만들지 않고 안전한 이전만 안내한다.

### BRD-05

#### 입력

- 계약 catalog의 atomic-v1 규칙과 계산된 기능 추적성 summary

#### 출력

- Board Settings의 구현 계약 버전, 묶음 금지, 준비 기능 수와 무인덱스 안내

#### 업무 규칙

- Board는 기능 계약을 재계산하지 않고 공용 contract snapshot을 가시화한다.

#### 상태와 전이

- 문서 functionIds와 TST 연결이 바뀌면 다음 snapshot의 준비 수가 갱신된다.

#### 권한과 승인

- 요약은 읽기 전용이며 문서 본문 변경은 기존 document revision API를 사용한다.

#### 정상·오류·취소

- 계약이 유효하면 준비 수를 표시하고 legacy-unconfigured면 구현 요약을 비운다.

#### 감사 기록

- 표시 근거는 정본 문서 frontmatter와 직접 링크에 있고 별도 인덱스 파일을 쓰지 않는다.

#### 수용 기준

- Settings가 `atomic-v1`, 기능별 독립 명세, 계산된 준비 수와 별도 인덱스 없음 문구를 표시한다.
