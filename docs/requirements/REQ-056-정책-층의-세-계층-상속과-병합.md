# 정책 층의 세 계층 상속과 병합

## 배경

표시 설정은 이미 내장 기본값과 작업공간과 프로젝트의 세 계층으로 합쳐진다. 조직 공통 문구를 한 번 정의하고 프로젝트가 필요한 항목만 덮는 구조다.

계약 상속은 그동안 배제되어 있었다. ADR-003이 "작업공간 계약 상속은 도입하지 않는다"고 못박았기 때문이다. ADR-020이 정책 층에 한해 그것을 풀었으므로, 이제 정책 값도 같은 세 계층을 탄다.

순서는 이미 있는 것을 그대로 쓰면 된다. 정해야 하는 것은 병합 판정이다. 표시 필드는 항목 단위로 덮으면 그만이지만 정책 필드는 그렇지 않다. 정책 값에는 목록이 흔하고, 목록을 만났을 때 덮을 것인가 합칠 것인가에 따라 결과가 정반대가 된다. 합치기로 하면 작업공간이 뺀 값을 프로젝트가 되살릴 수 없고, 그때 조직 표준은 더할 수만 있고 뺄 수는 없는 반쪽이 된다.

한 가지 더 있다. 합쳐진 결과만으로는 설정을 편집할 수 없다. 어떤 값이 이 계층에서 덮인 것이고 어떤 값이 위에서 내려온 것인지 구분되어야, 지운다는 뜻과 같은 값으로 덮는다는 뜻이 갈린다.

## 요구사항

- 정책 층 값은 내장 기본값과 작업공간과 프로젝트 순으로 합쳐져야 한다.
- 하위 계층이 선언하지 않은 필드는 상위 값을 그대로 받아야 한다.
- 목록 값은 통째로 덮여야 한다.
- 합쳐진 결과와 함께 각 값의 출처가 계산되어야 한다.

## 사전조건

- 각 계층의 설정 파일이 PLC-01의 판정을 이미 통과했다.
- 프로젝트가 선택되어 있다. 프로젝트가 없으면 두 계층까지만 합친다.

## 동작 규칙

1. 적용 순서는 내장 기본값 → 작업공간 → 프로젝트다. 뒤가 앞을 덮는다.
2. 병합 단위는 항목의 필드다. 하위가 선언한 필드만 덮고, 선언하지 않은 필드는 상위 값을 그대로 받는다.
3. 목록 값은 통째로 덮는다. 원소를 합치지 않는다 — 합치면 상위에서 뺀 원소를 하위가 되살릴 방법이 없고, 조직 표준이 더하기 전용이 된다.
4. 합쳐진 값과 함께 계층별 원본을 그대로 낸다. 값 하나가 어느 계층에서 왔는지, 그리고 이 계층이 그 값을 명시했는지를 구분할 수 있어야 한다.
5. 하위가 상위와 같은 값을 명시적으로 적는 것과 적지 않는 것은 다르게 다룬다. 앞엣것은 상위가 바뀌어도 그대로 남고, 뒤엣것은 상위를 따라 바뀐다.
6. 상속은 정책 층과 표시 층에만 적용한다. 경계 층은 애초에 파일에 저장되지 않으므로 상속 대상이 아니다.
7. 계층 하나가 없으면 없는 대로 건너뛴다. 파일이 없는 것은 위반이 아니라 "덮지 않음"이다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 세 계층 모두 있음 | 병합 | 프로젝트 값이 최종. 출처가 프로젝트로 표시된다 |
| 프로젝트 파일 없음 | 병합 | 작업공간 값이 최종. 출처가 작업공간으로 표시된다 |
| 프로젝트가 필드 하나만 선언 | 병합 | 그 필드만 덮이고 나머지는 상위 값 |
| 작업공간이 목록을 셋으로 두고 프로젝트가 하나로 둠 | 병합 | 최종 목록은 하나. 합쳐서 넷이 되지 않는다 |
| 프로젝트가 상위와 같은 값을 명시 | 상위 값 변경 | 프로젝트 값이 유지된다 |
| 프로젝트가 값을 선언하지 않음 | 상위 값 변경 | 최종 값이 함께 바뀐다 |

## 수용 기준

- [ ] 세 계층이 순서대로 합쳐지고 뒤가 앞을 덮는다.
- [ ] 선언하지 않은 필드가 상위 값을 그대로 받는다.
- [ ] 목록이 통째로 덮이고 원소가 합쳐지지 않는다.
- [ ] 값마다 출처 계층이 함께 나온다.
- [ ] 명시한 값과 상속받은 값이 결과에서 구분된다.
- [ ] 계층 파일이 없어도 위반이 아니다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 판정 순수성 | 각 계층의 내용을 값으로 받아 합치며 파일을 직접 읽지 않는다 | 전이 의존 검사 |
| 결정성 | 같은 세 입력이면 언제나 같은 병합 결과 | 반복 호출 결과 비교 |
| 하위 호환 | 표시 필드만 있는 기존 설정의 병합 결과가 변경 전후로 같다 | 기존 설정에 대한 회귀 비교 |

## 제외 범위

- 각 계층 파일의 저장 형태와 필드 허용 판정은 PLC-01이 다룬다.
- 경계 층 값이 파일에 있을 때의 거부는 PLC-03이 다룬다.
- 병합 결과를 바꾸는 행위의 기록은 PLC-04가 다룬다.
- 화면이 출처를 어떻게 보이는지는 이 문서가 다루지 않는다.

## 기능별 설계 계약

### PLC-02

#### 입력

- 계층별 설정 객체 셋. 내장 기본값은 항상 있고 나머지 둘은 없을 수 있다.
- 그룹별 필드 목록. 어떤 필드가 목록형인지를 포함한다.

#### 출력

- 합쳐진 설정 객체.
- 계층별 원본 객체. 각 계층이 무엇을 명시했는지 그대로 담는다.
- 값 단위 출처 정보. 그룹과 항목과 필드마다 어느 계층에서 왔는지를 담는다.

#### 업무 규칙

- 덮기는 필드 단위이고 목록은 원자값으로 다룬다. 이 둘이 어긋나면 목록이 절반만 덮이는 결과가 나온다.
- 없는 계층은 빈 객체와 같지 않다. 빈 객체는 "아무것도 명시하지 않음"이고 없는 계층도 같은 뜻이므로 결과는 같지만, 출처 계산에서는 그 계층이 존재하지 않았음을 남긴다.
- 병합은 상위를 변형하지 않는다. 같은 상위 객체로 여러 프로젝트를 합칠 수 있어야 한다.

#### 상태와 전이

- 병합은 상태를 갖지 않는다. 같은 입력이면 같은 출력이다.
- 계층 수는 프로젝트 선택 여부로 정해지고 병합 중에 바뀌지 않는다.

#### 권한과 승인

- 병합에 권한 개념이 없다. 읽을 수 있으면 같은 결과를 받는다.

#### 정상·오류·취소

- 정상: 합쳐진 객체와 출처 정보.
- 오류: 그룹이나 필드가 목록에 없을 때. 다만 그 판정은 PLC-01이 이미 했으므로 여기서는 방어적 검사다.
- 취소: 없음.

#### 감사 기록

- 병합은 기록을 남기지 않는다. 파생값이므로 언제든 다시 계산된다.

#### 수용 기준

- [ ] 필드 단위 덮기와 목록 통째 덮기가 함께 성립한다.
- [ ] 출처 정보가 값마다 계층을 지목한다.
- [ ] 상위 객체가 병합으로 변형되지 않는다.
