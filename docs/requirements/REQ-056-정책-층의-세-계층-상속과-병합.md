# 정책 층의 세 계층 상속과 병합

## 배경

표시 설정은 이미 내장 기본값과 작업공간과 프로젝트의 세 계층으로 합쳐진다. 조직 공통 문구를 한 번 정의하고 프로젝트가 필요한 항목만 덮는 구조다.

계약 상속은 그동안 배제되어 있었다. ADR-003이 "작업공간 계약 상속은 도입하지 않는다"고 못박았기 때문이다. ADR-020이 정책 층에 한해 그것을 풀었으므로, 이제 정책 값도 같은 세 계층을 탄다.

순서는 이미 있는 것을 그대로 쓰면 된다. 정해야 하는 것은 병합 판정이다. 표시 필드는 항목 단위로 덮으면 그만이지만 정책 필드는 그렇지 않다. 정책 값에는 목록이 흔하고, 목록을 만났을 때 덮을 것인가 합칠 것인가에 따라 결과가 정반대가 된다. 합치기로 하면 작업공간이 뺀 값을 프로젝트가 되살릴 수 없고, 그때 조직 표준은 더할 수만 있고 뺄 수는 없는 반쪽이 된다.

그런데 "덮을 것인가 합칠 것인가"를 값 전체에 하나로 답하면 반대쪽이 망가진다. 업무 유형처럼 키로 식별되는 항목의 모음을 통째로 덮게 하면, 프로젝트가 유형 하나를 더하려고 작업공간 유형 전부를 다시 적어야 한다. 반대로 정책 상태의 필수 유형 나열처럼 구성 자체가 뜻인 값을 키 단위로 합치면, 작업공간이 뺀 원소를 프로젝트가 되살릴 수 없다. 값의 성질이 둘이므로 규칙도 둘이어야 한다.

표시 설정의 기존 병합이 이미 앞엣것을 그렇게 다루고 있다. 그룹과 키와 필드 세 단계로 합치므로 키를 더하는 것과 항목의 필드 하나만 고치는 것이 모두 된다. 다만 그 방식에는 삭제가 없다. 하위가 상속받은 키를 파일에서 빼면 지워지는 것이 아니라 "선언하지 않음"이 되어 상위 값이 그대로 내려온다. 없애려면 없앤다고 적어야 하고, 그것이 우연이 아니라 설계다 — 없앴다는 판단이 파일에 남아야 나중에 왜 없앴는지 답할 수 있다.

한 가지 더 있다. 합쳐진 결과만으로는 설정을 편집할 수 없다. 어떤 값이 이 계층에서 덮인 것이고 어떤 값이 위에서 내려온 것인지 구분되어야, 지운다는 뜻과 같은 값으로 덮는다는 뜻이 갈린다.

## 요구사항

- 정책 층 값은 내장 기본값과 작업공간과 프로젝트 순으로 합쳐져야 한다.
- 하위 계층이 선언하지 않은 필드는 상위 값을 그대로 받아야 한다.
- 목록 값은 통째로 덮여야 한다.
- 합쳐진 결과와 함께 각 값의 출처가 계산되어야 한다.

## 사전조건

- 각 계층의 설정 파일이 PLC-01의 판정을 이미 통과했다.
- 프로젝트가 선택되어 있다. 프로젝트가 없으면 두 계층까지만 합친다.

## 동작 규칙

1. 적용 순서는 내장 기본값 → 작업공간 → 프로젝트다. 뒤가 앞을 덮는다.
2. 정책 값에는 성질이 다른 둘이 있고 병합 방식도 다르다. 키로 식별되는 항목의 모음은 맵이고, 원소의 구성 자체가 뜻인 나열은 목록이다. 둘을 하나로 다루면 한쪽이 반드시 망가진다 — 맵을 통째로 덮으면 항목 하나를 더하려고 상위 전부를 다시 적어야 하고, 목록을 키 단위로 합치면 상위에서 뺀 원소를 하위가 되살릴 수 없다.
3. 맵은 키 단위로 합치고 항목 안에서는 필드 단위로 덮는다. 하위는 새 키를 더할 수 있고, 기존 키의 필드 하나만 고칠 수 있으며, 선언하지 않은 필드는 상위 값을 그대로 받는다.
4. 목록은 통째로 덮는다. 원소를 합치지 않는다. 조직 표준이 더하기 전용이 되지 않으려면 하위가 뺄 수 있어야 한다.
5. 상속받은 키를 하위가 없애려면 사용 안 함 표식을 명시한다. 맵 병합에는 삭제가 없으므로 키를 빼는 것으로는 지워지지 않는다 — 빼면 "선언하지 않음"이 되어 상위 값이 그대로 내려온다. 이것은 우회가 아니라 설계다. 없앤다는 판단이 파일에 남아야 나중에 왜 없앴는지 답할 수 있고, 정책 상태의 사용 안 함이 이미 같은 뜻으로 쓰이고 있다.
6. 사용 안 함 표식이 붙은 키는 병합 결과에서 지우지 않고 그 표식과 함께 남긴다. 결과에서 없애면 상위에 원래 있었는지, 하위가 없앤 것인지를 화면이 구분할 수 없고, 되돌리는 조작도 걸 자리가 없다.
7. 합쳐진 값과 함께 계층별 원본을 그대로 낸다. 값 하나가 어느 계층에서 왔는지, 그리고 이 계층이 그 값을 명시했는지를 구분할 수 있어야 한다.
8. 하위가 상위와 같은 값을 명시적으로 적는 것과 적지 않는 것은 다르게 다룬다. 앞엣것은 상위가 바뀌어도 그대로 남고, 뒤엣것은 상위를 따라 바뀐다.
9. 상속은 정책 층과 표시 층에만 적용한다. 경계 층은 애초에 파일에 저장되지 않으므로 상속 대상이 아니다.
10. 계층 하나가 없으면 없는 대로 건너뛴다. 파일이 없는 것은 위반이 아니라 "덮지 않음"이다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 세 계층 모두 있음 | 병합 | 프로젝트 값이 최종. 출처가 프로젝트로 표시된다 |
| 프로젝트 파일 없음 | 병합 | 작업공간 값이 최종. 출처가 작업공간으로 표시된다 |
| 프로젝트가 항목의 필드 하나만 선언 | 병합 | 그 필드만 덮이고 나머지는 상위 값 |
| 프로젝트가 맵에 새 키를 더함 | 병합 | 상위 키와 새 키가 함께 남는다 |
| 작업공간이 목록을 셋으로 두고 프로젝트가 하나로 둠 | 병합 | 최종 목록은 하나. 합쳐서 넷이 되지 않는다 |
| 프로젝트가 상속받은 키를 파일에서 뺌 | 병합 | 지워지지 않는다. 상위 값이 그대로 내려온다 |
| 프로젝트가 상속받은 키에 사용 안 함을 명시 | 병합 | 결과에 남되 사용 안 함으로 표시되고 출처가 프로젝트다 |
| 프로젝트가 상위와 같은 값을 명시 | 상위 값 변경 | 프로젝트 값이 유지된다 |
| 프로젝트가 값을 선언하지 않음 | 상위 값 변경 | 최종 값이 함께 바뀐다 |

## 수용 기준

- [ ] 세 계층이 순서대로 합쳐지고 뒤가 앞을 덮는다.
- [ ] 맵에 하위가 새 키를 더하면 상위 키와 함께 남는다.
- [ ] 맵의 항목에서 선언하지 않은 필드가 상위 값을 그대로 받는다.
- [ ] 목록이 통째로 덮이고 원소가 합쳐지지 않는다.
- [ ] 상속받은 키를 파일에서 빼는 것으로는 지워지지 않는다.
- [ ] 사용 안 함을 명시한 키가 결과에 표식과 함께 남는다.
- [ ] 값마다 출처 계층이 함께 나온다.
- [ ] 명시한 값과 상속받은 값이 결과에서 구분된다.
- [ ] 계층 파일이 없어도 위반이 아니다.

| 결정성 | 같은 세 입력이면 언제나 같은 병합 결과 | 반복 호출 결과 비교 |

## 제외 범위

- 각 계층 파일의 저장 형태와 필드 허용 판정은 PLC-01이 다룬다.
- 경계 층 값이 파일에 있을 때의 거부는 PLC-03이 다룬다.
- 병합 결과를 바꾸는 행위의 기록은 PLC-04가 다룬다.
- 화면이 출처를 어떻게 보이는지는 이 문서가 다루지 않는다.

## 기능별 설계 계약

### PLC-02

#### 입력

- 계층별 설정 객체 셋. 내장 기본값은 항상 있고 나머지 둘은 없을 수 있다.
- 그룹별 구조 분류. 그룹이 맵인지, 그리고 항목 안의 어떤 필드가 목록형인지를 담는다. 이 분류는 코드가 갖는다 — 파일이 자기 구조를 선언하면 같은 그룹이 계층마다 다른 방식으로 합쳐질 수 있다.

#### 출력

- 합쳐진 설정 객체.
- 계층별 원본 객체. 각 계층이 무엇을 명시했는지 그대로 담는다.
- 값 단위 출처 정보. 그룹과 항목과 필드마다 어느 계층에서 왔는지를 담는다.

#### 업무 규칙

- 맵은 키 단위로 합치고 항목 안에서 필드 단위로 덮으며, 목록은 원자값으로 다룬다. 이 셋이 어긋나면 목록이 절반만 덮이거나 맵에 항목을 더할 수 없게 된다.
- 사용 안 함 표식은 값이 아니라 항목의 상태다. 값으로 다루면 상위가 그 필드를 갖지 않을 때 표식이 필드 덮기로 흘러들어가 다른 항목까지 물들인다.
- 없는 계층은 빈 객체와 같지 않다. 빈 객체는 "아무것도 명시하지 않음"이고 없는 계층도 같은 뜻이므로 결과는 같지만, 출처 계산에서는 그 계층이 존재하지 않았음을 남긴다.
- 병합은 상위를 변형하지 않는다. 같은 상위 객체로 여러 프로젝트를 합칠 수 있어야 한다.

#### 상태와 전이

- 병합은 상태를 갖지 않는다. 같은 입력이면 같은 출력이다.
- 계층 수는 프로젝트 선택 여부로 정해지고 병합 중에 바뀌지 않는다.

#### 권한과 승인

- 병합에 권한 개념이 없다. 읽을 수 있으면 같은 결과를 받는다.

#### 정상·오류·취소

- 정상: 합쳐진 객체와 출처 정보.
- 오류: 그룹이나 필드가 목록에 없을 때. 다만 그 판정은 PLC-01이 이미 했으므로 여기서는 방어적 검사다.
- 취소: 없음.

#### 감사 기록

- 병합은 기록을 남기지 않는다. 파생값이므로 언제든 다시 계산된다.

#### 수용 기준

- [ ] 맵 키 추가와 필드 단위 덮기와 목록 통째 덮기가 함께 성립한다.
- [ ] 사용 안 함 표식이 항목 상태로 다뤄지고 다른 항목에 번지지 않는다.
- [ ] 출처 정보가 값마다 계층을 지목한다.
- [ ] 상위 객체가 병합으로 변형되지 않는다.
