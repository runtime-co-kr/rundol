# 프로젝트 멤버 등록

## 배경

협업 Client는 `owner`로 `MEMBER-NNN`을 참조하고, 문서 lease는 그 owner가 대상 프로젝트의 등록된 멤버일 때만 성립한다. 따라서 새 사람이 합류하면 Client 등록보다 먼저 프로젝트 멤버가 되어야 하며, 그렇지 않으면 등록과 lease가 모두 거절된다.

지금은 멤버를 추가하는 명령이 없다. 기존 명령은 등록된 멤버의 정보를 고칠 수만 있고 새 블록을 만들지 못하므로, 사람이 `project.md`를 직접 편집하는 방법밖에 없다. 손으로 쓰면 블록 ID 중복, 필수 필드 누락, 존재하지 않는 역할 참조가 검사 단계에 가서야 드러난다.

이 요구는 그 입구를 명령으로 만든다. 멤버 추가는 정본 변경이므로 화면이 아니라 명령줄에서만 수행한다.

## 요구사항

- 명령줄에서 프로젝트에 새 멤버를 추가할 수 있다.
- 추가된 멤버는 charter가 요구하는 다섯 필드를 모두 갖는다.
- 멤버 ID는 자동 채번하되 사용자가 지정할 수도 있다.
- 등록된 역할만 참조할 수 있다.

## 사전조건

- 대상 프로젝트가 연결되어 있고 `project.md`가 존재한다.
- 참조하려는 역할 블록이 `project.md`에 이미 있다.
- 프로젝트 worktree가 자기 branch에 연결되어 있다.

## 동작 규칙

1. 멤버 ID를 지정하지 않으면 기존 `MEMBER-NNN` 중 가장 큰 번호의 다음 값을 세 자리로 채번한다.
2. 이름, 소속, 업무 계정, 책임 영역, 역할을 입력으로 받아 charter 필수 필드 다섯 개를 모두 채운 블록을 만든다.
3. 역할은 하나 이상 지정하며 각각 `project.md`에 존재하는 `ROLE-NNN`이어야 한다.
4. 상태는 항상 `active`로 시작한다.
5. 새 블록은 `프로젝트 팀원` 절의 마지막 멤버 뒤에 넣고 다른 절과 기존 블록은 바꾸지 않는다.
6. 저장 전에 프로젝트 검사를 수행하고 오류가 있으면 파일을 되돌린다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 멤버 3명 등록됨 | ID 없이 추가 | `MEMBER-004`로 채번해 추가한다 |
| `MEMBER-002` 존재 | 같은 ID로 추가 | 중복 ID로 거절하고 파일을 바꾸지 않는다 |
| `ROLE-003` 없음 | 그 역할로 추가 | 존재하지 않는 역할로 거절한다 |
| 필수 입력 누락 | 추가 | 누락 필드를 알리고 거절한다 |
| `프로젝트 팀원` 절 없음 | 추가 | 절을 찾지 못했다고 거절한다 |

## 수용 기준

- [x] 새 멤버 블록이 다섯 필수 필드를 모두 갖고 `rdl check --strict`를 통과한다.
- [x] ID를 지정하지 않으면 다음 번호로 채번한다.
- [x] 중복 ID, 미등록 역할, 필수 입력 누락은 파일을 바꾸지 않고 거절한다.
- [x] 추가 후 그 멤버를 owner로 하는 Client 등록이 성립한다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 무결성 | 실패 시 `project.md`가 원본과 바이트 단위로 같다 | 실패 경로 후 파일 비교 |
| 가독성 | 기존 멤버 블록과 같은 형식으로 기록한다 | 생성 결과 검사 |

## 제외 범위

- 역할, 이해관계자, 책임 매트릭스 정의
- 기존 멤버의 정보 수정과 비활성화
- Board 화면에서의 멤버 추가

## 기능별 설계 계약

### COL-03

#### 입력

`project:string`은 대상 프로젝트 key다. `name:string`은 trim 후 비어 있지 않은 이름이다. `organization:string`은 소속, `account:string`은 업무 계정, `responsibility:string`은 책임 영역이다. `roles:string[]`은 하나 이상의 `ROLE-NNN`이다. `member:string`은 선택 입력이며 주어지면 `^MEMBER-\d{3}$` 형식이어야 한다.

#### 출력

`project`, 배정된 `member` ID, `name`, `roles`, 기록된 `file` 경로, 반영 후 `commit`을 돌려준다.

#### 업무 규칙

멤버 ID는 `MEMBER-` 접두사와 세 자리 숫자로 구성한다. 미지정 시 기존 최대 번호에 1을 더해 채번한다. 역할은 하나 이상이며 각각 `project.md`의 `^ROLE-` 블록으로 존재해야 한다. 다섯 필수 필드는 모두 비어 있지 않아야 한다. 새 블록은 `프로젝트 팀원` 절 안, 마지막 멤버 블록 뒤에 삽입하며 그 절 밖의 내용은 바꾸지 않는다.

#### 상태와 전이

`미등록 -> active`만 허용한다. 이미 존재하는 ID로의 추가는 오류이며 상태 변경이나 비활성화는 이 기능이 다루지 않는다.

#### 권한과 승인

프로젝트 문서 branch의 worktree에서만 수행한다. 별도 승인 절차 없이 명령 실행자가 곧 변경 주체이며, 변경 근거는 Git 이력으로 보존한다.

#### 정상·오류·취소

정상 경로는 블록 삽입, 검사 통과, commit 순으로 진행한다. 중복 ID, 미등록 역할, 필수 입력 누락, `프로젝트 팀원` 절 부재는 파일을 쓰기 전에 거절한다. 삽입 후 검사에서 오류가 나면 원본을 복원하고 commit하지 않는다.

#### 감사 기록

멤버 추가는 프로젝트 branch의 commit 하나로 남으며 누가 언제 어떤 멤버를 추가했는지 Git 이력에서 확인한다. 별도 이벤트 로그를 만들지 않는다.

#### 수용 기준

- 다섯 필수 필드를 갖춘 블록이 `프로젝트 팀원` 절 마지막에 추가된다.
- ID 미지정 시 기존 최대 번호 다음으로 채번한다.
- 중복 ID, 미등록 역할, 빈 필수 입력은 파일을 바꾸지 않고 거절한다.
- 실패 경로 후 `project.md`가 원본과 같다.
- 추가된 멤버를 owner로 지정한 Client 등록이 성공한다.
