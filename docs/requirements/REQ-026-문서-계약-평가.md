# 문서 계약 평가

## 배경

문서 계획 계약의 평가는 [[REQ-010-문서-계획-계약-요구사항|REQ-010]]이 나르던 기능 하나를 문서 1개 = 기능 1개 계약에 따라 분리한 정본이다. 세 표면(CLI, 스킬, Board)이 각자 판단 규칙을 만들면 어느 결과가 정본인지 알 수 없게 되므로, 평가는 공용 evaluator 하나가 수행하고 모든 표면이 그 결과만 사용한다.

## 요구사항

- `rdl contract next`는 모든 미작성 활성 유형을 ready로 반환하고 작성 순서 참고값을 함께 표시하며, blocked는 호환성을 위해 빈 배열로 유지한다. 작성 순서 참고값은 내장 상수에서 계산하며 계약에 저장하지 않는다.
- CLI, 스킬과 Board는 같은 evaluator 결과를 사용하고 별도 판단 규칙을 만들지 않는다.
- 같은 계약과 문서 집합은 같은 평가 JSON을 만든다.
- 평가는 읽기 전용이며 계약 revision과 문서 파일을 바꾸지 않는다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 유효 계약 | 평가 | present, ready, 작성 순서 참고값과 violations를 반환한다. |
| unsupported-schema | 평가 | 오류와 지원 범위를 반환하며 파일은 바꾸지 않는다. |

## 기능별 설계 계약

### FN-001

#### 입력

- 현재 documentProfile과 프로젝트의 정규 문서 집합

#### 출력

- present, ready, 작성 순서 참고값과 violations를 포함한 평가 JSON

#### 업무 규칙

- 작성 순서 참고값은 blocked 선행조건으로 변환하지 않고 같은 입력에는 같은 결과를 반환한다.

#### 상태와 전이

- 문서가 생성되면 present와 ready만 다시 계산하며 계약 revision은 바꾸지 않는다.

#### 권한과 승인

- CLI, 스킬과 Board는 공용 evaluator 결과만 사용하고 별도 판단 규칙을 만들지 않는다.

#### 정상·오류·취소

- 유효 계약은 평가하고 unsupported schema는 오류와 지원 범위를 반환하며 파일은 바꾸지 않는다.

#### 감사 기록

- 평가는 읽기 전용이며 변경 감사는 입력 문서와 계약의 Git 이력으로 추적한다.

#### 수용 기준

- CLI contract 결과와 Board snapshot의 revision·violations가 동일하다.
