# 로컬 보드와 협업 인터페이스

## 배경

Markdown과 JSON 정본은 이식성과 자동화에 적합하지만, 프로젝트 전체 상태를 빠르게 훑거나 태스크를 칸반 형태로 관리하려는 사용자는 파일을 개별적으로 열어야 한다. 책임자, 완료 조건, 문서 연결, 선행 태스크와 Git 상태를 함께 보지 못하면 조치가 필요한 항목을 놓치기 쉽다.

Board는 새로운 데이터베이스가 아니라 Workspace 파일을 읽고 검증된 명령으로 변경하는 localhost 인터페이스여야 한다. IDE·Obsidian·CLI 같은 외부 주체가 파일을 동시에 수정할 수 있으므로, 조회한 revision을 기준으로 쓰고 오래된 변경은 덮어쓰지 않아야 한다.

## 요구사항

- REQ-005-FR-01: 사용자는 등록 프로젝트 목록과 선택 프로젝트의 문서·태스크·사람·Client·임대·Git 상태를 하나의 Workspace UI에서 조회할 수 있어야 한다.
- REQ-005-FR-02: 시스템은 각 데이터 영역의 revision과 통합 snapshot을 제공해 외부 변경 여부를 판별할 수 있어야 한다.
- REQ-005-FR-03: 사용자는 문서를 읽고 명시적 편집 모드에서 본문을 수정할 수 있어야 한다.
- REQ-005-FR-04: 사용자는 태스크를 생성하고 상태·우선순위·담당자·완료 조건 등 지원 필드를 편집할 수 있어야 한다.
- REQ-005-FR-05: 시스템은 담당자 부재, 완료 조건 부재, 검토자 부재, 미완료 선행 태스크, 깨진 문서 연결과 Git 이상을 Needs Attention으로 집계해야 한다.
- REQ-005-FR-06: 사용자는 책임 구조, Client Registry, 문서 소프트 임대와 동기화 상태를 조회·관리할 수 있어야 한다.
- REQ-005-FR-07: 모든 쓰기는 로컬 세션 토큰과 base revision을 검증하고 Core의 동일한 프로젝트 규칙을 적용해야 한다.
- REQ-005-FR-08: 시스템은 IDE·CLI·Obsidian의 외부 파일 변경을 주기적으로 감지해 변경된 영역만 다시 렌더링해야 한다.
- REQ-005-FR-09: UI는 데스크톱과 좁은 화면에서 핵심 탐색·조회·편집 흐름을 제공해야 한다.

## 사전조건

- 유효한 Workspace와 하나 이상의 등록 프로젝트가 로컬 worktree로 연결되어 있어야 한다.
- Board를 실행할 로컬 포트가 사용 가능해야 한다.
- 변경 작업에는 프로젝트 파일·branch에 대한 운영체제 및 Git 쓰기 권한이 있어야 한다.
- 문서·태스크 편집 대상은 최신 snapshot에서 읽은 revision을 가져야 한다.
- owner·reviewer·stakeholder 변경 대상은 해당 프로젝트 헌장에 등록되어 있어야 한다.
- 원격 동기화 작업에는 별도 동기화 요구사항의 remote·인증 사전조건을 충족해야 한다.

## 동작 규칙

1. Board HTTP 서버는 기본적으로 `127.0.0.1`에만 바인딩하고 외부 네트워크 인터페이스에 노출하지 않는다.
2. 서버는 실행마다 충분히 예측하기 어려운 세션 토큰을 만들고 모든 비조회 요청의 `X-Rundol-Token`과 비교해야 한다.
3. 조회 API는 Workspace overview, 프로젝트 목록, 통합 snapshot, 태스크, 문서, 책임 구조, Client, 임대와 sync 상태를 제공한다.
4. 통합 snapshot은 workspace, tasks, documents, people, clients, leases, sync 영역별 revision을 포함해야 한다.
5. 태스크와 문서 엔티티는 내용에서 계산한 안정적인 revision을 제공해야 한다.
6. 문서·태스크 수정 요청은 조회 시 받은 `baseRevision`을 요구한다. 현재 revision과 다르면 `409 Conflict`와 최신 엔티티를 반환하고 파일을 변경하지 않는다.
7. 문서 편집은 frontmatter를 수정하지 않고 본문만 교체하며 UTF-8 크기 512KB를 초과하거나 프로젝트 루트 밖의 경로를 거부한다.
8. 문서 저장 후 프로젝트 전체 strict 검사를 실행하고 실패하면 원본 파일을 복원한다.
9. 태스크 생성·편집은 CLI와 같은 입력 정규화, 담당자 참조, 상태·완료 조건 검증과 Git commit 흐름을 사용한다.
10. UI의 낙관적 태스크 변경은 500ms 동안 병합할 수 있으며 실패 시 최신 snapshot을 다시 읽어 화면을 원본 상태로 되돌린다.
11. snapshot revision이 이전 값과 다를 때만 영향받는 화면과 context를 다시 렌더링한다. 기본 외부 변경 감지 주기는 3초다.
12. Needs Attention은 저장된 정본에서 파생하며 별도 상태로 저장하지 않는다.
13. 문서 렌더링은 Markdown과 Mermaid를 지원하되 HTML·스크립트 입력을 정화하고 안전 모드로 실행해야 한다.
14. Client의 `active`는 등록 정책 상태이며 온라인 presence로 표시하지 않는다. Client ID를 인증 수단으로 사용하지 않는다.
15. 문서 임대는 충돌 위험을 알리는 소프트 임대이며 편집을 강제로 잠그지 않는다.
16. 데스크톱은 Navigation, Main content, Context 3영역을 제공하고 720px 이하에서는 Navigation과 Context를 drawer로 전환한다.
17. Home은 전체 태스크·문서·검토 요청·조치 필요 수치와 Needs Attention을 우선 보여준다.
18. 문서는 검색·유형·목록에서 탐색하고 읽기 화면에 typed metadata, 연결 태스크와 검증 revision을 표시한다.
19. 태스크는 목록과 상태별 Board를 제공하고 검색·상태·담당자 필터를 동일 logical task store에 적용한다.
20. Board가 종료되어도 정본 파일과 Git commit은 유지되며 메모리 index는 재시작 시 재생성한다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 유효한 Workspace | `rdl board --project <key>` | localhost 서버를 시작하고 선택 프로젝트 snapshot을 표시한다. |
| 프로젝트를 지정하지 않고 하나만 등록됨 | board 실행 | 유일한 프로젝트를 자동 선택한다. |
| 여러 프로젝트가 등록됨 | 프로젝트 switch | 선택 프로젝트의 모든 snapshot 영역과 navigation을 갱신한다. |
| 올바른 token 없음 | POST 요청 | `403`을 반환하고 파일·Git 상태를 변경하지 않는다. |
| 존재하지 않는 프로젝트·문서·태스크 | 조회 요청 | `404`와 식별 가능한 오류를 반환한다. |
| 최신 base revision | 유효한 문서·태스크 수정 | strict 검증 후 정본과 commit을 갱신하고 최신 엔티티를 반환한다. |
| 오래된 base revision | 수정 요청 | `409`와 최신 엔티티를 반환하고 기존 변경을 덮어쓰지 않는다. |
| 문서 본문이 512KB 초과 | 저장 요청 | `400`을 반환하고 원본을 보존한다. |
| 문서 편집이 strict 검사 실패 | 저장 요청 | 원본 파일을 복원하고 검증 오류를 반환한다. |
| 태스크 담당자가 프로젝트에 없음 | 생성·수정 | `400`을 반환하고 태스크를 변경하지 않는다. |
| 외부 도구가 파일 변경 | 다음 polling cycle | 관련 revision 차이를 감지하고 최신 snapshot으로 화면을 갱신한다. |
| 낙관적 태스크 저장 실패 | API 오류 | pending 표시를 해제하고 snapshot을 다시 읽어 UI를 되돌린다. |
| 담당자·완료 조건·연결 문제 존재 | Home 조회 | 원인과 severity를 가진 Needs Attention 항목을 표시한다. |
| Git 충돌 상태 | Operations·Home 조회 | sync 상태와 error severity 조치 항목을 표시한다. |
| 좁은 화면 | Navigation·Context 열기 | Main content를 유지하며 각 panel을 독립 drawer로 표시한다. |
| Board 프로세스 재시작 | 같은 Workspace 접속 | 파일과 Git 정본에서 동일 엔티티·revision을 재구성한다. |

## 수용 기준

- [ ] Board 서버가 loopback 주소에서만 요청을 수신한다.
- [ ] 실행마다 생성된 token과 다른 모든 POST 요청이 `403`이며 정본 hash와 HEAD가 변하지 않는다.
- [ ] overview와 project switch가 Registry에 등록된 전체 프로젝트를 일관되게 표시한다.
- [ ] 통합 snapshot에 문서·태스크·사람·Client·임대·sync와 영역별 revision이 포함된다.
- [ ] 문서 목록·검색·상세 읽기에서 ID, 유형, 상태, owner, description과 본문을 확인할 수 있다.
- [ ] 최신 revision의 유효한 문서 본문 편집이 frontmatter를 byte 단위로 보존한다.
- [ ] 오래된 revision, 512KB 초과, 프로젝트 밖 경로와 strict 검사 실패가 원본을 변경하지 않는다.
- [ ] 태스크 생성이 제목과 하나 이상의 완료 조건을 요구하고 프로젝트 정본에 commit된다.
- [ ] 태스크 상태·우선순위·owner 편집이 revision을 사용하고 실패 시 UI와 파일을 되돌린다.
- [ ] 미등록 owner·reviewer·stakeholder 입력이 거부된다.
- [ ] 담당자·완료 조건·검토자·선행 태스크·문서 링크·Git 문제 fixture가 기대 severity의 Attention 항목을 만든다.
- [ ] Attention 목록에서 태스크 또는 Operations 상세 화면으로 이동할 수 있다.
- [ ] 외부 CLI로 문서·태스크를 변경하면 3초 이내 snapshot revision 차이가 감지된다.
- [ ] 변경되지 않은 polling 응답은 현재 편집·선택 상태를 불필요하게 다시 렌더링하지 않는다.
- [ ] Markdown의 위험한 HTML·스크립트가 실행되지 않고 Mermaid가 strict security level로 렌더링된다.
- [ ] Client active 상태가 온라인 presence로 표현되지 않고 쓰기 권한은 token·Git 권한으로 제한된다.
- [ ] 임대 만료·갱신·해제가 조회 결과에 반영되지만 임대가 없어도 파일 읽기는 가능하다.
- [ ] Operations에서 HEAD, ahead·behind, 변경·충돌 상태를 확인하고 명시적으로 refresh·sync를 실행할 수 있다.
- [ ] 720px 이하에서 Navigation과 Context drawer로 주요 조회·편집 흐름을 완료할 수 있다.
- [ ] 서버 재시작 후 메모리 상태 없이도 동일 Workspace snapshot을 재구성한다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 보안 | 외부 bind와 token 없는 쓰기, 경로 이탈, 저장된 script 실행을 허용하지 않는다. | 네트워크 bind·403·path traversal·XSS 통합 테스트를 실행한다. |
| 동시성 안전성 | 오래된 문서·태스크 쓰기가 최신 변경을 덮어쓰지 않는다. | 두 revision의 동시 편집 fixture에서 두 번째 요청이 409인지 확인한다. |
| 응답성 | 1천 태스크·1천 문서 snapshot의 로컬 응답이 일반 환경 1초 이내다. | 표준 대규모 fixture에서 20회 측정한 95백분위 값을 사용한다. |
| 접근성 | 키보드로 navigation, dialog, 목록, 편집과 저장을 수행하고 상태를 텍스트로 구분할 수 있다. | 키보드 시나리오와 자동 접근성 검사를 수행한다. |
| 반응형 | 360px 이상 viewport에서 가로 페이지 유실 없이 주요 기능을 사용할 수 있다. | 360·720·1050·1440px 시각 회귀 테스트를 수행한다. |
| 복구성 | UI·서버 실패가 정본 손실로 이어지지 않고 재시작 시 상태를 재구성한다. | 저장 단계 실패 주입과 프로세스 재시작 후 파일·HEAD·snapshot을 비교한다. |
| 일관성 | CLI와 Board가 같은 validation·task store·sync 결과를 사용한다. | 동일 입력을 CLI와 API로 실행한 정본·진단 결과를 비교한다. |

## 제외 범위

- 인터넷에 공개되는 원격 Board 호스팅과 다중 사용자 웹 서비스는 제공하지 않는다.
- Client ID를 사용자 인증, 온라인 presence 또는 권한 역할로 사용하지 않는다.
- 문자 단위 실시간 공동 편집과 강한 문서 잠금은 제공하지 않는다.
- 범용 Markdown WYSIWYG, 바이너리 첨부 편집과 오피스 문서 렌더링은 제공하지 않는다.
- 파일·Git 외 별도 Board 데이터베이스를 정본으로 만들지 않는다.
- 조직별 dashboard KPI와 임의 위젯 빌더는 제공하지 않는다.
- Git 자격 증명 설정과 remote 서비스 계정 관리는 제공하지 않는다.
