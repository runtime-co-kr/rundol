# 태스크 상태와 완료 전환

## 배경

태스크 완료는 단순 status 변경이 아니라 수용조건, TST 증거, 기능별 atomic 계약이 충족됐음을 보증해야 한다. waiting과 review 또한 대기 대상과 검토 증거를 명시해야 한다.

하지 않기로 결정한 태스크를 담을 상태도 필요하다. `done`으로 닫으면 완료 게이트가 수용조건과 TST 증거를 요구하므로 애초에 통과할 수 없고, 통과시키려 게이트를 우회하면 기록이 "완료"로 남아 뒤에 읽는 사람이 그 산출물을 찾아 나선다. 반려는 완료의 하위 사례가 아니라 별개의 종료 사유이므로 별도 상태로 둔다.

## 요구사항

- 태스크 상태는 `todo`, `doing`, `waiting`, `review`, `done`, `cancelled`만 허용한다.
- 필드 변경은 실제 차이가 있을 때만 저장·operation·commit을 생성한다.
- acceptance 전환은 지정 ID의 `done`만 변경하고 기존 문구를 보존한다.
- `done`은 모든 수용조건 완료, TST link, 연결된 atomic REQ/TST 계약 충족 후에만 허용한다.
- `cancelled`는 완료 게이트를 적용하지 않는 대신 반려 사유를 필수로 요구한다.
- `done`과 `cancelled`는 종료 상태이며 선행 태스크로서 후행 태스크를 더 이상 막지 않는다.

## 사전조건

- 대상 taskId가 선택 project store에 존재해야 한다.
- acceptance 변경 시 acceptanceId가 해당 태스크에 존재해야 한다.

## 동작 규칙

1. `doing`, `review`, `done`, `cancelled`는 등록된 owner를 필수로 한다.
2. `waiting`은 `waitingFor`, `condition`, `since`를 갖춘 blocker를 필수로 하고, 다른 상태는 blocker를 허용하지 않는다.
3. `review`는 PR 또는 검토 대상 externalRef를 하나 이상 요구한다.
4. `done`은 미완료 acceptance가 없고 TST 문서를 연결해야 한다.
5. REQ/TST 연결 task의 `done`은 `implementationReadiness: atomic-v1`과 연결 문서의 완전한 기능별 계약을 검증한다.
6. status 변경 시 `statusChangedAt`과 `updatedAt`을, 기타 변경 시 `updatedAt`만 갱신한다.
7. `cancelled`는 `reason`, `decidedBy`, `at`을 갖춘 cancellation을 필수로 하고, 다른 상태는 cancellation을 허용하지 않는다.
8. `cancelled`에는 규칙 4와 5의 완료 게이트를 적용하지 않는다. 미완료 수용조건은 하지 않기로 한 범위를 그대로 남긴다.
9. `cancelled`로 전환할 때 blocker가 남아 있으면 같은 변경에서 제거한다.

## 상태와 예외

| 현재/목표 상태 | 조건 | 기대 동작 |
|---|---|---|
| 임의→doing | owner 없음 | 오류, rollback |
| 임의→waiting | 완전한 blocker | 전환 허용 |
| waiting→기타 | blocker 잔존 | 오류, blocker 제거 요구 |
| 임의→review | externalRefs 없음 | 오류 |
| 임의→done | acceptance/TST/atomic 미충족 | 오류, 이전 상태 보존 |
| 임의→cancelled | 완전한 cancellation | 전환 허용, 완료 게이트 미적용 |
| 임의→cancelled | 사유 없음 | 오류, rollback |
| cancelled→기타 | cancellation 잔존 | 오류, cancellation 제거 요구 |
| 동일 값 재설정 | 차이 없음 | `changed: false`, commit 없음 |

- [x] 초안 문구가 남은 atomic REQ/TST 연결 task는 done 전환이 차단된다.

- [x] 같은 status·owner를 다시 설정하면 `changed: false`를 반환한다.
- [x] 미완료 수용조건과 TST link가 없는 태스크도 사유를 갖추면 cancelled로 전환된다.
- [x] 사유 없는 cancelled 전환과 cancellation이 남은 상태 복귀는 차단된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 무결성 | 검증 실패 시 canonical·projection·commit 부분 변경 없음 | 실패 전후 task deep equality |
| 멱등성 | 동일 변경은 새 operation·commit을 만들지 않음 | `changed: false` 단언 |

- 외부 PR의 실제 승인 상태 조회

## 기능별 설계 계약

### FN-001

#### 입력

- project key, taskId, 변경할 필드 집합 또는 acceptanceId와 done boolean

#### 출력

- changed, taskId, before, after, commit, projection; 변경 없음은 현재 commit

#### 업무 규칙

- JSON 값이 다른 필드만 변경하고 상태별 필수 관계와 done atomic gate를 strict 검증한다.

#### 상태와 전이

- 초기 대기, 진행, 외부 대기, 검토, 완료, 반려 여섯 상태 사이 전이를 허용하되 각 목표 상태의 owner·blocker·externalRef·cancellation·completion gate를 만족해야 한다. 완료와 반려는 종료 상태이며 서로 다른 게이트를 갖는다.

#### 권한과 승인

- project state branch 쓰기 권한과 등록된 owner/reviewer/stakeholder 참조가 필요하며 done은 수용조건과 독립 TST 계약이, cancelled는 결정자와 사유가 승인 근거다.

#### 정상·오류·취소

- 정상은 변경·projection·operation·commit을 만들고, 태스크/수용조건 미존재와 게이트 위반은 rollback하며, 동일 값은 무변경으로 종료한다. 반려는 오류가 아니라 기록되는 결정이므로 사유와 결정자를 남기고 정상 종료한다.

#### 감사 기록

- operation의 baseRevision·before·after·createdAt, `rdl: update`와 task ID·변경 필드를 조합한 commit, status 시각을 보존한다.

#### 수용 기준

- `test/action.test.js`, `test/git.test.js`, `test/check.test.js`, `test/implementation-contract.test.js`의 acceptance, idempotency, done gate, task diagnostic 단언이 통과한다.
