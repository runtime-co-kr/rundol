# 조회 인덱스와 무인덱스 경로

## 배경

프로젝트 상태를 알려면 지금은 파일을 뒤져야 하고, 그 비용이 세션마다 반복된다. [[ADR-010-조회-인덱스와-이력-조회의-경계|ADR-010]]은 정본에서 파생한 조회 계층을 두되 그것을 삭제 가능한 캐시로 유지하기로 정했다. 이 문서는 그 캐시가 언제 유효하고 언제 다시 만들어지는지, 그리고 캐시가 없을 때의 답이 어떻게 같음을 유지하는지 정한다.

가장 위험한 실패는 인덱스가 틀린 답을 자신 있게 내놓는 것이다. 느린 것은 불편할 뿐이지만 틀린 것은 신뢰를 무너뜨린다. 그래서 정확성의 기준은 언제나 무인덱스 경로이고, 인덱스는 그 답을 빠르게 할 뿐 바꾸지 못한다.

## 요구사항

- 인덱스가 없거나 손상되었거나 낡았을 때도 조회는 같은 답을 돌려준다.
- 인덱스는 정본에서 전부 다시 만들 수 있고, 지워도 데이터가 사라지지 않는다.
- 인덱스의 유효성은 정본 입력의 지문으로 판정하며, 낡았으면 사용하지 않는다.
- 상시 감시 프로세스는 성능을 위한 것이며 정확성의 조건이 아니다.
- 인덱스는 저장소에 커밋하지 않는다.

## 사전조건

- Workspace와 대상 프로젝트가 연결돼 있어야 한다.
- 조회의 출력 계약이 먼저 정해져 있어야 한다. 인덱스는 그 계약을 가속할 뿐 바꾸지 않는다.

## 동작 규칙

1. 조회의 기본 경로는 무인덱스다. 인덱스는 요청할 때만 쓰고, 요청받았더라도 유효하지 않으면 무인덱스 경로로 답한다. 실패를 사용자에게 전가하지 않는다.
2. 기본 경로를 무엇으로 둘지는 측정이 정한다. 캐시가 아끼는 비용보다 캐시의 유효성을 확인하는 비용이 크면 그 캐시는 가속이 아니라 감속이다.
3. 유효성 지문은 정본 입력 전체를 덮어야 한다. Rundol의 정본은 하나의 Git HEAD가 아니다 — 프로젝트별 worktree, 커밋되지 않은 작업 내용, 그리고 Git 밖의 로컬 상태가 함께 입력이다. 그중 하나라도 빠지면 인덱스가 낡은 채로 유효하다고 판정된다.
4. 시각에 따라 달라지는 값은 인덱스에 굽지 않는다. 만료 여부처럼 읽는 시점이 정하는 것은 조회 시점에 계산한다.
5. 인덱스는 조인 키만 갖고 원본 내용을 복제하지 않는다. 상세가 필요하면 정본을 읽는다.
6. 증분 갱신을 두는 경우 전체 재생성과 같은 결과를 내야 한다. 다르면 증분 경로의 결함이다.
7. 인덱스 형식이 바뀌면 낡은 인덱스는 사용하지 않고 다시 만든다. 마이그레이션하지 않는다 — 캐시이기 때문이다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 인덱스 없음 | 조회 | 무인덱스 경로로 답한다. 조회가 인덱스를 만들지는 않는다 — 만드는 시점은 사용자가 정한다. |
| 인덱스 손상 | 조회 | 무인덱스 경로로 답한다. 인덱스는 다음 재생성 때 덮어쓴다. |

| 인덱스 형식이 다름 | 조회 | 폐기하고 다시 만든다. |

## 수용 기준

- [x] 인덱스를 지워도 데이터가 사라지지 않고 다시 만들어진다.
- [x] 커밋되지 않은 변경과 Git 밖 상태가 유효성 판정에 반영된다.
- [x] 기본 경로가 무인덱스이고, 인덱스 사용 여부가 답을 바꾸지 않는다.
- [ ] 전체 재생성과 증분 갱신의 결과가 같다. — 증분 갱신을 두지 않기로 해 보류한다. 아래 측정 참고.

### 증분 갱신을 지금 두지 않는 이유

이 저장소(문서 66건, 태스크 44건)에서 실제로 재 본 값이다.

| 구간 | 시간 |
|---|---|
| 무인덱스 조회 전체 | 4ms |
| 인덱스 유효성 확인 | 259ms |
| ├ git rev-parse HEAD | 131ms |
| └ git status --porcelain | 147ms |

인덱스가 아끼려던 일이 이미 4ms인데 그것을 써도 되는지 확인하는 데 259ms가 든다. 비용의 전부는 지문을 만들기 위한 Git 하위 프로세스 두 번이고, 이것은 문서 수가 아니라 프로젝트 수에 비례하므로 규모가 커져도 줄지 않는다.

여기에 증분 갱신을 얹으면 이미 손해인 경로를 더 복잡하게 만들 뿐이다. 갱신을 아무리 싸게 해도 확인 비용이 그대로면 조회는 빨라지지 않는다.

교차점은 무인덱스 읽기가 259ms를 넘을 때, 즉 지금의 60배 규모다. 그때 다시 재고, 그때도 먼저 볼 것은 증분 갱신이 아니라 지문 비용이다 — Git 하위 프로세스 대신 파일 상태로 지문을 만들면 확인 비용이 한 자리 ms로 내려가고 교차점도 함께 내려간다. 다만 그 지문은 "질의가 실제로 읽는 입력"을 정확히 덮어야 하며, 빠뜨리면 낡은 인덱스가 유효하다고 판정되어 틀린 답을 자신 있게 내놓는다. 이 요구사항이 가장 위험한 실패로 지목한 바로 그것이다.

## 기능별 설계 계약

### QRY-01

#### 입력

- 정본 입력의 지문(프로젝트별 worktree 상태, 커밋되지 않은 변경, Git 밖 로컬 상태)과 기존 인덱스의 지문·형식 버전

#### 출력

- 조회 결과, 그리고 그 결과가 인덱스에서 왔는지 무인덱스 경로에서 왔는지의 표시

#### 업무 규칙

- 조회는 요청받았을 때만 인덱스를 본다. 인덱스 유효성은 정본 입력 지문의 일치로만 판정한다. 낡았거나 손상되었거나 형식이 다르면 사용하지 않고 무인덱스 경로로 답한다. 시각에 따라 달라지는 값은 인덱스에 저장하지 않고 조회 시점에 계산한다.

#### 상태와 전이

- 인덱스는 없음·유효·낡음·손상 중 하나이며, 유효 외의 모든 상태에서 무인덱스 경로가 답을 낸다. 재생성은 언제든 가능하고 실패해도 조회는 성공한다.

#### 권한과 승인

- 인덱스는 로컬 파생물이므로 별도 권한이 없다. 정본 읽기 권한이 곧 조회 권한이다.

#### 정상·오류·취소

- 유효한 인덱스는 같은 답을 빠르게 내고, 무효·손상은 무인덱스 경로로 조용히 물러난다. 인덱스 생성 실패는 조회 실패가 아니며 경고로 남는다.

#### 감사 기록

- 결과에 인덱스 사용 여부와 지문을 표시해, 두 경로가 다른 답을 낸 경우를 사후에 지목할 수 있게 한다.

#### 수용 기준

- 인덱스 유무와 무관하게 같은 답이 나오고, 인덱스를 삭제해도 데이터가 사라지지 않으며, 기본 경로는 측정으로 정한다.
