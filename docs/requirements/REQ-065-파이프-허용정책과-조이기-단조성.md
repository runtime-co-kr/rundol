# 파이프 허용정책과 조이기 단조성

## 배경

프로젝트 하나가 모드 하나만 갖는 것으로는 부족하다. 같은 프로젝트 안에서도 문서를 쓰는 구간과 그것을 밖으로 내보내는 구간은 되돌릴 수 있는 정도가 다르다. 구간마다 다르게 정할 수 있어야 배분이 실제로 의미를 갖는다.

동시에 구간마다 자유롭게 정할 수 있으면 프로젝트 모드는 선언에 그친다. "이 프로젝트는 사람만"이라고 적어 두고 스텝마다 AI만으로 풀어 두는 것이 가능하면, 모드는 아무것도 보장하지 않는다.

절차 오버라이드가 이미 이 문제를 풀어 두었다. 하위 계층은 스텝을 더하거나 파라미터를 조일 수만 있고, 게이트 제거와 게이트 명령 변경과 시도 상한 증가와 사람 게이트 제거는 로드 시점에 거부된다. 같은 성질을 허용정책에도 적용하면 모드가 바닥이 되고 파이프가 그 위에서만 움직인다.

## 요구사항

- 절차 스텝마다 허용정책을 선언할 수 있어야 한다.
- 프로젝트 모드가 모든 스텝의 바닥이 되어야 한다.
- 하위 계층과 스텝 정책은 바닥보다 조일 수만 있어야 한다.
- 조이는 변경도 결정으로 기록되어야 한다.
- 푸는 시도는 로드 시점에 거부되어야 한다.

## 사전조건

- 프로젝트 모드가 정해져 있고 그 손잡이 값과 강약 순위를 알 수 있다.
- 절차가 내장과 작업공간과 프로젝트 세 계층으로 해석된다.

## 동작 규칙

1. 스텝은 허용정책을 선언할 수 있다. 담는 것은 허용 실행 주체, 사람 게이트 요구, 최소 검증자 수, 다양성 요구다.
2. 프로젝트 모드가 모든 스텝의 바닥이다. 스텝이 정책을 선언하지 않으면 바닥이 그대로 적용된다.
3. 스텝 정책은 바닥보다 조일 수만 있다. 사람 게이트를 요구로 올릴 수 있고 없앨 수 없다. 최소 검증자를 올릴 수 있고 내릴 수 없다. 다양성 요구를 켤 수 있고 끌 수 없다. 허용 실행 주체를 줄일 수 있고 늘릴 수 없다.
4. 푸는 시도는 로드 시점에 거부한다. 실행 시점에 거부하면 이미 시작한 런이 중간에 멈추고, 어디까지 유효한지 아무도 답할 수 없다.
5. 계층 사이에도 같은 규칙을 적용한다. 작업공간이 조인 것을 프로젝트가 풀 수 없다.
6. 조이는 변경도 계약 변경 결정으로 기록한다. 방향으로 기록을 면제하지 않는다 — 무엇이 조이는 것인지는 값의 의미를 알아야 정하고, 그 판정을 기록 조건으로 삼으면 판정이 틀리는 순간 기록이 사라진다.
7. 바닥을 내리는 변경은 그 자체가 정책 변경이며, 이미 조여 둔 스텝은 영향받지 않는다. 바닥이 내려가도 스텝이 스스로 조여 둔 값은 그대로다.
8. 거부 메시지는 무엇이 바닥이고 무엇을 시도했는지를 함께 말한다. 이름만 알리면 사용자는 스텝을 고치려 들지만 고쳐야 할 것은 바닥이다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 스텝이 정책을 선언하지 않음 | 로드 | 바닥이 그대로 적용된다 |
| 스텝이 사람 게이트를 요구로 올림 | 로드 | 허용된다 |
| 스텝이 사람 게이트를 없앰 | 로드 | 거부. 바닥과 시도값을 함께 알린다 |
| 스텝이 최소 검증자를 올림 | 로드 | 허용된다 |
| 스텝이 최소 검증자를 내림 | 로드 | 거부 |
| 스텝이 다양성 요구를 끔 | 로드 | 거부 |
| 스텝이 허용 실행 주체를 늘림 | 로드 | 거부 |
| 작업공간이 조인 값을 프로젝트가 풂 | 로드 | 거부 |
| 바닥이 내려감 | 로드 | 이미 조여 둔 스텝 값은 그대로 |
| 조이는 변경을 결정 없이 저장 | 저장 | 거부. 방향과 무관하게 결정을 요구한다 |

## 수용 기준

- [ ] 스텝이 정책을 선언하지 않으면 바닥이 적용된다.
- [ ] 조이는 변경이 허용된다.
- [ ] 푸는 변경이 로드 시점에 거부된다.
- [ ] 계층 사이에도 같은 단조성이 적용된다.
- [ ] 조이는 변경도 결정을 요구한다.
- [ ] 거부 메시지가 바닥과 시도값을 함께 담는다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 실패 방향 | 조임 방향 판정이 애매하면 거부한다 | 판정 불능 입력에 대한 동작 확인 |
| 조기 실패 | 푸는 시도가 실행 전에 잡힌다 | 로드 시점 거부 여부 확인 |
| 결정성 | 같은 계층 구성이면 같은 해석 결과 | 반복 로드 결과 비교 |

## 제외 범위

- 모드 자체의 손잡이 구성과 강약 순위는 APV-01이 다룬다.
- 절차 실행의 진행과 재시도와 되돌아가기는 기존 절차 계약이 갖는다.
- 정책 변경이 결정으로 남는 경로 자체는 PLC-04가 다룬다. 이 문서는 방향과 무관하게 그 경로를 탄다는 것만 정한다.

## 기능별 설계 계약

### APV-02

#### 입력

- 계층별 절차 정의와 각 스텝의 허용정책.
- 프로젝트 모드가 정한 바닥 손잡이 값.
- 손잡이별 조임 방향 정의. 어느 쪽이 조이는 것인지를 담는다.

#### 출력

- 해석된 절차. 스텝마다 최종 허용정책을 담는다.
- 푸는 시도가 있으면 예외. 메시지에 스텝과 손잡이와 바닥값과 시도값을 담는다.

#### 업무 규칙

- 조임 방향은 손잡이마다 다르다. 검증자 수는 클수록 조이고 허용 실행 주체는 적을수록 조인다. 하나의 비교 연산으로 전부 판정하려 하면 반드시 한쪽이 뒤집힌다.
- 판정은 해석된 부모와 견준다. 원본 선언과 견주면 중간 계층이 조인 것을 건너뛰고 바닥과 직접 비교하게 되어, 작업공간이 조인 값을 프로젝트가 푸는 길이 열린다.
- 바닥은 판정에만 쓰고 저장하지 않는다. 저장하면 모드를 바꿨을 때 스텝에 굳어 버린 옛 바닥이 남는다.

#### 상태와 전이

- 해석은 상태를 갖지 않는다. 같은 계층 구성이면 같은 결과다.
- 해석은 실행 전에 한 번 끝난다. 실행 중에 다시 해석하지 않는다.

#### 권한과 승인

- 해석에 권한 개념이 없다. 정책을 바꾸는 것은 계약 변경 결정을 요구한다.
- 푸는 변경은 결정으로도 허용되지 않는다. 바닥을 내리는 것이 유일한 경로이며 그것도 결정을 남긴다.

#### 정상·오류·취소

- 정상: 해석된 절차.
- 오류: 푸는 시도. 스텝과 손잡이를 지목하고 바닥값과 시도값을 함께 알린다.
- 취소: 없음. 해석은 중단 지점을 갖지 않는다.

#### 감사 기록

- 해석은 기록을 남기지 않는다. 정책을 바꾼 계약 변경 결정이 기록을 갖는다.

#### 수용 기준

- [ ] 손잡이마다 조임 방향이 따로 판정된다.
- [ ] 판정이 해석된 부모와 견준다.
- [ ] 바닥이 스텝에 저장되지 않는다.
