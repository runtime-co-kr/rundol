# 제약 다섯 종류의 판정과 진단

## 배경

유형이 데이터가 되면 검사도 데이터를 읽어 판정해야 한다. 지금은 검사 코드가 유형 이름을 직접 묻는 분기 일곱 개를 갖고 있고, 유형이 늘면 분기도 는다.

판정을 데이터로 옮길 때 흔한 실수는 진단 코드까지 함께 데이터로 만드는 것이다. 그러면 코드 목록이 설정에 따라 달라지고, 문서와 도구가 그 목록을 따라갈 수 없다. 어제 본 코드가 오늘 없을 수 있는 목록은 참조할 수 없다.

카탈로그가 다섯인 근거는 현재 검증 유형의 규칙 일곱이 이 다섯으로 남김없이 표현된다는 것이다. 표현되지 않고 남는 규칙이 있으면 그 규칙은 영원히 코드에 남고, 카탈로그는 절반짜리가 된다.

## 요구사항

- 제약 다섯 종류 각각의 판정 의미가 정해져야 한다.
- 진단 코드는 제약 종류마다 하나여야 하며 유형에 따라 늘지 않아야 한다.
- 어느 유형이 위반했는지는 진단의 대상으로 전달되어야 한다.
- 면제는 판정 자체를 건너뛰어야 하며 위반을 감추는 방식이면 안 된다.
- 현재 검증 유형의 규칙 일곱이 이 판정으로 남김없이 재현되어야 한다.

## 사전조건

- 유형 정의가 형태 판정을 이미 통과했다.
- 태스크 집합과 문서 집합을 값으로 받을 수 있다.

## 동작 규칙

1. `fields`는 그 유형이 갖는 추가 필드와 허용값을 정한다. 값이 허용 집합 밖이면 진단한다. 그 필드를 선언하지 않은 유형의 태스크가 값을 갖고 있으면 진단한다 — 선언하지 않은 필드에 값이 있다는 것은 유형을 바꾸고 값을 남긴 것이다.
2. `requiresLink`는 대상 문서 유형을 최소 몇 개, 최대 몇 개 연결해야 하는지 정한다. 개수가 범위 밖이면 진단한다.
3. `requiredWhen`은 조건 필드가 특정 값일 때 요구 필드가 채워져야 함을 정한다. 조건이 맞는데 요구 필드가 비어 있으면 진단한다. 조건이 맞지 않으면 아무것도 판정하지 않는다.
4. `unique`는 필드 조합이 프로젝트 안에서 유일해야 함을 정한다. 같은 조합이 둘 이상이면 진단하며, 메시지에 먼저 그 조합을 차지한 태스크를 담는다. 이름만 알리면 어느 쪽을 고쳐야 하는지 알 수 없다.
5. `unique`는 유일성을 놓아주는 상태 목록을 함께 받는다. 그 상태에 있는 항목은 집계에서 빠지므로 같은 조합을 다시 쓸 수 있다. 지금 반려된 검증 태스크가 차수 슬롯을 놓아주는 규칙이 이것이며, 그것이 없으면 한 번 반려한 차수를 다시 시작할 수 없다.
6. 상태 목록은 값의 나열이지 조건이 아니다. 비교 연산자나 부정을 받지 않는다 — 받는 순간 이 설계는 규칙 언어가 되고, 규칙을 읽으려면 규칙 언어를 먼저 읽어야 한다. "취소가 아닌 것들 사이에서만 유일"이 아니라 "이 상태들은 집계에서 뺀다"로 적는다. 같은 것을 뜻하지만 뒤엣것만 조건식 없이 표현된다.
7. `exempt`는 지정한 게이트의 판정을 건너뛴다. 판정하고 결과를 감추는 것이 아니라 판정 자체를 돌지 않는다 — 감추는 방식이면 통계와 목록에는 위반이 남아 두 숫자가 어긋난다.
8. 진단 코드는 제약 종류마다 하나다. 유형이 열 개여도 코드는 다섯이다.
9. 어느 유형이 위반했는지는 진단의 대상 필드로 전달한다. 코드에 유형 이름을 섞지 않는다.
10. 기존에 쓰이던 검증 유형 진단 코드는 그대로 둔다. 코드를 재배열하면 이미 기록된 진단과 그것을 참조한 문서가 함께 흔들리고, 얻는 것은 이름의 정연함뿐이다.
11. 판정은 첫 위반에서 멈추지 않는다. 태스크 여럿이 어긋나 있으면 전부 낸다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 필드 값이 허용 집합 안 | 판정 | 진단 없음 |
| 필드 값이 허용 집합 밖 | 판정 | `fields` 진단. 대상에 유형과 필드를 담는다 |
| 선언하지 않은 필드에 값이 있음 | 판정 | `fields` 진단 |
| 연결 개수가 범위 안 | 판정 | 진단 없음 |
| 연결 개수가 범위 밖 | 판정 | `requiresLink` 진단. 현재 개수를 담는다 |
| 조건이 맞고 요구 필드가 빔 | 판정 | `requiredWhen` 진단 |
| 조건이 맞지 않음 | 판정 | 아무것도 판정하지 않는다 |
| 같은 조합이 둘 | 판정 | `unique` 진단. 먼저 차지한 태스크를 담는다 |
| 하나가 놓아주는 상태임 | 판정 | 집계에서 빠져 진단하지 않는다 |
| 면제된 게이트 | 판정 | 그 게이트를 돌지 않는다. 통과로 세지도 않는다 |
| 유형이 사용 안 함으로 표시됨 | 판정 | 그 유형의 태스크가 있으면 진단한다 |

## 검증 유형 규칙의 재현

| 현재 규칙 | 재현하는 제약 |
|---|---|
| 판정은 네 값 중 하나 | `fields` |
| 차수는 1 이상의 정수 | `fields` |
| 검증 문서를 정확히 하나 연결 | `requiresLink` 최소 1 최대 1 |
| 완료한 검증 태스크에는 판정이 필요 | `requiredWhen` |
| 같은 검증 문서의 같은 차수는 하나 | `unique` |
| 반려된 검증 태스크는 차수 슬롯을 놓아줌 | `unique`의 놓아주는 상태 목록 |
| 구현 준비도 게이트 면제 | `exempt` |

일곱이 다섯으로 남김없이 옮겨진다. 옮긴 뒤 같은 태스크 집합에 대해 진단 결과가 달라지면 구현이 틀린 것이다.

## 수용 기준

- [ ] 다섯 종류가 각각 자기 진단 코드를 갖는다.
- [ ] 놓아주는 상태의 항목이 유일성 집계에서 빠진다.
- [ ] 놓아주는 상태 목록이 비교 연산자를 받지 않는다.
- [ ] 유형을 늘려도 진단 코드 수가 늘지 않는다.
- [ ] 위반한 유형이 진단의 대상으로 전달된다.
- [ ] 면제가 판정을 건너뛰고 결과를 감추지 않는다.
- [ ] 검증 유형 규칙 일곱이 재현된다.
- [ ] 판정이 첫 위반에서 멈추지 않는다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 결과 동등성 | 이관 전후로 같은 태스크 집합에 같은 진단이 나온다 | 이관 전 결과를 고정값으로 두고 대조 |
| 판정 순수성 | 태스크와 정의를 값으로 받아 판정하며 파일을 읽지 않는다 | 전이 의존 검사 |
| 결정성 | 같은 입력이면 같은 진단 목록과 같은 순서 | 반복 호출 결과 비교 |

## 제외 범위

- 유형 정의의 저장 형태와 면제 가능 목록은 REQ-062#FN-001이 다룬다.
- 기존 하드코딩 분기를 걷어내는 순서와 회귀 대조 절차는 구현 태스크가 다룬다.
- 진단을 화면에 어떻게 보이는지는 이 문서가 다루지 않는다.

## 기능별 설계 계약

### FN-001

#### 입력

- 정규화된 유형 정의 맵.
- 판정 대상 태스크 집합과, 연결 대조에 쓰는 문서 식별자 집합.
- 면제 가능 게이트 이름 목록.

#### 출력

- 진단 목록. 위반 하나마다 제약 종류의 코드 하나. 대상에 유형과 필드와 태스크 식별자를 담는다.

#### 업무 규칙

- 유일성 판정은 프로젝트 전체를 훑어야 하므로 태스크 하나만 보고 답할 수 없다. 다른 넷과 달리 집합을 입력으로 받는 이유가 이것이며, 그래서 이 판정만 순서가 결과에 영향을 준다 — 먼저 차지한 쪽을 정하려면 안정된 순서가 필요하다.
- 면제는 게이트 이름으로 판정하며 진단 코드로 판정하지 않는다. 코드로 하면 한 게이트가 코드 둘을 내는 순간 절반만 면제된다.
- 사용 안 함으로 표시된 유형은 정의가 남아 있으므로 판정할 수 있다. 정의를 지우지 않고 표식만 두는 이유가 여기서도 쓰인다.

#### 상태와 전이

- 판정은 상태를 갖지 않는다. 같은 입력이면 같은 목록이다.
- 유일성 판정만 집합 전체를 한 번 훑은 뒤에 결론이 난다.

#### 권한과 승인

- 판정에 권한 개념이 없다. 검사를 부를 수 있으면 같은 답을 받는다.

#### 정상·오류·취소

- 정상: 진단 목록. 비어 있을 수 있다.
- 오류: 정의가 형태 판정을 통과하지 않은 경우. 사전조건 위반이므로 방어적 검사다.
- 취소: 없음.

#### 감사 기록

- 진단 자체가 기록이다. 저장소 상태에서 다시 계산할 수 있으므로 별도 이벤트를 남기지 않는다.

#### 수용 기준

- [ ] 유일성 판정이 안정된 순서로 먼저 차지한 쪽을 정한다.
- [ ] 면제가 게이트 이름으로 판정된다.
- [ ] 사용 안 함 유형의 태스크가 진단된다.
