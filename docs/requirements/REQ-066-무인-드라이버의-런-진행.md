# 무인 드라이버의 런 진행

## 배경

`rdl run drive --scheduled`는 데몬을 띄우지 않는다. 그 플래그가 하는 일은 이 클라이언트가 설정된 스케줄러인지 확인하는 것뿐이며, **바깥의 스케줄러를 전제하고 만든 이음매**다. 그 바깥이 비어 있는 동안 런은 사람이 명령을 칠 때만 전진했다.

원장은 이미 사람 없이도 정확하다. 추가 전용이고 읽을 때마다 다시 접히므로 프로세스가 어디에서 끊겨도 커서가 복원된다. 없는 것은 상태가 아니라 **그 상태를 보고 다음 한 걸음을 밟을 주체**였다.

## 요구사항

- 사람이 자리에 없는 동안 몰 수 있는 런이 스스로 전진한다.
- 작업공간이 동의한 프로젝트의 런만 대상이 된다.
- 원장이 움직이지 않은 런을 다시 밀지 않는다.
- 사람의 판단이 필요한 경계 앞에서 멈춘다.

## 사전조건

- 프로젝트의 하네스 설정이 이 클라이언트를 스케줄러로 지정했다. 지정하지 않은 프로젝트는 범위 밖이며 오류가 아니다.
- 드라이버로 동작하는 Client가 자동 실행 자격을 가진 유형으로 등록되어 있다.

## 동작 규칙

1. 회전 한 번이 후보 하나를 고른다. 관문은 셋이며 순서가 고정이다 — 프로젝트 동의, 런 판정, 진행 증거.
2. 프로젝트 동의는 설정에 대한 물음이지 런에 대한 물음이 아니다. 런 판정에 섞지 않는다.
3. 런 판정은 개입 대기 조회가 쓰는 것과 **같은 판정**이며 여기서 조건을 더하지 않는다. 더하고 싶어지는 조건들은 실행 직전 검사가 이미 판정한다.
4. 동시에 진행하는 런은 언제나 하나다. 희소한 것은 벽시계가 아니라 계정 사용량이며, 여럿을 동시에 몰면 그만큼 빨리 태운다.
5. 시작한 진행에 바깥에서 시간 제한을 걸지 않는다. 제한을 지키려면 프로세스 나무를 죽여야 하는데 그 보장이 아직 없고, 보장하지 못하는 것을 보장하는 척하지 않는다.
6. 한 번의 진행이 끝나면 원장을 다시 읽어 움직였는지 잰다. 움직이지 않았으면 그 런을 격리하고, 격리된 런은 증거가 달라질 때까지 고르지 않는다.
7. 격리는 프로세스 기억이며 저장하지 않는다. 저장하면 원장이 이미 말하는 것을 두 번 말하게 된다.
8. 정지한 런은 건드리지 않고 되살리지도 않는다. 정지 사유의 판정은 원장의 몫이며 드라이버가 다시 분류하지 않는다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 동의한 프로젝트가 없음 | 회전 | 아무것도 몰지 않고 성공으로 끝난다 |
| 몰 수 있는 런이 없음 | 회전 | 출력 없이 성공으로 끝난다 |
| 몰 수 있는 런이 있음 | 회전 | 하나를 골라 경계까지 밀고 결과 한 줄을 남긴다 |
| 진행 뒤 원장이 움직임 | 증거 비교 | 격리하지 않는다 |
| 진행 뒤 원장이 그대로 | 증거 비교 | 격리하고 증거를 함께 기억한다 |
| 격리된 런의 증거가 달라짐 | 회전 | 격리를 풀고 다시 후보가 된다 |
| 사람 승인을 기다리는 런 | 회전 | 고르지 않는다 |
| 이미 다른 실행자가 쥔 런 | 회전 | 고르지 않는다 |
| 드라이버가 이미 돌고 있음 | 기동 | 두 번째 기동이 거절되며 누가 쥐고 있는지 알린다 |
| 중단 신호 | 실행 중 | 진행 중인 한 걸음을 마치고 잠금을 놓는다 |

## 수용 기준

- [ ] 동의하지 않은 프로젝트의 런은 한 번도 진행되지 않는다.
- [ ] 사람 승인을 기다리는 런을 기계가 밀지 않는다.
- [ ] 원장이 움직이지 않은 런이 다음 회전에서 다시 선택되지 않는다.
- [ ] 원장이 움직이면 격리가 스스로 풀린다.
- [ ] 한 작업공간에서 드라이버는 하나만 돈다.
- [ ] 몰 것이 없는 회전이 아무것도 출력하지 않고 성공으로 끝난다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 동시성 | 진행 중인 런은 언제나 하나 이하 | 회전 중 진행 호출 수 관찰 |
| 침묵 | 몰 것이 없으면 출력이 정확히 비어 있다 | 표준 출력 문자열 비교 |
| 배타 | 두 번째 드라이버가 기동에서 거절된다 | 두 번 기동해 두 번째의 종료 상태 확인 |

## 제외 범위

- 런의 절차 정의와 스텝 실행 자체. 드라이버는 부를 뿐 무엇을 할지 정하지 않는다.
- 개입 대기 조회와 사람에게 알리는 경로. 하나는 사람이 앉았을 때 무엇을 볼지이고 다른 하나는 사람이 없을 때 무엇을 밀지다.
- 운영체제 유닛의 설치. 문서로 본문을 싣되 도구가 넣지 않는다.

## 기능별 설계 계약

### HRN-11

#### 입력

- 드라이버로 동작할 Client 식별자. 없으면 시작하지 않는다.
- 선택적 프로젝트 범위. 주지 않으면 작업공간의 모든 프로젝트가 대상이다.
- 선택적 유휴 주기와 한 번만 돌기 선택.

#### 출력

- 진행한 런의 프로젝트, 식별자, 결과 상태, 전진 여부, 사유 한 줄.
- 기계 판독 요구 시 회전 결과 전부. 몰지 않은 회전도 형태를 갖춘 결과를 낸다.
- 몰 것이 없으면 사람 출력은 비어 있다.

#### 업무 규칙

- 관문 셋의 순서는 고정이며 각 관문이 묻는 물음이 다르다.
- 런 판정에 조건을 더하지 않는다. 더한 조건은 같은 물음의 두 번째 판정자가 된다.
- 진행 여부는 반환값이 아니라 원장을 다시 읽어 판정한다.
- 실행 직전 검사가 던진 거절과 원장을 움직이지 않은 반환은 같은 관문이 받는다.

#### 상태와 전이

- 런의 상태는 드라이버가 바꾸지 않는다. 진행을 부를 뿐이며 전이는 실행이 남긴다.
- 격리는 드라이버의 상태이지 런의 상태가 아니다. 프로세스가 끝나면 사라진다.

#### 권한과 승인

- 자동 실행 자격을 가진 Client만 드라이버가 될 수 있다.
- 사람 승인이 필요한 경계는 드라이버가 지나지 못한다. 그 자격은 사람 유형에만 있다.
- 드라이버는 소유권을 옮기지 않는다. 기계를 넘기는 일은 사람의 결정이다.

#### 정상·오류·취소

- 정상: 회전이 성공하면 성공으로 끝난다. 몰 것이 없는 것도, 격리가 생긴 것도, 런이 정지한 것도 드라이버의 실패가 아니다.
- 오류: 인자가 잘못되었거나 기동 조건을 갖추지 못하면 실패로 끝난다. 자격 없는 Client로 조용히 도는 것보다 시끄럽게 실패하는 편이 낫다.
- 취소: 중단 신호를 받으면 진행 중인 한 걸음을 마치고 잠금을 놓는다. 걸음 도중에 끊지 않는다.

#### 감사 기록

- 드라이버는 원장에 자기 사건을 남기지 않는다. 남는 것은 진행이 만든 런 사건뿐이다.
- 격리는 기록하지 않는다. 원장이 움직이지 않았다는 사실은 원장 자체가 이미 말한다.

#### 수용 기준

- [ ] 동의하지 않은 프로젝트의 런에 대해 진행이 한 번도 호출되지 않는다.
- [ ] 사람 승인을 기다리는 런이 후보에서 빠진다.
- [ ] 원장이 움직이지 않은 런이 이어지는 회전에서 다시 호출되지 않는다.
- [ ] 실행 직전 검사가 던진 경우도 전진 없음과 같게 처리된다.
- [ ] 격리된 런의 증거가 달라지면 다시 후보가 된다.
- [ ] 진행 중인 런은 언제나 하나 이하다.
- [ ] 두 번째 드라이버 기동이 거절된다.
- [ ] 몰 것이 없는 회전의 사람 출력이 비어 있고 성공으로 끝난다.
