# 정책 층 값의 저장 형태

## 배경

ADR-020은 설정을 경계·정책·내용 세 층으로 나누고, 정책 층 값이 표시 설정 파일에 살 수 있게 했다. 그전까지 이 파일은 표시 전용이었다 — 항목마다 라벨과 설명과 순서만 받았고, 계약 의미는 바꾸지 못했다.

값을 담을 자리가 열렸다는 것과 어떤 모양으로 담을지가 정해졌다는 것은 다르다. 모양을 정하지 않으면 항목마다 제각각 자리를 잡는다. 업무 유형은 최상위 키로, 승인 모드는 그룹 안쪽으로, 우선순위는 또 다른 곳으로 가고, 그렇게 되면 "이 값이 어느 층인지"를 저장된 형태만으로 판정할 수 없게 된다. 판정할 수 없으면 경계 층 값이 섞여 들어와도 알아채지 못한다.

선례는 이미 있다. 프로필 항목은 라벨·설명·순서와 나란히 정책과 하부 요소를 이미 들고 있다. 표시 항목 안에 동작을 정하는 값이 형제로 앉는 형태가 이 파일에서 이미 쓰이고 있고, 문제 없이 상속된다.

## 요구사항

- 정책 층 값은 표시 항목과 같은 파일, 같은 항목 안에 형제 키로 저장되어야 한다.
- 어떤 필드가 그 그룹의 정책 필드인지는 저장된 파일이 아니라 코드가 정해야 한다.
- 목록에 없는 필드는 저장 시점에 거부되어야 한다.
- 저장값과 표시 문구가 섞이지 않아야 한다.

## 사전조건

- 표시 설정 파일이 작업공간과 프로젝트 두 위치에 있을 수 있다.
- 그룹마다 허용 필드 목록이 코드에 정의되어 있다.

## 동작 규칙

1. 정책 층 값은 그룹 항목 안에 표시 필드와 형제로 둔다. 별도 파일이나 별도 최상위 키를 만들지 않는다 — 같은 항목의 표시와 정책이 다른 곳에 살면 한쪽만 상속되는 사고가 나고, 그 사고는 값이 조용히 기본값으로 돌아가는 형태로 나타난다.
2. 그룹마다 허용 필드 목록이 있다. 표시 필드 셋(라벨·설명·순서)은 모든 그룹이 공통으로 갖고, 정책 필드는 그룹마다 다르다.
3. 허용 목록에 없는 필드가 있으면 파일 이름과 경로를 지목해 거부한다. 무시하지 않는다 — 무시하면 오타로 적은 정책이 조용히 적용되지 않고, 그 사실은 사고가 난 뒤에 드러난다.
4. 저장값은 라틴 소문자와 숫자와 붙임표로만 이루어진 식별자다. 표시 문구는 라벨에만 둔다. 저장값에 표시 문구가 들어가면 표기를 바꾸는 순간 저장된 계약이 깨진다.
5. 정책 필드를 하나라도 담은 파일은 스키마 판수 2 이상을 선언한다.
6. 판수 1 파일은 표시 필드만 갖는 것으로 읽고 그대로 유효하다. 기존 파일이 이 변경만으로 거부되면 안 된다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| 판수 1 파일에 표시 필드만 있음 | 읽기 | 그대로 유효. 정책 필드는 기본값 |
| 판수 1 파일에 정책 필드가 있음 | 읽기 | 거부. 판수를 올리라고 알린다 |
| 판수 2 파일에 허용된 정책 필드가 있음 | 읽기 | 그 값이 정책 층 값으로 채택된다 |
| 허용 목록에 없는 필드가 있음 | 읽기 | 거부. 파일과 키 경로를 지목한다 |
| 저장값에 표시 문구가 들어감 | 읽기 | 거부. 식별자 형식을 알린다 |

## 수용 기준

- [ ] 정책 필드가 그룹 항목 안에 표시 필드와 형제로 저장된다.
- [ ] 허용 목록에 없는 필드가 파일과 키 경로를 지목해 거부된다.
- [ ] 판수 1 파일이 이 변경만으로 거부되지 않는다.
- [ ] 판수 1 파일에 정책 필드를 넣으면 거부된다.
- [ ] 저장값이 식별자 형식을 벗어나면 거부된다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 하위 호환 | 기존 판수 1 파일의 읽기 결과가 이 변경 전후로 같다 | 기존 설정 파일에 대한 회귀 비교 |
| 판정 순수성 | 파일 내용을 값으로 받아 판정하며 다른 파일을 읽지 않는다 | 전이 의존 검사 |
| 결정성 | 같은 파일 내용이면 언제나 같은 판정 | 반복 호출 결과 비교 |

## 제외 범위

- 값이 세 계층에서 어떻게 합쳐지는지는 PLC-02가 다룬다.
- 경계 층에 해당하는 값이 왔을 때의 거부는 PLC-03이 다룬다.
- 변경이 결정 원장에 어떻게 남는지는 PLC-04가 다룬다.
- 어떤 값이 어느 층인지의 분류 근거는 ADR-020이 갖는다. 이 문서는 층이 정해진 뒤의 저장 형태만 다룬다.

## 기능별 설계 계약

### PLC-01

#### 입력

- 표시 설정 파일 하나의 파싱된 내용과 그 파일의 절대 경로.
- 그룹별 허용 필드 목록. 표시 필드와 정책 필드를 구분해 담는다.

#### 출력

- 정규화된 설정 객체. 그룹마다 항목이 있고 항목마다 표시 필드와 정책 필드가 나뉘어 담긴다.
- 위반이 있으면 예외. 메시지는 파일 경로와 키 경로를 담는다.

#### 업무 규칙

- 허용 목록은 코드가 갖는다. 파일이 자기 허용 목록을 선언할 수 없다 — 선언할 수 있으면 아무 필드나 허용된다고 적으면 그만이다.
- 표시 필드와 정책 필드는 이름이 겹치지 않는다. 겹치면 어느 쪽 규칙으로 검사할지 정할 수 없다.
- 거부는 첫 위반에서 멈춘다. 설정 파일은 사람이 고치는 것이고, 한 번에 하나씩 고치는 편이 목록을 받는 것보다 낫다.

#### 상태와 전이

- 읽기는 상태를 갖지 않는다. 같은 파일 내용이면 같은 결과다.
- 판수는 파일이 선언하고, 읽는 쪽이 그 값으로 허용 필드 범위를 정한다.

#### 권한과 승인

- 읽기에 권한 개념이 없다. 쓰기에 필요한 권한은 PLC-04가 다룬다.

#### 정상·오류·취소

- 정상: 정규화된 설정 객체.
- 오류: 예외. 알 수 없는 필드, 판수 위반, 식별자 형식 위반 셋을 구분해 알린다.
- 취소: 없음. 읽기에 중단 지점이 없다.

#### 감사 기록

- 읽기는 기록을 남기지 않는다. 파일 자체가 기록이고 이력은 형상 관리가 갖는다.

#### 수용 기준

- [ ] 그룹별 허용 필드 목록 밖의 키가 거부된다.
- [ ] 표시 필드와 정책 필드가 결과에서 구분되어 나온다.
- [ ] 판수 1 파일이 표시 필드만으로 정상 파싱된다.
