# 검증된 프로젝트 저장과 동기화

## 배경

프로젝트 문서와 태스크는 전용 브랜치에 있으며, 잘못된 문서·참조·태스크 상태를 커밋하거나 원격에 push해서는 안 된다. 동시 편집은 fast-forward 또는 안전한 병합으로 해소한다.

## 요구사항

- `save`는 strict 검증 통과 후 전용 worktree의 변경만 커밋한다.
- `sync`는 save, fetch, 이력 관계 판정, fast-forward/병합, 재검증, 동일 이름 ref push 순으로 실행한다.
- 의미 충돌이나 공통 이력 부재 시 push 전에 실패한다.

## 사전조건

- 대상 프로젝트가 연결되어 있고 브랜치 경계가 유효해야 한다.
- sync에는 지정 remote가 존재하고 Git 가져오기·보내기 권한이 있어야 한다.

## 동작 규칙

1. `checkWorkspace(..., strict: true)`에 error가 하나라도 있으면 save/sync를 중단한다.
2. 변경이 없는 save는 `changed: false`와 현재 commit을 반환한다.
3. sync는 `FETCH_HEAD`를 사용하지 않고 전용 remote-tracking ref로 fetch한다.
4. 원격 눈에 로컬이 조상이면 fast-forward, 로컬만 앞서면 local-ahead, 양쪽이 변경됐으면 semantic/git merge를 적용한다.
5. push는 `refs/heads/rundol/<key>:refs/heads/rundol/<key>` 동일 이름으로만 수행한다.

## 상태와 예외

| 상황 | 사건 | 기대 동작 |
|---|---|---|
| 변경 없음 | save | `changed: false` |
| 원격 ref 없음 | sync | `publish-new` 후 push |
| 로컬만 앞선 | sync | `local-ahead` 후 push |
| 원격만 앞선 | sync | `fast-forward`, worktree reset |
| 서로 다른 태스크/문서 변경 | sync | `semantic-merge` 또는 `git-merge` |
| 같은 필드 충돌 | sync | pending conflict 증거 저장, push 중단 |
| strict 검증 실패 | save/sync | commit·push 중단 |

## 수용 기준

- [x] 유효한 문서 변경은 save에서 커밋되고 최초 sync에서 `publish-new`로 게시된다.
- [x] local-ahead, fast-forward, 서로 다른 변경의 semantic merge가 각 action으로 구분된다.
- [x] 원격과 로컬 브랜치 commit이 push 후 일치한다.
- [x] strict 검증 또는 의미 충돌 실패 시 원격을 변경하지 않는다.

## 비기능 요구

| 품질 속성 | 기준 | 측정 방법 |
|---|---|---|
| 데이터 안전성 | 검증·병합 실패 시 push 없음 | remote ref 전후 비교 |
| 동시성 | 서로 다른 태스크 변경을 손실 없이 병합 | 2-clone 통합 테스트 |
| 추적성 | save와 merge가 명시적 Git commit을 생성 | commit 이력 검사 |

## 제외 범위

- 코드 브랜치 commit/push, force push, 이름이 다른 원격 ref로의 push
- 의미 충돌의 자동 선택과 사용자 승인 대행

## 기능별 설계 계약

### SYN-01

#### 입력

- Git root, 선택 project, remote(기본 `origin`), commit message, push 여부

#### 출력

- branch, commit, changed/saved/pushed, remote, `unchanged|publish-new|local-ahead|fast-forward|semantic-merge|git-merge` action, projection 경로

#### 업무 규칙

- strict 검증은 commit과 push보다 먼저 수행하고 성공한 전용 ref만 동일 이름으로 게시한다.

#### 상태와 전이

- dirty worktree→saved commit, remote-ahead→fast-forward, diverged→merge commit, local-ahead→push로 전이한다.

#### 권한과 승인

- 로컬 project worktree 쓰기와 remote fetch/push 권한이 필요하며 checkpoint 계약이 변경 승인 gate다.

#### 정상·오류·취소

- 정상은 action과 commit을 반환하고, 검증·remote·공통 이력·병합 충돌 오류는 push 전에 중단하며 `--no-push`는 병합까지 수행한다.

#### 감사 기록

- save/merge commit, pending `merge-conflicts.json`, CLI JSON action을 Git 이력과 로컬 증거로 남긴다.

#### 수용 기준

- `test/git.test.js`의 publish-new, local-ahead, fast-forward, semantic-merge, remote ref 일치 단언이 통과한다.
