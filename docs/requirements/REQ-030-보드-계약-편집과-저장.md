# 보드 계약 편집과 저장

## 배경

Board 계약 편집은 [[REQ-011-보드-문서-계획과-표시-설정-요구사항|REQ-011]]이 나르던 기능 하나를 문서 1개 = 기능 1개 계약에 따라 분리한 정본이다. 프로필 선택은 화면의 미리보기이고 저장은 revision 기반 원자 변경이다 — 화면이 편집하지 않는 값을 payload에 실으면 저장할 때마다 그 값을 덮어쓰게 된다.

## 요구사항

- 보드 계약 편집기는 프로필을 고르면 유형별 정책 상태를 그 프리셋 값으로 즉시 다시 칠하되, 저장은 계약 저장이 한다.
- 사용자가 정책 상태를 직접 바꿔 어느 프리셋과도 달라지면 그 사실을 알리고 이름을 붙여 프리셋으로 저장할 길을 연다.
- 모든 저장 요청은 Board session token과 현재 baseRevision을 요구한다.
- 저장 성공 후 최신 snapshot을 다시 읽어 화면과 파일을 맞춘다.

## 상태와 예외

| 현재 상태 또는 상황 | 사건 | 기대 상태 또는 동작 |
|---|---|---|
| stale baseRevision | 저장 | 409와 현재 계약을 반환하고 아무것도 쓰지 않는다. |
| 프리셋과 다른 직접 편집 | 화면 | 커스텀임을 알리고 프리셋 저장 경로를 제공한다. |

## 기능별 설계 계약

### FN-001

#### 입력

- 현재 계약, baseRevision, 프로필 이름, 강제 수준과 유형별 정책 상태

#### 출력

- 저장된 새 계약 또는 stale revision 409 응답

#### 업무 규칙

- payload는 화면이 실제로 편집하는 것만 싣는다. 편집하지 않는 값을 함께 보내면 저장할 때마다 그 값을 덮어쓰게 된다.

#### 상태와 전이

- 프로필 선택은 화면에서 정책 상태를 다시 칠하고, 저장 후 snapshot을 다시 읽어 화면과 파일을 맞춘다.

#### 권한과 승인

- 모든 POST는 Board session token과 현재 baseRevision을 요구한다.

#### 정상·오류·취소

- 유효 편집은 저장하고 중복·빈 구성요소·stale 요청은 원본을 보존하며 오류를 표시한다.

#### 감사 기록

- 계약 revision과 Git 커밋이 변경 주체의 결과를 보존한다.

#### 수용 기준

- 키보드만으로 상태 선택, 구성요소 추가·삭제와 저장을 수행하고 결과를 aria-live로 확인한다.
