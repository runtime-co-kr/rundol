# 문서 소프트 리스 폐기와 동시성 판정의 일원화

## 맥락

Rundol에는 성질이 다른 세 가지 동시성 기제가 "임대"라는 한 단어 아래 섞여 있다.

- 로컬 append 락. 같은 장치의 여러 프로세스가 이벤트 원장에 동시에 쓰는 것을 직렬화한다.
- 태스크 클레임. 여러 장치의 실행이 같은 태스크를 중복 수행하지 않게 한다([[ADR-007-에이전트-실행-격리와-태스크-클레임|ADR-007]]).
- 문서 소프트 리스. 여러 사람·Client가 같은 문서를 동시에 편집하는 것을 조정한다([[REQ-020-문서-편집-소프트-리스|REQ-020]]).

셋은 보장할 수 있는 것이 서로 다른데 같은 이름으로 불린다. 이 혼동이 "임대를 통합하자" 또는 "임대를 강화하자"는 제안을 반복해서 불러왔다.

문제는 문서 소프트 리스다. 이 기제는 만료 시각(`expiresAt`)에 의존한다. 시간 만료가 배타성을 보장하려면 세 가지가 필요하다. 참여자가 합의하는 공통 시계, 즉시 관측 가능한 공유 상태, 그리고 만료를 판정하는 단일 권위. Rundol은 중앙 서버 없는 Git 기반 로컬 우선 도구이므로 셋 다 없다. 각 장치는 자기 시계를 쓰고, 공유 상태는 push와 pull 사이에서 낡으며, 만료를 판정할 심판이 없다.

그래서 이 기제가 실제로 주는 것은 보장이 아니라 조언이다. 그런데 코드와 문서는 보장인 것처럼 다룬다. 복잡도는 전액 지불하면서 안전은 얻지 못하는 상태다.

방치했을 때의 영향도 이미 나타났다. 잠금 자체를 관리하다 생긴 결함이 연이어 발생했고("죽은 잠금을 치우다가 살아 있는 잠금을 지운다", "만들어지는 중인 잠금을 깨진 잠금으로 읽는다"), 이 종류의 결함은 잠금이 없으면 존재하지 않는다.

결정적인 것은 사용 실적이다. [[ADR-014-실행-엔진의-경계와-인가-2계층-유지|ADR-014]]가 기록한 대로 이 저장소에 축적된 공유 이벤트는 문서 리스 한 건과 문서 번호 예약뿐이며, driver 임대의 실사용 이벤트는 0건이다. 없어도 운영이 되고 있었다.

## 결정 기준

- 보장할 수 없는 것을 보장하는 것처럼 다루지 않을 것. 조언이면 조언이라고 부르거나 없앤다.
- 중앙 서버를 전제하지 않을 것. 로컬 우선과 폐쇄망 운영은 이 제품의 전제이지 선택지가 아니다.
- 이미 있는 수단을 먼저 쓸 것. 새로 검증해야 하는 기제의 수를 늘리지 않는다.
- 대체재 없는 구간을 만들지 않을 것. 폐기는 대체 수단이 선 다음이다.
- 실사용 근거로 판단할 것. 쓰이지 않는 기제를 상상된 필요로 유지하지 않는다.

## 선택지

| 선택지 | 장점 | 단점 | 위험 |
|---|---|---|---|
| 소프트 리스를 유지하고 만료·재생·회수를 보강한다 | 기존 문서와 구현을 바꾸지 않는다 | 공통 시계가 없어 보강해도 보장이 되지 않는다 | 복잡도만 늘고 잠금 관리 결함이 계속 발생한다 |
| 리스를 강한 잠금으로 승격한다 | 배타성이 명확해진다 | 중앙 권위가 필요하다 | 로컬 우선 전제를 무너뜨려 제품의 차별점을 없앤다 |
| 리스를 폐기하고 문서 동시 편집을 Git merge에 맡긴다 | 새로 검증할 기제가 없다. 문서 1개 = 파일 1개라 충돌 면적이 이미 작다 | 동시 편집을 사전에 막지 못하고 사후에 병합한다 | 같은 문서 같은 줄을 동시에 고치면 사람이 병합해야 한다 |
| 리스를 폐기하고 할당 발급 시점에 겹침을 계산한다 | 조정자가 있는 구조에서 런타임 잠금 자체가 불필요해진다 | 할당 계약이 먼저 서야 한다 | 할당을 거치지 않는 편집은 계산 대상 밖이다 |

## 결정

**문서 소프트 리스를 폐기하고, 문서 동시 편집의 판정을 Git merge에 일원화한다. 할당을 거치는 작업은 발급 시점의 `allowedPaths` 겹침 계산으로 사전 조정한다.** 2026-08-20, MEMBER-001 결정.

### 판정자는 Git 하나다

리스를 걷어내면 문서와 태스크의 동시성 수단이 하나의 계열로 수렴한다. 둘 다 Git이 판정하며, 차이는 무엇을 잠그느냐가 아니라 충돌을 어디서 감지하느냐뿐이다.

- 문서: 병합 시점에 감지한다. 문서 1개가 파일 1개이므로 서로 다른 문서를 고치는 편집은 충돌하지 않는다.
- 태스크: push 시점에 감지한다. 원격 ref 갱신의 성패가 판정이며, 이것은 시간이 아니라 비교-교환이다.

태스크 클레임은 시간 기반 임대가 아니라 원격 ref를 기준점으로 삼는 비교-교환이므로 공통 시계를 필요로 하지 않는다. 그래서 이 결정은 [[ADR-007-에이전트-실행-격리와-태스크-클레임|ADR-007]]을 대체하지 않고 유지한다. ADR-007은 선택지 검토에서 "lease를 태스크로 확장"을 이미 기각했으며, 이 결정은 그 판단의 연장이다.

### 조정자가 있으면 런타임 잠금이 필요 없다

임대는 조정자가 없을 때 선착순 배타를 만드는 기제다. 이 제품은 프로젝트 책임자가 설계와 태스크를 통제하는 구조이므로 조정자가 이미 있다. 할당이 수정 가능 범위를 들고 있으면 발급 시점에 겹침을 계산할 수 있고, 겹치는 할당을 동시에 내보내지 않으면 런타임에 잠글 것이 남지 않는다.

지정된 자리에 주차하는 체계에서 차량 잠금장치를 다는 것은 낭비다. 임대는 선착순 주차장의 도구다.

### 로컬 append 락은 유지한다

같은 장치의 여러 프로세스가 이벤트 원장에 동시에 쓰는 것은 실재하는 문제이며, 같은 파일시스템 안에서는 원자적 생성과 프로세스 생존 확인으로 실제 보장이 가능하다. 이것은 임대가 아니라 락이고, 이 결정의 폐기 대상이 아니다. [[ADR-005-로컬-Board-동시성-보호|ADR-005]]의 로컬 보호는 이 범위에서 유효하다.

### 인가 2계층은 이 결정과 무관하다

[[ADR-014-실행-엔진의-경계와-인가-2계층-유지|ADR-014]]가 유지하기로 한 것은 쓰기 시점 인가와 읽기 시점 인가의 분리이며, 동시성 기제가 아니다. 임대를 없앤다고 해서 병합으로 들어온 이벤트를 검사하지 않아도 되는 것은 아니다. ADR-014는 그대로 유지한다.

### 폐기 대상과 순서

폐기 대상은 문서 소프트 리스 계약 한 벌이다. [[REQ-020-문서-편집-소프트-리스|REQ-020]]과 그 데이터 모델·검증 문서가 한 세트로 함께 물러난다. 문서 1개가 기능 1개를 담는 계약 덕분에 이 폐기는 외과적으로 가능하다.

폐기는 대체 수단이 선 다음이다. 할당 계약과 겹침 계산이 먼저 서야 하며, 그 전에 리스를 걷어내면 대체재 없는 구간이 생긴다. 그 구간에서 동시 편집 사고가 나면 "역시 임대가 필요했다"는 잘못된 교훈을 남긴다.

## 결과

- 긍정: 보장하지 못하는 것을 보장하는 척하는 상태가 사라진다. 잠금 관리 자체에서 생기던 결함의 종류가 없어진다.
- 긍정: 동시성 수단이 하나의 계열(Git 판정)로 수렴해 설명과 검증 면적이 줄어든다.
- 긍정: 중앙 권위를 전제하는 방향으로 끌려가지 않는다. 로컬 우선과 폐쇄망 운영이 유지된다.
- 부정: 같은 문서의 같은 줄을 동시에 고치면 사람이 병합해야 한다. 사전 경고가 없다.
- 부정: 할당을 거치지 않는 직접 편집은 겹침 계산의 대상이 아니다. 이 경로는 Git merge만 남는다.
- 후속 작업: 할당 계약과 보고 계약을 정의하고, `allowedPaths` 겹침을 계산하는 순수 함수를 만든다. 그다음에 REQ-020 계열 문서와 구현 경로를 폐기한다.
- 후속 작업: 용어집에서 "임대"가 가리키던 세 기제를 락·클레임·리스로 갈라 적고, 폐기된 것이 무엇인지 남긴다.
- 재검토 조건: 조정자 없이 여러 사람이 같은 문서를 동시에 편집하는 사용 방식이 실제로 나타나고, Git 병합 충돌이 운영을 방해할 만큼 반복되면 다시 검토한다. 그때도 시간 만료가 아니라 발급 시점 조정을 먼저 검토한다.
