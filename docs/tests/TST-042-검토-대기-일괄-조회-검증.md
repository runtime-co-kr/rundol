# 검토 대기 일괄 조회 검증

## 목적과 범위

검토 대기 문서가 한 산출물에 모이는지, 그 값이 기존 판정이 낸 값과 같은지, 비교 결과가 비교함과 비교 기준 없음과 계산하지 않음 셋으로 갈리는지, 미승인의 바뀐 줄 수가 0이 아니라 없음인지, 차분 상한이 낡음에만 걸리고 상한을 넘긴 문서가 목록에 남는지, 상태 필터가 셈을 건드리지 않는지, 그리고 그 줄을 화면이 네 갈래로 가르는지를 검증한다.

승인 행위와 그 인가 판정, 파생 뷰 파일의 자리와 형식, 승인본 대비 제출본 비교는 검증하지 않는다. 앞엣것은 별도 요구가, 가운데는 TST-043이, 뒤엣것은 다른 검증이 갖는다.

## 테스트 데이터와 환경

저장소는 시험 안에서 만든다. 승인 원장은 이벤트를 직접 써서 세우고, 문서는 커밋해 형상 이력을 갖게 한다. 낡음을 만들려면 승인한 뒤 문서를 고쳐 다시 커밋해야 하고, 승인 리비전을 담은 커밋이 없는 갈래는 승인만 하고 커밋하지 않은 상태로 둔다 — 이 갈래는 합성 값으로 만들 수 없다. 승인 판정이 형상 이력을 실제로 걸어야 나오는 답이기 때문이다.

차분 요약을 세는 시나리오는 패치 문자열을 값으로 넣는다. 형상까지 걸면 머리말 줄이 몇 개인지가 저장소 상태에 딸려 붙어 무엇을 세는 시험인지가 흐려진다.

상한 시나리오는 기본 상한보다 작은 상한을 주어 문서 수를 늘리지 않고 만든다. 기본 상한만큼 낡음을 만들면 시험 하나가 형상 조작 수십 번을 돌게 되고, 느린 시험은 결국 꺼진다.

판정 일치 시나리오만 이 저장소의 실제 문서와 원장을 입력으로 쓴다. 합성 저장소로는 인가되지 않은 승인 기록이나 사유 없는 승인 같은 실제 모양을 다 만들지 못한다.

화면 시나리오는 검토 줄을 값으로 넣고 그린 결과를 본다. 서버를 함께 띄우지 않는 이유는 그리는 규칙이 그 값 하나에만 달려 있기 때문이다. 네 갈래를 위해 줄 값 네 벌을 둔다 — 자리가 없는 것, 못 읽은 이유가 실린 것, 사용 여부가 거짓인 것, 줄이 실린 것.

승인 원장을 갖기 전 판의 작업공간은 판 번호를 낮춘 작업공간으로 만든다.

시험이 만든 저장소는 시험이 끝나면 지운다. 개인정보는 쓰지 않으며 승인자와 위임 식별자는 시험용 값이다.

## 통과 기준

- 시나리오가 모두 통과한다.
- 비교 결과 세 값이 서로 다른 값이자 서로 다른 문장으로 나오고, 미승인의 줄 수 셋이 0이 아니라 없음이다.
- 차분 상한이 낡음에만 걸리고, 상한을 넘긴 문서가 목록에 남으며, 잘림 표식이 값에 있다.
- 상태 필터를 걸어도 상태별 셈이 전건 그대로다.
- 이 저장소의 실제 원장으로 만든 산출물이 문서 상태 조회·차분 조회의 답과 문서마다 일치한다.
- 산출물을 만들어도 원장 파일과 문서 바이트가 바뀌지 않는다.
- 화면이 네 갈래를 서로 다른 말로 그리고, 어느 갈래에서도 승인 요소가 존재하지 않는다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-070#FN-001

#### 사전 조건

- 승인 원장을 갖는 판의 작업공간과 프로젝트가 준비된다.
- 신뢰 상태 셋을 각각 갖는 문서가 준비된다. 낡음은 승인 뒤 고쳐 커밋한 문서로, 미승인은 승인 이력이 없는 문서로 만든다.
- 승인 리비전을 담은 커밋이 없는 갈래는 승인한 뒤 커밋하지 않은 상태로 둔다.
- 인가되지 않은 승인 기록 갈래는 인가 컨텍스트가 받지 않는 승인 사건을 원장에 넣어 만든다.
- 상한 시나리오는 기본보다 작은 상한을 주어 준비한다.
- 화면 시나리오는 검토 줄 값 네 벌을 준비한다.

#### 입력과 데이터

- 작업공간 시작 경로와 프로젝트 키.
- 상태 필터. 낡음, 미승인, 승인됨, 그리고 주지 않는 경우 넷을 다 쓴다.
- 차분 상한. 기본값, 기본보다 작은 값, 0, 소수, 글자를 쓴다.
- 차분 본문 포함 여부 두 갈래.
- 고정된 생성 시각. 결정성 시나리오가 이 값을 고정해 두 생성을 견준다.
- 차분 요약 시나리오용 패치 문자열. 머리말 줄이 있는 것과 한 글자만 고친 것을 둔다.
- 화면 시나리오용 검토 줄 값 네 벌. 자리가 없는 것, 못 읽은 이유가 실린 것, 사용 여부가 거짓인 것, 줄과 셈이 실린 것.

#### 실행 절차

1. 시나리오가 정한 저장소와 원장을 세운다.
2. 상태 필터와 상한과 본문 포함 여부를 주어 산출물 값을 만든다.
3. 값에서 마크다운을 만든다.
4. 값의 두 묶음과 셈과 잘림 표식과 진단 묶음을 본다.
5. 항목마다 비교 결과의 계산 여부와 성립 여부와 이유와 줄 수 셋을 본다.
6. 판정 일치 시나리오는 문서 상태 조회와 승인 이후 차분 조회를 나란히 불러 문서마다 답을 견준다.
7. 결정성 시나리오는 생성 시각을 고정해 두 번 만들고 두 값을 견준다.
8. 부작용 시나리오는 생성 전후로 원장 파일과 문서 바이트를 견준다.
9. 화면 시나리오는 검토 줄 값을 넣고 그린 결과에서 안내 문장과 거르개와 목록과 승인 요소를 찾는다.

#### 기대 결과

- 산출물은 프로젝트 키·생성 시각·상태별 셈·문서 전건 수·검토 대기 수·두 묶음·잘림 표식·진단 묶음을 갖는다.
- 항목 하나는 식별자·유형·제목·파일·리비전·상태·누적 승인 횟수·승인자·승인 리비전·마지막 승인·비교 결과를 갖는다.
- 비교 결과는 셋으로 갈린다. 계산했고 성립한 경우에만 줄 수 셋이 값을 갖고, 나머지 둘에서는 값 없음이다.
- 두 이유 문장이 서로 다르다. 승인 기록이 없는 것과 승인 리비전을 담은 커밋을 못 찾은 것은 같은 말로 적히지 않는다.
- 상한은 낡음에만 걸린다. 미승인에는 계산하지 않음이 하나도 없다.
- 상태 필터는 묶음만 비우고 셈을 건드리지 않는다.
- 마크다운은 값에 없는 사실을 말하지 않고 값에 있는 세 갈래를 세 문장으로 적는다.
- 화면은 네 갈래를 서로 다른 말로 그리고, 줄이 서는 갈래에서만 거르개와 목록을 낸다.

#### 오류와 취소

- 승인됨을 상태 필터로 주면 거부하고 쓸 수 있는 상태를 메시지에 담는다.
- 상한이 1 미만이거나 정수가 아니면 거부하고 받는 값의 범위를 메시지에 담는다.
- 승인 원장을 갖기 전 판의 작업공간이면 그 사실을 말하고 멈춘다. 빈 산출물을 내지 않는다.
- 차분을 구하지 못한 것은 오류가 아니다. 이유를 실은 항목으로 남고 나머지 항목이 함께 나온다.
- 취소할 것이 없다. 읽기만 하므로 중간에 그만두어도 저장소가 그대로다.

#### 증거

- 산출물 값 시험 파일의 세 갈래 구역과 상한 구역과 필터 구역.
- 차분 요약 시험 파일의 머리말 구역.
- 마크다운 시험 파일의 문장 구역과 셈 표 구역.
- 판정 일치 시험이 남긴 두 경로의 답 대조표.
- 부작용 시험이 남긴 생성 전후 파일 해시.
- 화면 시험 파일의 네 갈래 구역과 절단 구역과 승인 요소 검색 결과.
