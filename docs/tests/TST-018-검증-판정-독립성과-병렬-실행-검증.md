# 검증 판정 독립성과 병렬 실행 검증

## 목적과 범위

판정자 배분·검증 동시성·저작 병렬을 같은 절차 픽스처로 교차 검증한다. 세 기능이 한 런에서 함께 관찰되므로 증거를 나누지 않는다. 실제 모델 어댑터의 판별력은 이 문서가 다루지 않는다 — 여기서 증명하는 것은 배선과 정책이지 판정의 품질이 아니다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 어댑터 배분 함수, 다양성 집계, 만족 가능성 검사 | 순수 함수의 결정성 | 자동 |
| 통합 | 검증 실행 경로와 재개 | 동시 실행이 판정과 재개를 바꾸지 않음 | 자동 |
| 종단 | drive 절차의 fan-out 저작 | 격리·복귀·부분 실패 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| S-01 | 어댑터 둘 등록 | 정족수 2·다양성 요구로 검증 | 통과에 도달 | 높음 |
| S-02 | 어댑터 하나 등록 | 같은 정책 선언 | 절차 로드 거부 | 높음 |
| S-03 | 검증 1회 완료 | 재개 | slot별 어댑터가 처음과 같음 | 높음 |
| S-04 | 선택 렌즈의 어댑터 비활성 | 검증 | 완료하되 미실행으로 기록 | 높음 |
| S-05 | 렌즈 셋·validator 둘 | 순차와 동시 각각 실행 | 판정 동일, 소요는 최대치에 근접 | 높음 |
| S-06 | 호출 하나 실패 | 재실행 | 성공 판정은 재호출되지 않음 | 높음 |
| S-07 | 형제 문서 셋 | fan-out 저작 | 순차 합보다 짧음 | 중간 |
| S-08 | 대상 하나 실패 | fan-out 저작 | 나머지 결과가 본 트리에 남음 | 높음 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 동시성 | 총 소요가 순차 합이 아닌 최대치에 근접 | 스텁 판정자, 고정 지연 | 순차·동시 두 실행의 벽시계 비교 |
| 결정성 | 같은 입력에 같은 판정 | 동일 픽스처 | 두 실행의 집계 대조 |
| 자원 | 동시 실행이 상한을 넘지 않음 | 상한 2 설정 | 동시에 살아 있는 자식 프로세스 수 관찰 |

## 테스트 데이터와 환경

임시 워크스페이스에 프로젝트 하나를 만들고, 모델을 부르지 않는 스텁 판정자 둘을 서로 다른 이름으로 등록한다. 판정 결과와 지연은 파일로 조종한다 — 환경 변수는 어댑터 경계를 넘지 못하므로 그것으로 조종하면 스텁이 조용히 기본값으로 돌고 시험은 자기가 무엇을 시켰는지 모르는 채 통과한다. 격리 트리는 실행 후 정리되었는지 확인하고, 시험이 끝나면 임시 워크스페이스 전체를 지운다.

## 통과 기준

- S-01~S-08이 모두 통과한다.
- 기존 검증 스위트가 변경 없이 통과한다.
- 각 방어를 하나씩 껐을 때 대응하는 시나리오가 실패한다.

## 기능별 검증 계약

### REQ-042#FN-001

#### 사전 조건

- 어댑터 둘 이상이 설정에 등록돼 활성이고, 그중 하나는 모델을 부르지 않는 판정자다.

#### 입력과 데이터

- 렌즈 목록, 어댑터 목록, 정족수 정책(validators·quorum·다양성 요구), 렌즈별 필수 여부와 접근 방식 선언

#### 실행 절차

- 어댑터 둘을 고정한 절차로 검증을 돌리고, 같은 정책을 어댑터 하나로 선언한 절차의 로드를 시도하며, 한 번 돈 검증을 재개해 slot별 어댑터를 대조한다.

#### 기대 결과

- 서로 다른 어댑터의 통과가 정족수를 채워 통과에 도달하고, 어댑터가 정족수보다 적은 선언은 로드에서 거부되며, 재개한 검증의 slot별 어댑터가 처음과 같다.

#### 오류와 취소

- 만족 불가능한 다양성 선언은 로드에서 거부하고 어긋난 값을 알린다. 필수 렌즈 미실행은 미완으로 남기고, 선택 렌즈 미실행은 완료하되 미실행으로 기록한다.

#### 증거

- 판정 이벤트의 어댑터 이름·접근 방식·지시문 pin, 절차 로드 거부 메시지, 재개 전후의 slot·어댑터 대조 결과

#### 수용 기준

- S-01~S-04가 통과하고, 다양성 집계를 무력화했을 때 S-01이 실패한다.

### REQ-043#FN-001

#### 사전 조건

- 검증 스텝이 절차에 고정돼 있고 대상 커밋이 pin돼 있으며, 판정 호출들이 서로의 결과를 입력으로 쓰지 않는다.

#### 입력과 데이터

- 렌즈 셋과 validator 둘로 구성한 여섯 개 호출, 동시 실행 상한 설정값, 이미 결과가 있는 자식 요청 키 집합

#### 실행 절차

- 같은 검증을 순차와 동시로 각각 돌려 소요와 판정을 비교하고, 호출 하나를 실패시킨 뒤 다시 실행해 재호출 여부를 관찰한다.

#### 기대 결과

- 동시 실행의 총 소요가 순차 합이 아니라 최대치에 가깝고, 두 방식의 판정 결과가 같으며, 성공했던 판정은 재실행에서 다시 호출되지 않는다.

#### 오류와 취소

- 일부 호출이 실패해도 나머지를 중단하지 않고 성공분을 보존한다. 실행 중 대상 커밋이 바뀌면 검증 전체를 무효로 하고 멈춘다. 취소는 진행 중인 호출 전체에 전달되며 이미 받은 결과는 버리지 않는다.

#### 증거

- 순차·동시 두 실행의 소요와 판정 집계, 재실행 시 호출된 자식 요청 키 목록, 기존 검증 스위트의 통과 결과

#### 수용 기준

- S-05와 S-06이 통과하고, 동시 실행 상한을 2로 두었을 때 동시에 살아 있는 자식이 둘을 넘지 않는다.

### REQ-044#FN-001

#### 사전 조건

- 서로의 선행 조건이 아닌 형제 문서 셋이 있고, 각 대상이 절차가 요구하는 저작 계약을 갖는다.

#### 입력과 데이터

- 계약 평가가 계산한 준비 완료 대상 집합, fan-out 스텝 선언, 동시 실행 상한

#### 실행 절차

- 형제 문서 셋을 fan-out으로 저작하고 총 소요를 순차와 비교하며, 한 대상을 실패시켜 나머지 결과의 복귀를 관찰하고, 선행 문서가 없는 대상이 집합에 들어가는지 확인한다.

#### 기대 결과

- 동시 저작의 총 소요가 순차 합보다 짧고, 한 대상이 실패해도 나머지 결과가 본 트리에 남으며, 선행 문서가 없는 대상은 준비 완료 집합에 들어가지 않는다.

#### 오류와 취소

- 대상 하나의 실패는 그 대상만 미완으로 남기고 그 격리 트리를 폐기한다. 대상 밖을 고친 저작은 그 대상만 거부한다. 취소는 진행 중인 모든 대상에 전달되고 이미 복귀한 결과는 유지된다.

#### 증거

- 대상별 저작 결과와 실패 사유, 실행되지 못한 대상 목록, 격리 트리의 생성과 정리 기록, 순차·동시 소요 비교

#### 수용 기준

- S-07과 S-08이 통과하고, 실행 후 격리 트리가 남지 않는다.
