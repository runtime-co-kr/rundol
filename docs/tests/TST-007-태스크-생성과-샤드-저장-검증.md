# 태스크 생성과 샤드 저장 검증

## 목적과 범위

CLI와 state API로 생성한 태스크가 계약 필드를 보존하고 올바른 project와 client shard에 저장되며 projection에서 손실 없이 읽힘을 검증한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위/용량 | `src/tasks.js` shard 선택·통합 | 개발자 | 자동 |
| CLI/Git 통합 | `task add`, project store, commit/projection | 개발자 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| TSK01-01 | 단일 project Workspace | 전체 CLI 필드로 `task add` | 규격 ID, title/owner/reviewer/stakeholder/priority/acceptance 보존 | P0 |
| TSK01-02 | memo/tms 복수 project | project 없이 add | exit 2, `--project` 안내 | P0 |
| TSK01-03 | memo/tms 복수 project | `--project tms` add | tms store에만 1개, memo 0개 | P0 |
| TSK01-04 | REQ/TST link 제공 | task add | `implementationReadiness: atomic-v1` | P0 |
| TSK01-05 | client-a, maxItems 500 | 1,001개 생성 | 3 shard, 통합 1,001개 | P1 |
| TSK01-06 | sharded project store | task create | canonical shard, projection, pending op, create commit 생성 | P1 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 용량 | 1,001개를 3개 shard로 분할 | 임시 디렉터리 | shard 수·task 수 정확 비교 |
| 격리 | 선택 project 외 store 무변경 | 2-project Workspace | project별 task count |
| 일관성 | shard 통합과 projection의 ID 집합 일치 | sharded store | deep equality |

## 테스트 데이터와 환경

임시 Git repo, `test/fixtures/workspace`, memo/tms project, `client-a`, 프로세스 안에서 생성한 1,001개 가상 태스크를 사용한다. 개인정보와 외부 네트워크 의존성은 없고 테스트 후 임시 파일을 제거한다.

## 통과 기준

- `node test/features.test.js`, `node test/init.test.js`, `node test/git.test.js`가 exit 0으로 완료되고 생성·격리·shard 단언이 통과한다.

## 기능별 검증 계약

### TSK-01

#### 사전 조건

- 대상 project에 유효한 charter·state branch·worktree가 있고 Git 사용자가 설정돼 있다.

#### 입력과 데이터

- 한국어 title/summary/acceptance, MEMBER/STAKEHOLDER ID, priority high, TST link, project `tms`, client-a, 1,001 task ID

#### 실행 절차

- CLI `task add`와 `createTaskInStore`를 호출하고 반환 JSON, project별 canonical store, shard 목록, projection, commit을 읽어 비교한다.

#### 기대 결과

- 태스크 ID·필드·project·atomic-v1이 계약과 일치하고 500개 한도에서 샤드와 projection이 손실 없이 만들어진다.

#### 오류와 취소

- 다중 project 미선택, 잘못된 client ID, 중복 ID, malformed shard, projection 검증 실패는 nonzero/예외로 종료하고 쓴 파일을 rollback한다.

#### 증거

- `test/features.test.js`, `test/init.test.js`, `test/git.test.js` assert, shard JSON, projection JSON, Git commit, 각 테스트 pass 출력

#### 수용 기준

- TSK01-01~06이 통과하고 canonical store·projection·commit 사이에 task ID 손실이 없다.
