# 프로젝트 저장과 동기화 검증

## 목적과 범위

프로젝트 변경이 strict 검증 후에만 커밋·push되고, 두 clone의 독립 변경이 손실 없이 병합되며 같은 필드 충돌은 차단됨을 검증한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | `mergeTaskDocuments` 의미 병합 | 개발자 | 자동 |
| Git E2E | `rdl save`, `rdl sync`, 2-clone remote | 개발자 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| SYN01-01 | 로컬 문서 변경, 원격 project ref 없음 | save 후 sync | changed true, `publish-new`, ref commit 일치 | P0 |
| SYN01-02 | 로컬만 앞선 이력 | sync | `local-ahead` | P0 |
| SYN01-03 | 원격만 앞선 이력 | sync | `fast-forward` | P0 |
| SYN01-04 | 두 clone이 다른 문서/태스크 변경 | sync | `semantic-merge`, 모든 변경 보존 | P0 |
| SYN01-05 | 같은 task status를 다르게 변경 | merge | `/tasks/A/status` conflict | P0 |
| SYN01-06 | strict diagnostic error | save/sync | commit·push 전 실패 | P0 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 손실 방지 | 독립 변경 모두 원격에 존재 | 2 clone + bare remote | remote `git show` 필드 단언 |
| 부작용 격리 | 충돌/검증 실패 시 push 없음 | 로컬 remote | ref commit 전후 비교 |

## 테스트 데이터와 환경

`test/fixtures/workspace`를 복사한 두 clone, 로컬 bare remote, 서로 다른 task/document 변경을 사용한다. 외부 네트워크는 없고 모든 임시 경로는 finally에서 제거한다.

## 통과 기준

- `node test/git.test.js`가 exit 0으로 완료되고 semantic merge·action·remote ref 단언이 모두 통과한다.
- checkpoint/strict 차단 회귀 테스트가 원격 무변경을 보증한다.

## 기능별 검증 계약

### SYN-01

#### 사전 조건

- Git 사용자가 설정된 두 clone과 push 가능한 bare remote, 유효한 project branch가 있다.

#### 입력과 데이터

- project `tms`, 문서 주석 변경, 서로 다른 task status/owner 변경, 의미 충돌 task fixture

#### 실행 절차

- save/sync를 순서별로 실행하고 JSON action, local/remote commit, remote `tasks.json`을 비교하며 단위 merge에 conflict fixture를 주입한다.

#### 기대 결과

- publish-new·local-ahead·fast-forward·semantic-merge가 이력 관계와 일치하고 성공 후 remote/local commit과 독립 task 변경이 일치한다.

#### 오류와 취소

- 공통 이력 부재, remote 오류, strict 실패, 같은 필드 충돌은 nonzero로 종료하고 push를 수행하지 않는다.

#### 증거

- `test/git.test.js` assert, remote `git show`, `git tests passed` 출력, strict/checkpoint 테스트 결과

#### 수용 기준

- SYN01-01~06이 통과하고 원격에 부분·잘못된 ref 업데이트가 없다.
