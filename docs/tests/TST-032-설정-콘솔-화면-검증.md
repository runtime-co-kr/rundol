# 설정 콘솔 화면 검증

## 목적과 범위

항목이 범위별로 묶여 노출되는지, 출처가 색 없이도 읽히는지, 상속과 명시가 서로 다른 조작을 내는지, 정책 저장이 결정 필요 상태를 거치는지, 경계 층이 조작 가능한 형태로 존재하지 않는지를 검증한다. 값이 어떻게 합쳐지는지는 검증하지 않는다 — 이 화면의 입력이다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 노출 목록 구성 함수 | 개발 | 자동 |
| 통합 | 보드 화면의 요소 구조와 조작 결과 | 개발 | 자동 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 접근성 | 출처·층·잠김 구분이 색 외의 단서를 함께 갖는다 | 로컬 | 색 제거 렌더에서 구분 가능 여부 확인 |
| 결정성 | 같은 병합 결과와 출처면 같은 화면 구성 | 로컬 | 반복 렌더 결과 비교 |
| 반응형 | 좁은 폭에서 본문이 가로로 밀리지 않는다 | 로컬 | 폭을 줄인 렌더에서 가로 스크롤 발생 여부 확인 |

## 테스트 데이터와 환경

병합 결과와 출처 정보는 시험 안에서 값으로 만든다. 화면 구성은 순수 계산이므로 파일을 거치지 않는다. 통합 수준 시나리오만 임시 작업공간을 쓰고 끝나면 지운다. 경계 층 목록은 코드에서 가져와 쓰고 시험이 다시 적지 않는다 — 다시 적으면 목록이 늘어날 때 새 항목이 검증되지 않은 채 남는다.

## 통과 기준

- 열두 시나리오가 모두 통과한다.
- 경계 층 목록의 모든 원소가 조작 가능한 요소로 나오지 않는다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-060#FN-001

#### 사전 조건

- 병합된 설정과 계층별 원본과 값 단위 출처 정보가 값으로 주어진다.
- 항목별 층 구분과 경계 층 목록이 코드에서 읽힌다.
- 프로젝트 선택 여부는 시나리오가 정한다.

#### 입력과 데이터

- 범위 묶음과 그 저장 성격, 항목 목록과 층 구분, 값과 출처 표시기, 저장 띠, 경계 층 설명 구역 — SCR-003의 바인딩이 정한 여덟 요소.
- 상위와 같은 값을 명시한 항목을 최소 하나 포함한다.
- 상위 계층이 바닥을 정한 선택지 집합을 최소 하나 포함한다.

#### 실행 절차

1. 시나리오가 정한 병합 결과와 출처 정보를 만든다.
2. 설정 콘솔을 연다.
3. 레일에서 범위와 항목을 고른다.
4. 값을 조작하고 저장 띠를 확인한 뒤 저장한다.
5. 저장 뒤의 상태와 이동 여부를 읽는다.

#### 기대 결과

- 범위 묶음 수가 프로젝트 선택 여부와 맞는다.
- 출처 표시기의 채움 개수가 계층과 맞고, 색을 제거해도 값이 유지된다.
- 상속받은 값에는 덮기가, 명시한 값에는 되돌리기가 나온다.
- 표시 층 저장은 화면에 머물고, 정책 층 저장은 결정 필요를 거쳐 SCR-002로 나간다.
- 경계 층 이름은 읽기 전용 구역에만 있고 조작 요소가 없다.

#### 오류와 취소

- 저장 실패는 편집 중으로 되돌리고 조작한 값을 남긴다.
- 설정 읽기가 경계 층 위반으로 거부되면 빈 화면 대신 사유와 파일 위치를 보인다.
- 결정을 내지 않고 돌아오면 편집 중으로 복귀한다.

#### 증거

- 설정 콘솔 시험 파일의 노출 구역과 출처 구역과 저장 흐름 구역.

#### 수용 기준

- [ ] 경계 층 목록의 모든 원소가 조작 요소로 나오지 않는다.
- [ ] 출처 구분이 색 없이 읽힌다.
- [ ] 정책 저장이 결정 필요를 거쳐 SCR-002로 나간다.
