# 프로젝트 연결과 복구 검증

## 목적과 범위

원격 Rundol branch를 새 clone의 전용 worktree에 연결하고 branch boundary를 유지하며, 선점된 경로에서 부분 ref/worktree를 남기지 않음을 검증한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| CLI 통합 | `rdl attach`, `rdl init --project` | 개발자 | 자동 |
| Git 경계 | worktree/ref/exclude/boundary | 개발자 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| WSP02-01 | source가 crm Workspace/project를 sync함 | clone에서 `attach crm` | `attached`, 두 worktree 생성, 코드 status 무변경 | P0 |
| WSP02-02 | 같은 remote의 새 clone | `init --project crm` | action `attached`, crm `project.md` 존재 | P0 |
| WSP02-03 | `projects/crm` 비어 있지 않음 | init attach | nonzero, '비어 있지 않습니다', Workspace/ref 미생성 | P0 |
| WSP02-04 | 로컬 project ref 존재·worktree 누락 | repair | 올바른 branch worktree 재생성 | P1 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 원자성 | occupied target 실패 시 Rundol ref/worktree 없음 | 임시 clone | ref·파일 존재 검사 |
| 경계 안전성 | structure audit clean, 코드 branch status 무변경 | Git worktree | `check --structure`, `git status --short` |

## 테스트 데이터와 환경

임시 source, bare remote, clone, bootstrap-clone, conflict-clone과 각각의 `RUNDOL_HOME`을 사용한다. remote는 로컬 경로이며 테스트 종료 시 전체 임시 트리를 제거한다.

## 통과 기준

- [x] `node test/attach.test.js`와 `node test/bootstrap.test.js`가 exit 0으로 완료되고 성공·충돌·복구 단언이 통과한다.

## 기능별 검증 계약

### WSP-02

#### 사전 조건

- 원격에 유효한 `rundol/workspace`, `rundol/crm`, main branch가 게시되어 있다.

#### 입력과 데이터

- project `crm`, service profile, advisory enforcement, 정상 clone·bootstrap clone·occupied clone

#### 실행 절차

- source를 init/sync한 뒤 clone별로 attach 또는 init bootstrap을 실행하고 JSON, worktree 파일, ref, structure audit를 검사한다.

#### 기대 결과

- 정상 경로는 Workspace/project worktree와 boundary를 만들고, occupied 경로는 아무 Rundol ref나 Workspace worktree도 만들지 않는다.

#### 오류와 취소

- 비어 있지 않은 target, 잘못된 branch, 분기 ref, remote/project 누락은 nonzero로 종료하고 기존 데이터를 보존한다.

#### 증거

- `test/attach.test.js`, `test/bootstrap.test.js` assert, Git ref/worktree 목록, `attach tests passed` 출력

#### 수용 기준

- WSP02-01~04와 branch boundary 검사가 통과하고 실패 fixture에 부분 연결이 없다.
