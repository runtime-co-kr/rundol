## 테스트 데이터와 환경

그림은 시험 안에서 만든다. 외부 파일을 두면 그 파일이 저장소에 남아 이 시험이 막으려는 문제를 자기가 일으킨다. 작업공간은 임시 디렉터리에 새로 만들고 끝나면 지운다 — 개발자 기계에 붙은 작업공간에 기대면 CI에서 죽는다.

## 기능별 검증 계약

### REQ-053#FN-001

#### 사전 조건

- 자산 디렉터리의 내용을 시나리오마다 다르게 준비한다.
- 차원 판독은 손으로 만든 헤더 바이트로 검증한다 — 실제 이미지 파일을 두면 이 시험이 막으려는 문제를 자기가 일으킨다.

#### 입력과 데이터

- 손으로 만든 PNG·GIF·JPEG·SVG 헤더.
- `rdl asset add`로 넣은 실제 자산.

#### 실행 절차

1. 헤더 바이트로 `imageSize`를 직접 부른다.
2. 임시 작업공간에 자산을 넣고 `rdl check --json`을 실행한다.
3. 문서에 참조를 넣고 다시 검사한다.

#### 기대 결과

- 네 형식의 차원이 헤더가 담은 값과 같다.
- 알아보지 못한 바이트는 `null`이다.
- 한계 초과와 고아 진단이 해당 자산을 지목한다.

#### 오류와 취소

- 자산 디렉터리가 없는 것은 위반이 아니다. 진단이 나면 실패다.

#### 증거

- `test/asset.test.js`의 헤더 판독 구역과 명령·검사 구역.

#### 수용 기준

- [ ] 일곱 시나리오가 모두 통과한다.
- [ ] 차원 판독이 디코딩 없이 이뤄진다.
