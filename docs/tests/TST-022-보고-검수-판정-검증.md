# 보고 검수 판정 검증

## 목적과 범위

[[REQ-050-보고-검수-판정|REQ-050]]이 정의한 WRK-03을 검증한다. 검증 대상은 순수성, 결정성, 세 판정 구분의 산출, 반려가 사람 판단보다 앞서는 우선 규칙, 근거 목록의 내용, 그리고 네 표면이 같은 판정을 얻는지다.

가장 중요한 검증은 순수성이다. 이 함수가 파일이나 저장소에 닿는 순간 표면마다 판정이 갈리고 제품의 전제가 무너지므로, 순수성 검사를 통과하지 못하면 다른 시나리오의 통과 여부와 무관하게 실패로 판정한다.

접수 단계의 형식 검사와 사람 결정의 기록은 대상이 아니다. 이 문서는 명세만 담으며 실행 결과는 검증 태스크가 나른다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 정적 | 검수 모듈의 require 연쇄에 금지 의존이 없는지 | 구현·검증 담당 | 자동 |
| 단위 | 판정 구분과 근거 목록의 산출 | 구현·검증 담당 | 자동 |
| 속성 | 같은 입력에서 같은 출력이 나오는지 | 구현·검증 담당 | 자동 |
| 통합 | 명령줄·보드·워커 어댑터의 판정 일치 | 구현·검증 담당 | 자동 |

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| S01 | 검수 모듈이 존재한다 | require 연쇄를 전이적으로 따라간다 | 파일 시스템·하위 프로세스·저장소·작업공간 모듈이 나타나지 않는다 | high |
| S02 | 모든 수용 조건이 증거와 함께 충족되고 절차가 일치하며 범위 위반이 없는 입력 | 검수한다 | 통과를 돌려주고 막힌 항목이 비어 있다 | high |
| S03 | 수용 조건 하나가 미충족으로 표시된 입력 | 검수한다 | 반려를 돌려주고 막힌 항목에 그 식별자가 담긴다 | high |
| S04 | 충족 표시에 증거 참조가 빈 입력 | 검수한다 | 반려를 돌려주고 증거 없음이 사유로 담긴다 | high |
| S05 | 변경 대상이 수정 가능 경로 밖인 입력 | 검수한다 | 반려를 돌려주고 벗어난 대상이 지목된다 | high |
| S06 | 보고가 금지 항목 위반을 밝힌 입력 | 검수한다 | 반려를 돌려준다 | mid |
| S07 | 결과 구분이 차단인 입력 | 검수한다 | 사람 판단 필요를 돌려주고 차단 사유가 전달된다 | high |
| S08 | 절차 다이제스트가 할당의 고정 값과 다른 입력 | 검수한다 | 사람 판단 필요를 돌려주고 두 다이제스트가 함께 반환된다 | high |
| S09 | 미충족 수용 조건과 차단 결과가 동시에 있는 입력 | 검수한다 | 반려를 돌려준다 | high |
| S10 | 같은 입력 하나 | 백 번 호출한다 | 모든 출력의 직렬화 결과가 동일하다 | high |
| S11 | 같은 입력 하나 | 시각과 환경 변수를 바꾼 뒤 호출한다 | 판정이 변하지 않는다 | high |
| S12 | 같은 입력 하나 | 명령줄·보드·워커 어댑터로 각각 통과시킨다 | 세 판정이 동일하다 | high |
| S13 | 보고가 언급하지 않은 수용 조건이 있는 입력 | 검수한다 | 판정 구분이 아니라 계약 위반 예외로 알린다 | mid |
| S14 | 수용 조건 목록이 빈 할당 | 검수한다 | 계약 위반 예외로 알린다 | mid |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 순수성 | 금지 의존 0건, 전이 포함 | 로컬 | S01의 require 연쇄 추적 결과 |
| 결정성 | 반복 호출 출력 동일 | 로컬 | S10·S11의 직렬화 비교 |
| 표면 일관성 | 세 표면 판정 동일 | 로컬 | S12의 판정 비교 |

## 테스트 데이터와 환경

할당과 보고를 값으로만 구성한 fixture 집합을 쓴다. 저장소나 임시 작업공간이 필요 없다는 점이 이 검증의 특징이며, 파일이 필요해지면 그 자체가 순수성 위반 신호다. 표면 일관성 시나리오만 임시 작업공간을 쓰며, 종료 시 지운다. 개인정보와 외부 서비스 의존은 없다.

## 통과 기준

- S01이 통과한다. 순수성 위반이 있으면 나머지 결과와 무관하게 실패로 판정한다.
- 우선순위 high 시나리오가 모두 통과한다.
- 세 판정 구분이 각각 산출되는 것을 S02·S03·S07에서 확인한다.
- 반려 우선 규칙이 S09에서 확인된다.
- 결정성이 S10·S11에서, 표면 일관성이 S12에서 확인된다.
- 계약 위반이 판정 구분으로 섞이지 않는 것을 S13·S14에서 확인한다.

## 기능별 검증 계약

### WRK-03

#### 사전 조건

- 검수 모듈이 존재하고 값 두 개를 받는 형태로 호출 가능하다.
- 할당과 보고를 값으로 구성한 fixture 집합이 준비되어 있다.
- 표면 일관성 검증을 위한 임시 작업공간이 준비되어 있다.

#### 입력과 데이터

- 통과 기준 입력: 수용 조건 셋이 모두 증거와 함께 충족되고 절차가 일치하며 범위 위반이 없다.
- 반려 유발 입력: 미충족 하나, 증거 없는 충족 하나, 범위 밖 변경 하나, 금지 항목 위반 하나.
- 사람 판단 유발 입력: 결과 구분 차단 하나, 절차 다이제스트 불일치 하나.
- 우선순위 검증 입력: 미충족과 차단이 동시에 있는 것.
- 계약 위반 입력: 수용 조건을 언급하지 않은 보고, 수용 조건 목록이 빈 할당.

#### 실행 절차

1. 검수 모듈의 require 연쇄를 전이적으로 수집해 금지 의존 유무를 판정한다.
2. 통과 기준 입력을 검수해 판정과 막힌 항목을 확인한다.
3. 반려 유발 입력들을 차례로 검수해 각 판정과 지목 대상을 수집한다.
4. 사람 판단 유발 입력들을 검수해 전달된 사유와 다이제스트를 확인한다.
5. 우선순위 검증 입력을 검수해 반려가 나오는지 확인한다.
6. 같은 입력을 백 번 호출해 출력을 직렬화하고 비교한다.
7. 시각과 환경 변수를 바꾼 뒤 같은 입력을 검수한다.
8. 같은 입력을 명령줄·보드·워커 어댑터로 각각 통과시켜 판정을 비교한다.
9. 계약 위반 입력을 검수해 예외로 알리는지 확인한다.

#### 기대 결과

- 금지 의존이 하나도 나타나지 않는다.
- 통과 기준 입력이 통과와 빈 막힌 항목을 돌려준다.
- 네 가지 반려 유발 입력이 모두 반려를 돌려주고 각각 지목 대상을 담는다.
- 두 가지 사람 판단 유발 입력이 사람 판단 필요를 돌려주고 사유와 다이제스트를 전달한다.
- 우선순위 검증 입력이 반려를 돌려준다.
- 백 번 호출의 출력이 모두 같고, 시각과 환경 변수 변경이 판정을 바꾸지 않는다.
- 세 표면의 판정이 동일하다.
- 계약 위반 입력이 판정 구분이 아니라 예외로 보고된다.

#### 오류와 취소

- 계약 위반과 반려를 구분하는지 확인한다. 판정할 수 없는 것을 반려로 돌려주면 실패로 판정한다.
- 예외 메시지가 어떤 계약이 깨졌는지를 지목하는지 확인한다.
- 검수 호출이 어떤 외부 상태도 바꾸지 않았는지 확인한다. 기록을 남기면 순수성 위반이다.
- 계산에 취소 경로가 없음을 확인한다. 중단할 진행 상태가 존재하면 설계 위반이다.

#### 증거

- require 연쇄 추적 결과와 발견된 의존 목록.
- 시나리오별 판정 구분과 근거 목록을 담은 실행 로그.
- 백 회 반복 호출의 직렬화 비교 결과.
- 세 표면의 판정 비교표.
- 실행 결과는 이 문서가 아니라 검증 태스크의 판정과 증거로 남긴다.

#### 수용 기준

- 검수 모듈의 전이 의존에 파일 시스템·하위 프로세스·저장소·작업공간 모듈이 없다.
- 세 판정 구분이 각각 해당 입력에서 산출된다.
- 네 가지 반려 사유가 모두 반려를 내며 지목 대상을 담는다.
- 두 가지 사람 판단 사유가 모두 사람 판단 필요를 내며 근거를 전달한다.
- 반려와 사람 판단이 동시에 성립할 때 반려가 나온다.
- 백 회 반복 호출의 출력이 모두 같다.
- 시각과 환경 변수 변경이 판정을 바꾸지 않는다.
- 명령줄·보드·워커 어댑터의 판정이 같다.
- 계약 위반이 예외로 보고되고 판정 구분에 섞이지 않는다.
