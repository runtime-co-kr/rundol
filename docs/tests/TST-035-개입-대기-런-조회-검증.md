# 개입 대기 런 조회 검증

## 목적과 범위

[[REQ-061-개입-대기-런-조회|REQ-061]]이 정한 갈래 판정과 출력 계약을 검증한다. 가장 큰 품질 위험 셋을 겨눈다.

첫째는 **조회가 원장을 바꾸는 것**이다. 이 조회는 세션이 열릴 때마다 도는 자리에 쓰이므로, 원장을 조정하는 경로를 타면 무엇이 주의를 요구하는지 묻는 행위가 원장을 바꾸는 행위가 된다.

둘째는 **침묵이 깨지는 것**이다. 개입 대기가 없을 때 한 글자라도 쓰면 그 표면은 곧 읽히지 않고, 읽히지 않는 표면은 없는 것과 같다.

셋째는 **이미 몰고 있는 런을 다시 밀라고 말하는 것**이다. 갈래가 둘뿐이면 실행 중인 런이 기계가 이어 밀 대상으로 나온다.

|---|---|---|---|

| 통합 | 열거와 읽기 경로 | 실제 작업공간에서 프로젝트를 훑고 원장을 읽는다 | 자동 |
| 계약 | 명령줄 표면 | 침묵, 종료 코드, 기계 판독 형태 | 자동 |

| 침묵 | 개입 대기가 없을 때 출력이 정확히 빈 문자열 | 임시 작업공간 | 표준 출력 문자열 비교 |
| 고립 | 손상 하나가 나머지 판정을 막지 않는다 | 원장 하나를 훼손한 임시 작업공간 | 나머지 런의 판정과 종료 코드 확인 |

## 테스트 데이터와 환경

갈래 판정은 합성 fold 객체로 검증한다. 판정이 순수 함수이므로 파일 시스템 없이 계약을 고정할 수 있고, 그것이 읽기 경로가 끼어들기 전에 판정을 못 박는 유일한 방법이다.

열거와 명령줄 계약은 임시 디렉터리에 만든 작업공간에서 검증한다. 저장소를 초기화하고 프로젝트를 둘 만든 뒤 실제 런을 시작한다.

실행 중임을 흉내내지 않는다. 프로세스 잠금은 실제로 쥐고, driver 리스는 실제 이벤트로 기록한다. 만료 판정은 시계 비교이므로 만료 시각을 직접 심는다.

## 통과 기준

- 모든 시나리오가 통과한다.
- 갈래 판정 시나리오가 파일 시스템에 접근하지 않는다.
- 읽기 전용 시나리오가 조회 전후의 바이트와 수정 시각이 같음을 단언한다.
- 침묵 시나리오가 빈 문자열을 단언한다. 공백이나 줄바꿈은 통과가 아니다.

## 기능별 검증 계약

### REQ-061#FN-001

#### 사전 조건

- Rundol Workspace가 연결된 임시 저장소가 있고 프로젝트가 등록되어 있다.
- 갈래 판정 시나리오에는 작업공간이 필요하지 않다. 합성 fold만으로 수행한다.
- 실행 중 판정 시나리오에는 실제 런과, 실제로 쥔 프로세스 잠금 또는 기록된 driver 이벤트가 있다.

#### 입력과 데이터

- 합성 fold: 런 식별자, 프로젝트 키, 상태, 커서와 결의된 커서 스텝, 소유자, 정지 사유, 소유권 충돌, operation 충돌 목록.
- 실행 중 여부: 리스 활성과 프로세스 잠금 생존을 나타내는 두 값.
- 명령줄 입력: 선택적 프로젝트 필터, 선택적 기계 판독 출력 요구.

#### 실행 절차

1. 합성 fold로 갈래 판정 함수를 직접 호출해 갈래, 사유, 다음 명령을 확인한다.
2. 임시 작업공간을 만들고 프로젝트를 둘 등록한 뒤 런을 시작한다.
3. 프로세스 잠금을 실제로 쥐었다 놓으며 각각 조회한다.
4. driver 이벤트를 유효·해제·만료 순으로 기록하며 각각 조회한다.
5. 원장 하나를 훼손하고 조회한다.
6. 조회 전후의 원장과 공유 이벤트 파일을 바이트와 수정 시각으로 비교한다.
7. 필터 없이, 각 프로젝트 필터로, 등록되지 않은 키로 각각 조회한다.

#### 기대 결과

- 정지·사람 게이트·충돌·동기화 대기는 사람 대기로, 커서가 준비된 런은 기계 대상으로, 실행 중인 사슬이 있는 런은 실행 중으로 판정된다.
- 정지 사유는 원장이 준 값과 같다.
- 충돌 항목의 다음 명령에 복구용 식별자가 들어 있다.
- 개입 대기가 없으면 사람 출력이 빈 문자열이고 종료 코드가 0이다.
- 조회 전후 파일의 바이트와 수정 시각이 같다.
- 손상된 런은 읽기 실패로 드러나고 나머지 런의 판정은 그대로 나온다.

#### 오류와 취소

- 등록되지 않은 프로젝트 키는 인자 오류로 끝나며 빈 결과로 조용히 끝나지 않는다.
- Workspace를 찾지 못한 경로에서의 호출은 오류가 아니며 빈 결과와 성공으로 끝난다.
- 조회는 중간 상태를 만들지 않으므로 도중에 끊겨도 되돌릴 것이 없다.

#### 증거

- 자동 시험의 실행 결과가 증거이며 시나리오 식별자로 결과를 가리킨다.
- 읽기 전용 시나리오는 조회 전후 파일의 바이트와 수정 시각을 비교한 값 자체를 증거로 남긴다. 판정이 아니라 비교값이 증거다.
- 실행 중 판정 시나리오는 실제로 쥔 잠금과 실제로 기록한 driver 이벤트를 증거로 삼는다. 흉내낸 상태는 증거가 되지 않는다.
- 시험 실행은 태스크의 실행 기록에 결부하며 이 문서에 결과를 적지 않는다. 정본에 결과를 적으면 다시 실행할 때 정본을 고쳐야 하고 그러면 무엇이 실패했었는지가 지워진다.

#### 수용 기준

- 갈래 판정 시나리오가 파일 시스템에 접근하지 않고 통과한다.
- 정지 사유가 원장이 준 값과 문자열로 같다.
- 실행 중인 사슬이 있는 런이 기계가 이어 밀 대상으로 제시되지 않는다.
- 개입 대기가 없을 때 표준 출력이 빈 문자열이다.
- 조회 전후 원장과 공유 이벤트 파일의 바이트와 수정 시각이 같다.
- 손상된 런이 있어도 나머지 런의 판정이 나오고 종료 코드가 성공이다.
- 등록되지 않은 프로젝트 키가 인자 오류로 끝난다.
