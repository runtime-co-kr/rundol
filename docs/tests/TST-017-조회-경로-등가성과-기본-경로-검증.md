# 조회 경로 등가성과 기본 경로 검증

## 목적과 범위

가장 위험한 실패는 인덱스가 틀린 답을 자신 있게 내놓는 것이다. 느린 것은 불편할 뿐이지만 틀린 것은 신뢰를 무너뜨린다. 이 문서는 [[REQ-041-조회-인덱스와-무인덱스-경로|REQ-041]]이 정한 두 가지를 검증한 증거를 남긴다 — 인덱스가 답을 바꾸지 못한다는 것, 그리고 기본 경로가 정본이라는 것.

질의 문법과 명령 표면, 문서 변경 이력의 조인은 각각의 문서가 다루므로 여기서 제외한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 유효성 지문이 정본 입력의 변화를 잡는가 | 인덱스 모듈 | 자동 |
| 통합 | 두 경로가 같은 답을 내는가 | CLI 조회 명령 | 자동 |
| 회귀 | 인덱스가 없거나 손상되거나 낡아도 조회가 성공하는가 | 인덱스 모듈 | 자동 |
| 성능 | 인덱스 경로가 정본 경로보다 느리지 않은가 | 실측 | 수동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| S-01 | 인덱스 없음 | 조회 | 정본 경로로 답한다 | 높음 |
| S-02 | 유효한 인덱스 있음 | 조회 | 정본 경로로 답한다. 인덱스가 있다는 이유만으로 쓰지 않는다 | 높음 |
| S-03 | 유효한 인덱스 있음 | 인덱스 경로를 요청 | 인덱스로 답하며 정본 경로와 결과가 같다 | 높음 |
| S-04 | 유효한 인덱스 있음 | 프로젝트·상태·열림 필터로 조회 | 모든 필터에서 두 경로의 결과가 같다 | 높음 |
| S-05 | 인덱스 손상 | 인덱스 경로를 요청 | 조회가 실패하지 않고 정본으로 물러난다 | 높음 |
| S-06 | 인덱스 형식이 다름 | 유효성 판정 | 마이그레이션하지 않고 낡음으로 본다 | 중간 |
| S-07 | 커밋되지 않은 변경 발생 | 유효성 판정 | 낡음으로 판정한다 | 높음 |
| S-08 | 그 변경을 되돌림 | 유효성 판정 | 다시 유효로 판정한다 | 중간 |
| S-09 | 태스크 추가 | 유효성 판정과 조회 | 낡음으로 판정하고 정본을 읽어 새 태스크를 포함한다 | 높음 |
| S-10 | 인덱스 삭제 | 조회 | 데이터가 사라지지 않고 같은 답이 나온다 | 높음 |

S-07은 이 기능에서 가장 중요한 시나리오다. 커밋되지 않은 변경을 지문에서 빠뜨리면 낡은 인덱스가 유효하다고 판정되어, 조회는 성공하면서 틀린 답을 돌려준다. 실패가 드러나지 않는 유일한 경로다.

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 정확성 | 인덱스 사용 여부가 답을 바꾸지 않는다 | 임시 Workspace | 두 경로 결과의 deep equality |
| 복구성 | 인덱스를 삭제·손상시켜도 조회가 성공한다 | 임시 Workspace | 삭제·손상 후 조회 |
| 격리성 | 인덱스가 정본 경로에 놓이지 않는다 | 임시 Workspace | 파일 위치 단언 |
| 가속 | 인덱스 경로가 정본 경로보다 느리지 않다 | 실제 저장소 | 두 경로 소요 시간 실측 |

가속 항목은 이 기능의 존재 이유이므로 검증 대상에 포함한다. 정확성만 검증하면 "느려도 맞으니 통과"가 되어, 캐시가 손해인 상태를 아무도 발견하지 못한다.

## 테스트 데이터와 환경

임시 디렉터리에 Git 저장소와 Workspace를 만들고 프로젝트·태스크를 생성해 쓴다. 인덱스는 실행 시점의 런타임 홈 아래에 놓이므로 검증에서도 그 위치를 단언하고, 시험이 끝나면 임시 디렉터리를 통째로 지운다. 외부 의존성과 개인정보는 없다.

가속 항목만 실제 저장소에서 잰다 — 임시 Workspace는 문서가 몇 건뿐이라 두 경로의 차이가 드러나지 않는다.

## 통과 기준

- 인덱스 유무·손상·형식 불일치·낡음의 모든 상태에서 조회가 성공하고 같은 답을 낸다.
- 커밋되지 않은 변경이 유효성 판정에 반영된다.
- 기본 경로가 정본이고, 인덱스 경로는 요청했을 때만 쓰인다.
- 인덱스가 정본 경로에 놓이지 않는다.
- 가속 항목을 실측하고 그 결과가 기본값 결정의 근거로 남는다.

## 기능별 검증 계약

### QRY-01

#### 사전 조건

- Workspace와 프로젝트가 있고 태스크가 하나 이상 있다. 인덱스는 없음·유효·낡음·손상·형식 불일치 중 하나의 상태에 둔다.

#### 입력과 데이터

- 프로젝트 키, 상태, 열림 여부의 조회 필터와, 인덱스 경로를 쓸지 정본을 강제할지의 선택

#### 실행 절차

- 각 인덱스 상태에서 같은 조회를 두 경로로 실행하고 결과를 비교한다. 정본 입력을 바꾸고(커밋되지 않은 파일 추가, 태스크 추가) 유효성 판정이 따라 바뀌는지 확인한다. 인덱스를 지우거나 손상시킨 뒤에도 조회가 성공하는지 확인한다.

#### 기대 결과

- 모든 상태에서 조회가 성공한다. 두 경로의 결과가 같다. 요청하지 않으면 정본 경로로 답한다. 결과에 어느 경로로 답했는지가 남는다.

#### 오류와 취소

- 인덱스 읽기는 던지지 않는다. 손상·형식 불일치·낡음은 전부 "쓸 수 없음"이고 그때 정본이 답한다. 인덱스 생성 실패는 조회 실패가 아니다.

#### 증거

- `test/query-index.test.js`의 자동 검증과, 실제 저장소에서 잰 두 경로의 소요 시간. 측정 결과는 [[REQ-041-조회-인덱스와-무인덱스-경로|REQ-041]]과 [[ADR-010-조회-인덱스와-이력-조회의-경계|ADR-010]]의 재검토 기록에 남아 있다.

#### 수용 기준

- 인덱스 상태와 무관하게 조회가 성공하고 같은 답이 나오며, 기본 경로가 정본이고, 두 경로의 비용이 실측되어 기본값 결정의 근거로 남는다.
