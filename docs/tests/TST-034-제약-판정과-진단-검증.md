# 제약 판정과 진단 검증

## 목적과 범위

제약 다섯이 각각 판정되는지, 진단 코드가 제약 종류마다 하나이고 유형이 늘어도 늘지 않는지, 면제가 판정을 건너뛰는지, 그리고 현재 검증 유형 규칙 여섯이 재현되는지를 검증한다. 정의의 저장 형태는 검증하지 않는다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 제약 해석 함수 | 개발 | 자동 |
| 통합 | 검사 명령의 진단 목록 | 개발 | 자동 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 결과 동등성 | 이관 전후로 같은 진단이 나온다 | 로컬과 통합 검사 매트릭스 | 이관 전 결과를 고정값으로 두고 대조 |
| 결정성 | 같은 입력이면 같은 목록과 같은 순서 | 로컬 | 반복 호출 결과 비교 |

## 테스트 데이터와 환경

태스크 집합과 정의는 시험 안에서 값으로 만든다. 이관 동등성 시나리오는 현재 저장소의 실제 태스크 집합을 입력으로 쓰고, 이관 전 진단 결과를 고정값으로 떠 두었다가 대조한다 — 합성 데이터로는 실제로 쓰이는 조합을 다 만들지 못한다. 검증 유형 규칙 여섯은 표로 대조하며, 표의 왼쪽은 코드에서 가져온 현재 진단 코드 목록이다.

## 통과 기준

- 열여섯 시나리오가 모두 통과한다.
- 이관 전후 진단 결과가 실제 태스크 집합에서 같다.
- 유형을 늘려도 진단 코드 수가 그대로다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### ITM-02

#### 사전 조건

- 정의가 형태 판정을 통과한 상태로 주어진다.
- 이관 전 진단 결과가 고정값으로 준비되어 있다.

#### 입력과 데이터

- 정규화된 유형 정의 맵.
- 판정 대상 태스크 집합과 문서 식별자 집합.
- 유일성 시나리오를 위해 같은 조합을 갖는 태스크 둘.
- 면제 시나리오를 위해 면제 가능 게이트 하나.

#### 실행 절차

1. 시나리오가 정한 정의와 태스크 집합을 만든다.
2. 판정을 호출해 진단 목록을 받는다.
3. 순서 시나리오는 태스크 입력 순서를 뒤집어 다시 호출한다.
4. 동등성 시나리오는 실제 태스크 집합으로 호출하고 고정값과 견준다.

#### 기대 결과

- 위반마다 제약 종류의 코드가 하나씩 난다.
- 대상 필드에 유형과 필드와 태스크 식별자가 담긴다.
- 면제된 게이트의 진단이 목록에 없고, 통과 집계에도 없다.
- 유형 수와 무관하게 코드 종류가 다섯이다.

#### 오류와 취소

- 정의가 형태 판정을 통과하지 않았으면 예외. 사전조건 위반이므로 방어적 검사다.
- 판정은 첫 위반에서 멈추지 않는다.

#### 증거

- 제약 판정 시험 파일의 다섯 종류 구역과 동등성 구역.

#### 수용 기준

- [ ] 유일성 판정이 입력 순서와 무관하게 같은 쪽을 먼저로 정한다.
- [ ] 놓아주는 상태의 항목이 유일성 집계에서 빠진다.
- [ ] 면제가 통과 집계에도 남지 않는다.
- [ ] 실제 태스크 집합에서 이관 전후 진단이 같다.
