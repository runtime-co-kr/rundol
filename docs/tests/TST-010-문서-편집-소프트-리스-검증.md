# 문서 편집 소프트 리스 검증

## 목적과 범위

COL-02의 CLI와 Board API에서 한 문서의 단일 활성 lease, 5분 갱신, release 제거와 이벤트 저장을 검증한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 통합 | lease CLI와 Workspace JSONL 저장 | 프로젝트 책임자 | 자동 |
| API 통합 | Board acquire/list endpoint | 프로젝트 책임자 | 자동 |
| 단위 | event projection과 만료 필터 | 프로젝트 책임자 | 자동 보강 대상 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| COL-02-S01 | active Client와 존재 문서 | acquire | `lease.acquired`, 이벤트 파일, 활성 1건 | P0 |
| COL-02-S02 | S01의 같은 Client | renew | 동일 leaseId, 새 expiresAt, 활성 1건 | P0 |
| COL-02-S03 | S02 완료 | release | `lease.released`, 활성 0건 | P0 |
| COL-02-S04 | 다른 Client가 유효 lease 보유 | acquire | 충돌 오류, 새 사건 없음 | P1 |
| COL-02-S05 | 만료 시각 경과 | activeLeases | 만료 lease 제외 | P1 |
| COL-02-S06 | disabled Client/비멤버/없는 문서 | acquire | 권한·대상 오류 | P1 |
| COL-02-S07 | 다른 Client가 유효 lease 보유 | 문서 본문 저장 | 200, 응답에 보유자·만료 시각을 담은 `leaseNotice` | P0 |
| COL-02-S08 | 유효 lease 없음 | 문서 본문 저장 | 200, `leaseNotice` 없음 | P1 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 감사성 | 모든 정상 전이가 JSONL 사건으로 남음 | 임시 Workspace | 사건 type·ID·baseRevision·시각 검사 |
| 경계 | 세그먼트 500건 또는 1MiB 제한 | 합성 이벤트 저장소 | 다음 NNNNNN 파일 생성 검사 |

## 테스트 데이터와 환경

임시 Git Workspace의 crm 프로젝트, MEMBER-001 소유 `laptop-a`, 실제 `project:crm` 문서를 사용한다. 만료 단위 테스트는 고정된 now 값을 주입하고 모든 임시 파일은 종료 시 삭제한다.

## 통과 기준

- [ ] `node test/collaboration-store.test.js`에서 acquire→list→renew→release→list 흐름이 통과한다.
- [ ] `node test/board-workspace.test.js`에서 lease POST와 GET이 200이고 활성 1건을 반환한다.
- [ ] `node test/board-workspace.test.js`에서 남의 lease가 걸린 문서 저장이 거절되지 않고 `leaseNotice`를 실어 돌아온다.

## 기능별 검증 계약

### COL-02

#### 사전 조건

- schemaVersion 6 Workspace, active Client, 프로젝트 멤버 owner와 frontmatter ID가 존재하는 문서가 준비된다.

#### 입력과 데이터

- project `crm`, documentId `project:crm`, clientId `laptop-a` 또는 `test-device`, acquire/renew/release action을 사용한다.

#### 실행 절차

- acquire 응답과 JSONL을 검사하고 list, renew, release, 최종 list를 호출한다. 충돌·만료·권한 변형도 독립 fixture로 실행한다.

#### 기대 결과

- 정상 흐름은 같은 lease ID를 유지하고 acquire/renew는 5분 만료를 가지며 release 후 활성 목록이 비어진다.
- lease가 어긋난 저장은 거절되지 않는다. 200과 함께 `leaseNotice.holder`·`leaseNotice.expiresAt`이 실려, 조율 신호와 저장 권한이 분리되어 있음이 확인된다.

#### 오류와 취소

- 중복 acquire와 소유하지 않은 renew/release는 사건 없이 실패한다. 사용자의 취소는 release 사건으로 검증한다.

#### 증거

- `test/collaboration-store.test.js`, `test/board-workspace.test.js` 로그와 Client ID가 포함된 첫 번째 lease JSONL 세그먼트 사건.

#### 수용 기준

- REQ-020의 단일 활성 lease, 소유 검증, 수명주기, 만료와 감사 필드를 자동 assertion으로 입증한다.
