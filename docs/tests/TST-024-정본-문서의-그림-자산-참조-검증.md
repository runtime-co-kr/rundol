# 정본 문서의 그림 자산 참조 검증

## 목적과 범위

자산 embed가 문서 참조 규칙에 걸리지 않는지, 그리고 끊긴 자산 참조가 잡히는지를 검증한다. 그림의 내용이 문서와 맞는지는 검증하지 않는다 — 기계가 답할 수 있는 질문이 아니다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 판정 함수와 코덱 | 개발 | 자동 |
| 통합 | `rdl` 명령과 검사 결과 | 개발 | 자동 |

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| RDLASSETREF01 | 자산이 자산 디렉터리에 있음 | 문서에 `![[a.png]]`를 넣고 검사 | `RDL-LINK-004`가 나지 않는다 | 높음 |
| RDLASSETREF02 | 자산 디렉터리가 비어 있음 | 문서에 `![[없는그림.png]]`를 넣고 검사 | `RDL-ASSET-001`이 그 이름을 지목한다 | 높음 |

## 테스트 데이터와 환경

그림은 시험 안에서 만든다. 외부 파일을 두면 그 파일이 저장소에 남아 이 시험이 막으려는 문제를 자기가 일으킨다. 작업공간은 임시 디렉터리에 새로 만들고 끝나면 지운다 — 개발자 기계에 붙은 작업공간에 기대면 CI에서 죽는다.

## 통과 기준

- 아래 시나리오 전부가 통과한다.
- 네 OS·Node 매트릭스에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-052#FN-001

#### 사전 조건

- 임시 작업공간에 프로젝트 하나가 있다.
- 자산 디렉터리의 내용은 시나리오마다 다르게 준비한다.

#### 입력과 데이터

- 본문에 embed를 담은 정본 문서 하나.
- 시험 안에서 만든 PNG. 외부 파일을 두지 않는다.

#### 실행 절차

1. 임시 디렉터리에 작업공간과 프로젝트를 만든다.
2. 시나리오가 요구하면 `rdl asset add`로 자산을 넣는다.
3. 문서 본문에 embed를 덧붙인다.
4. 프로젝트를 지정해 `rdl check`를 JSON으로 실행한다.

#### 기대 결과

- 진단 목록에서 `RDL-LINK-004` 중 대상이 자산 확장자인 것이 하나도 없다.
- 끊긴 참조는 `RDL-ASSET-001`로 나오며 대상이 embed에 쓴 이름과 같다.

#### 오류와 취소

- 검사는 첫 진단에서 멈추지 않는다. 여러 embed가 끊겨 있으면 전부 나온다.

#### 증거

- `test/asset.test.js`의 명령과 검사 구역.

#### 수용 기준

- [ ] 다섯 시나리오가 모두 통과한다.
- [ ] 임시 작업공간에서 실행되어 CI에서도 같은 결과가 나온다.
