# 경계 층 값 저장 거부 검증

## 목적과 범위

경계 층 키가 설정 파일에 있을 때 거부되는지, 그 거부가 판수나 계층으로 완화되지 않는지, 그리고 무시로 처리되지 않는지를 검증한다. 무엇이 경계 층인지의 분류는 검증하지 않는다 — 목록은 이 판정의 입력이다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 경계 키 판정 함수 | 개발 | 자동 |
| 통합 | 설정을 읽는 명령의 종료 코드와 메시지 | 개발 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| RDLBOUNDARYDENY01 | 프로젝트 파일에 경계 층 키가 있음 | 설정을 읽는다 | 거부되고 파일 경로와 키 경로가 메시지에 담긴다 | 높음 |
| RDLBOUNDARYDENY02 | 작업공간 파일에 경계 층 키가 있음 | 설정을 읽는다 | 프로젝트와 같은 강도로 거부된다 | 높음 |
| RDLBOUNDARYDENY03 | 판수를 2로 올리고 경계 층 키를 둠 | 설정을 읽는다 | 거부가 유지된다 | 높음 |
| RDLBOUNDARYDENY04 | 경계 키를 접두로 갖는 다른 이름의 정책 키 | 설정을 읽는다 | 경계로 판정되지 않고 허용 필드 판정으로 넘어간다 | 높음 |
| RDLBOUNDARYDENY05 | 경계 층 키와 알 수 없는 필드가 함께 있음 | 설정을 읽는다 | 경계 층 메시지가 나온다. 알 수 없는 필드 메시지가 아니다 | 높음 |
| RDLBOUNDARYDENY06 | 경계 층 키가 있음 | 설정을 읽는다 | 그 값이 결과 객체에 담기지 않는다 | 중간 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 실패 방향 | 판정이 애매하면 거부한다 | 로컬 | 경계 목록 대조가 정확 일치일 때만 통과하는지 확인 |
| 결정성 | 같은 내용이면 같은 판정 | 로컬 | 반복 호출 결과 비교 |
| 이식성 | 세 운영체제에서 같은 결과 | 통합 검사 매트릭스 | 통합 검사 통과 여부 |

## 테스트 데이터와 환경

경계 키 목록은 코드에서 가져와 쓴다. 시험이 목록을 다시 적으면 목록이 늘어날 때 새 키가 검증되지 않은 채 남는다. 접두 일치 시나리오는 실제 경계 키 하나를 골라 뒤에 글자를 붙여 만든다. 임시 작업공간을 쓰고 끝나면 지운다.

## 통과 기준

- 여섯 시나리오가 모두 통과한다.
- 경계 키 목록의 모든 원소에 대해 거부가 성립한다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### PLC-03

#### 사전 조건

- 설정 파일의 문법 파싱이 끝나 있다.
- 경계 키 목록과 정책 필드 목록이 이름을 공유하지 않는다.

#### 입력과 데이터

- 파싱된 설정 내용과 파일 경로.
- 경계 키 목록. 코드에서 가져온다.

#### 실행 절차

1. 시나리오가 정한 내용으로 설정 파일을 쓴다.
2. 설정을 읽는 경로를 호출한다.
3. 예외 메시지 또는 정상 결과를 받는다.
4. 목록 전수 시나리오는 경계 키마다 같은 절차를 되풀이한다.

#### 기대 결과

- 경계 키가 있으면 예외가 나고 메시지에 파일 경로와 키 경로와 거부 이유가 있다.
- 접두만 같은 이름은 경계로 판정되지 않는다.
- 경계 판정이 허용 필드 판정보다 먼저 나므로, 둘이 함께 있으면 경계 메시지가 나온다.

#### 오류와 취소

- 거부는 첫 위반에서 멈춘다.
- 우회 경로가 없다. 위임을 제시해도 결과가 같다.

#### 증거

- 경계 판정 시험 파일의 거부 구역과 목록 전수 구역.

#### 수용 기준

- [ ] 경계 키 목록의 모든 원소가 거부를 일으킨다.
- [ ] 접두만 같은 이름이 경계로 판정되지 않는다.
- [ ] 판수와 계층에 상관없이 같은 결과가 나온다.
