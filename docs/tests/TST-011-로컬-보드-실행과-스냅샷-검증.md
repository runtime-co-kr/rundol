# 로컬 보드 실행과 스냅샷 검증

## 목적과 범위

BOP-01의 loopback 서버, UI 자산 보안 헤더, 태스크 필터, 프로젝트 snapshot의 구성과 revision을 검증한다.

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| HTTP 통합 | createBoardServer 조회 API와 자산 | 프로젝트 책임자 | 자동 |
| Workspace 통합 | schemaVersion 6 snapshot과 표시 상속 | 프로젝트 책임자 | 자동 |
| 정적 UI 계약 | HTML·JS·CSS 필수 UI와 보안 표현 | 프로젝트 책임자 | 자동 |

## 테스트 데이터와 환경

버전 관리된 `test/fixtures/workspace`와 테스트 중 생성하는 임시 crm Workspace를 사용한다. 서버는 OS가 배정한 port에서 실행하고 `finally`에서 close하며 임시 저장소는 삭제한다.

## 통과 기준

- [ ] `node test/board.test.js`, `node test/board-workspace.test.js`, `node test/board-ui.test.js`가 모두 종료 코드 0이다.
- [ ] snapshot의 필수 배열·계약·표시·revision assertion이 모두 통과한다.

## 기능별 검증 계약

### BOP-01

#### 사전 조건

- 발견 가능한 Workspace, 태스크 저장소, 프로젝트 charter/docs와 로컬에서 사용 가능한 TCP port가 존재한다.

#### 입력과 데이터

- test token, tms/crm project, status `doing`, limit 2, Board 자산과 snapshot endpoint를 사용한다.

#### 실행 절차

- loopback 서버를 시작하고 자산·tasks·projects·snapshot·documents·revision·collaboration endpoint를 GET한 뒤 서버를 닫는다.

#### 기대 결과

- 모든 유효 조회가 200이며 snapshot은 프로젝트 범위 데이터와 계산된 revision·attention·contract·presentation을 반환한다.

#### 오류와 취소

- 없는 자원은 404이고 서버 close 후 listener가 남지 않는다. 필수 저장소가 없으면 경로를 포함한 오류로 실패한다.

#### 증거

- 세 Board 테스트의 assertion 로그, HTTP status/header/body와 snapshot JSON.

#### 수용 기준

- REQ-021의 loopback, 자산 보안, 필터, snapshot 구성과 revision 기준을 자동 검증한다.
