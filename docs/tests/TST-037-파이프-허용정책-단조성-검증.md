# 파이프 허용정책 단조성 검증

## 목적과 범위

스텝 정책이 바닥보다 조일 수만 있는지, 푸는 시도가 로드 시점에 거부되는지, 손잡이마다 조임 방향이 따로 판정되는지, 계층 사이에도 같은 규칙이 서는지를 검증한다. 모드 자체의 구성은 검증하지 않는다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 절차 해석과 단조성 판정 함수 | 개발 | 자동 |
| 통합 | 절차 로드 명령의 종료 코드와 메시지 | 개발 | 자동 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |

| 실패 방향 | 조임 방향 판정이 애매하면 거부한다 | 로컬 | 판정 불능 입력에 대한 동작 확인 |

## 테스트 데이터와 환경

절차 정의는 시험 안에서 값으로 만들고 계층 셋을 각각 구성한다. 손잡이 방향 정의는 코드에서 가져와, 손잡이가 늘어나면 방향이 정의되지 않은 채로는 시험이 통과하지 못하게 한다. 임시 작업공간을 쓰고 끝나면 지운다.

## 통과 기준

- 열네 시나리오가 모두 통과한다.
- 모든 손잡이에 조임 방향이 정의되어 있다.
- 푸는 절차로는 런이 시작되지 않는다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### APV-02

#### 사전 조건

- 프로젝트 모드가 정해져 바닥 손잡이 값을 알 수 있다.
- 절차가 세 계층으로 구성되어 있다.

#### 입력과 데이터

- 계층별 절차 정의와 스텝 허용정책.
- 바닥 손잡이 값.
- 손잡이별 조임 방향 정의. 코드에서 가져온다.

#### 실행 절차

1. 시나리오가 정한 계층별 절차를 만든다.
2. 절차를 로드한다.
3. 계층 시나리오는 작업공간과 프로젝트를 각각 구성해 로드한다.
4. 실행 시나리오는 로드 뒤 런 시작을 시도한다.

#### 기대 결과

- 조이는 변경은 해석된 절차에 반영된다.
- 푸는 변경은 예외로 나오며 스텝과 손잡이와 바닥값과 시도값이 담긴다.
- 해석된 부모와 견주므로 중간 계층이 조인 것을 건너뛰지 못한다.
- 바닥이 스텝 정의에 저장되지 않는다.

#### 오류와 취소

- 거부는 첫 위반에서 멈춘다. 절차 파일은 사람이 고치는 것이고 한 번에 하나씩 고치는 편이 낫다.
- 로드에서 거부되면 런이 시작되지 않는다. 중간에 멈춘 런을 남기지 않는다.

#### 증거

- 파이프 단조성 시험 파일의 손잡이별 방향 구역과 계층 구역.

#### 수용 기준

- [ ] 손잡이마다 조임 방향이 따로 판정된다.
- [ ] 판정이 해석된 부모와 견준다.
- [ ] 푸는 절차로 런이 시작되지 않는다.
