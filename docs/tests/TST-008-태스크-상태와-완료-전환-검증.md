## 목적과 범위

|---|---|---|---|

| 규칙/회귀 | `checkTasks`, atomic implementation readiness | 개발자 | 자동 |

## 기능별 검증 계약

### TSK-02

#### 사전 조건

- 수용조건과 REQ/TST link를 갖는 태스크, 유효한 project member, 쓰기 가능한 state branch가 있다.

#### 입력과 데이터

- taskId, AC-001, 초기 대기·진행·외부 대기·검토·완료 상태, owner, blocker, externalRefs, 초안/완성 atomic REQ/TST 문서

#### 실행 절차

- acceptance를 done으로 바꾸고 초안 문서 상태에서 done을 시도한 후 문서를 완성해 재시도한다. 각 상태 위반 fixture는 strict check로 진단한다.

#### 기대 결과

- acceptance 필드만 변경되고 atomic gate 미충족 done은 차단되며, 모든 gate 충족 후 done과 시각·operation·commit이 저장된다.

#### 오류와 취소

- 미존재 task/acceptance, 허용되지 않은 status, owner/blocker/review/done gate 위반은 nonzero로 종료하고 task·projection을 rollback한다.

#### 증거

- `test/action.test.js`, `test/git.test.js`, `test/check.test.js`, `test/implementation-contract.test.js` assert, diagnostic JSON, operation/commit, pass 출력

#### 수용 기준

- TSK02-01~08이 통과하고 차단된 전환에서 task status·projection·HEAD가 변하지 않는다.
