# 협업 클라이언트 등록 검증

## 목적과 범위

COL-01의 CLI 등록과 조회, Client YAML 생성, 기본 활성 상태와 소유자 보존을 자동 검증한다. lease 동작은 제외한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 통합 | CLI → collaboration-store → Workspace 저장 | 프로젝트 책임자 | 자동 |
| 단위 | ID·유형·owner·이름·상태 검증 | 프로젝트 책임자 | 자동 보강 대상 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| COL-01-S01 | schemaVersion 6 Workspace와 MEMBER-001 | `client register laptop-a --name 업무 노트북 --type device --owner MEMBER-001` | ID laptop-a, active, client YAML 생성 | P0 |
| COL-01-S02 | S01 완료 | `client show laptop-a` | owner MEMBER-001과 등록 필드 반환 | P0 |
| COL-01-S03 | 같은 ID 등록됨 | 동일 ID 재등록 | 오류, 기존 YAML 불변 | P1 |
| COL-01-S04 | 등록 Client | disable 후 enable | 상태와 revision이 각 전이마다 변경 | P1 |
| COL-01-S05 | 유효 Workspace | 잘못된 ID·type·owner·빈 name 등록 | 각 요청 거절, 파일 미생성 | P1 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 원자성 | 부분 YAML 미노출 | 임시 Git 저장소 | 저장 후 YAML 필드와 임시 파일 부재 검사 |
| 결정성 | Client 목록 파일명 순 정렬 | 복수 Client fixture | 반복 목록 결과 비교 |

## 테스트 데이터와 환경

OS 임시 디렉터리에 Git main 저장소를 초기화하고 `rdl init crm`으로 schemaVersion 6 Workspace를 만든다. 테스트가 만든 저장소는 종료 시 재귀 삭제하며 실제 사용자 경로와 자격 증명을 사용하지 않는다.

## 통과 기준

- `node test/collaboration-store.test.js`가 종료 코드 0이고 COL-01-S01~S02를 충족한다.
- 보강된 유효성·상태 테스트를 포함한 관련 전체 테스트에서 실패가 없다.

## 기능별 검증 계약

### COL-01

#### 사전 조건

- Git identity가 설정된 임시 저장소와 schemaVersion 6 Workspace, `project.md`의 MEMBER-001이 존재한다.

#### 입력과 데이터

- 유효값 `laptop-a`, `업무 노트북`, `device`, `MEMBER-001`과 중복·형식 오류 변형을 사용한다.

#### 실행 절차

- CLI를 임시 Workspace 절대 경로와 `--json` 옵션으로 호출하고 반환 JSON, Client 파일, 조회 및 상태 변경 결과를 순서대로 검사한다.

#### 기대 결과

- 유효 등록은 revision 1·active YAML과 commit을 만들고 조회 값이 일치한다. 실제 상태 전이만 revision을 증가시킨다.

#### 오류와 취소

- 중복 및 입력 오류는 비정상 종료하고 기존 파일을 보존한다. 취소 상태는 없고 상태 되돌리기는 enable/disable 반대 전이로 검증한다.

#### 증거

- `test/collaboration-store.test.js` 실행 로그, 반환 JSON, `projects/workspace/clients/client-laptop-a.yaml` 내용.

#### 수용 기준

- REQ-019의 등록·조회·상태·원자성 기준을 모두 자동 assertion으로 입증한다.
