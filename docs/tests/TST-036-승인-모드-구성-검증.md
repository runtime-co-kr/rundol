# 승인 모드 구성 검증

## 목적과 범위

네 모드가 손잡이 넷의 값을 각각 정하는지, 조합이 코드에 있고 파일이 덮을 수 없는지, 위임 불가 티어가 어느 모드에서도 열리지 않는지, 사전 위임 없는 승인이 거부되는지를 검증한다. 파이프별 단조성은 검증하지 않는다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 모드 조합 조회 함수 | 개발 | 자동 |
| 통합 | 승인 기록 경로와 원장 | 개발 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| RDLAPPRMODE01 | 모드 이름 넷 | 각각 조회한다 | 손잡이 넷의 값이 모두 정해져 나온다 | 높음 |
| RDLAPPRMODE02 | 사람만 모드 | 판정을 근거로 승인 | 거부되고 읽음 근거가 필요하다고 알린다 | 높음 |
| RDLAPPRMODE03 | AI 혼합 모드 | 검증자 없이 진행 | 거부된다 | 높음 |
| RDLAPPRMODE04 | AI 우선 모드, 검증이 반박함 | 진행한다 | 자동 통과하지 않고 사람 개입 지점에 선다 | 높음 |
| RDLAPPRMODE05 | AI만 모드, 사전 위임 있음 | 승인을 기록한다 | 기록되고 행위자와 승인자가 다르며 위임을 가리킨다 | 높음 |
| RDLAPPRMODE06 | AI만 모드, 위임 없음 | 승인을 기록한다 | 거부되고 승인이 남지 않는다 | 높음 |
| RDLAPPRMODE07 | AI만 모드, 위임이 만료됨 | 승인을 기록한다 | 거부된다. 기록 시각과 만료 시각을 견준다 | 높음 |
| RDLAPPRMODE08 | 위임 불가 티어 전체 | 네 모드로 각각 시도한다 | 어느 모드에서도 열리지 않는다 | 높음 |
| RDLAPPRMODE09 | 파일에 모드 조합을 적음 | 조회한다 | 파일 값이 무시되고 코드 조합이 나온다 | 높음 |
| RDLAPPRMODE10 | 조합의 일부만 바꾸려 함 | 저장한다 | 거부되고 모드 이름으로만 정한다고 알린다 | 높음 |
| RDLAPPRMODE11 | 네 모드 | 강약 순위를 매긴다 | 사람만이 가장 조이고 AI만이 가장 푼 쪽이다 | 높음 |
| RDLAPPRMODE12 | 같은 모드에서 검증자 수만 다름 | 순위를 매긴다 | 순위가 같다. 검증자 수가 순위에 영향을 주지 않는다 | 중간 |
| RDLAPPRMODE13 | 모든 모드의 승인 기록 | 승인자 필드를 훑는다 | 전부 구성원 식별자다 | 높음 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 책임 귀속 | 어느 모드에서도 승인의 책임 주체가 사람이다 | 로컬 | 승인 기록의 승인자 필드 전수 확인 |
| 실패 방향 | 모드 판정이 애매하면 더 조인 쪽으로 읽는다 | 로컬 | 판정 불능 입력에 대한 동작 확인 |
| 결정성 | 같은 모드 이름이면 같은 조합 | 로컬 | 반복 조회 결과 비교 |

## 테스트 데이터와 환경

임시 작업공간에 프로젝트와 클라이언트를 만들고 끝나면 지운다. 위임은 시험 안에서 부여하며, 만료 시나리오는 과거 만료 시각으로 부여해 시계에 기대지 않는다. 위임 불가 티어 목록은 코드에서 가져와 전수로 돈다 — 시험이 목록을 다시 적으면 티어가 늘어날 때 새 항목이 검증되지 않은 채 남는다.

## 통과 기준

- 열세 시나리오가 모두 통과한다.
- 위임 불가 티어 전체가 네 모드 모두에서 열리지 않는다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-064#FN-001

#### 사전 조건

- 임시 작업공간에 프로젝트와 등록된 클라이언트가 있다.
- 결정 카탈로그와 승인 근거 종류 목록이 코드에서 읽힌다.

#### 입력과 데이터

- 모드 이름 넷.
- 위임 불가 티어 목록. 코드에서 가져온다.
- 사전 위임 하나와 만료된 위임 하나.

#### 실행 절차

1. 임시 작업공간과 프로젝트와 클라이언트를 만든다.
2. 모드를 정하고 손잡이 조합을 조회한다.
3. 위임 시나리오는 위임을 먼저 부여한다.
4. 승인을 기록하고 원장을 읽는다.
5. 티어 전수 시나리오는 네 모드 × 위임 불가 티어로 돈다.

#### 기대 결과

- 조합 조회가 손잡이 넷을 모두 채워 낸다.
- 사전 위임 없는 AI만 모드에서 승인이 원장에 남지 않는다.
- 승인 기록의 승인자가 언제나 구성원 식별자다.
- 파일이 조합을 덮지 못한다.

#### 오류와 취소

- 알 수 없는 모드 이름과 조합의 부분 변경 시도를 서로 다른 메시지로 구분한다.
- 승인이 거부되면 원장에 아무것도 남지 않는다. 절반만 기록된 상태를 만들지 않는다.

#### 증거

- 승인 모드 시험 파일의 조합 구역과 위임 구역과 티어 전수 구역.

#### 수용 기준

- [ ] 위임 불가 티어가 네 모드 전수에서 열리지 않는다.
- [ ] 사전 위임 없는 승인이 원장에 남지 않는다.
- [ ] 파일이 모드 조합을 덮지 못한다.
