# 문서 이력과 두 지점 비교 검증

## 목적과 범위

한 문서의 원장 사건 세 종류와 커밋과 연결 태스크가 한 답에 실리는지, 어느 기록으로도 설명되지 않는 변경이 드러나는지, 이력과 차분이 스냅숏에 실리지 않는지, 지점이 리비전 해시와 커밋 해시를 둘 다 받고 종류를 길이로 가르는지, 16진수 밖의 값이 git에 닿기 전에 막히는지, 커밋을 찾지 못한 지점이 빈 차분으로 그려지지 않는지, 그리고 없는 문서와 모양 아닌 지점이 서버 결함과 갈리는지를 검증한다.

기준이 원장에 못박힌 두 비교 축, 이력을 그리는 화면의 진입과 상태, 승인·제출·반려를 남기는 조작은 검증하지 않는다.

## 테스트 데이터와 환경

저장소는 시험 안에서 임시로 만들고 커밋을 여러 개 쌓는다. 커밋된 리비전이 있어야 지점이 성립하므로 문서를 고칠 때마다 커밋한다. 커밋되지 않은 지점 시나리오는 고치기만 하고 커밋하지 않은 판의 리비전을 지점으로 쓴다.

이름이 바뀐 문서 시나리오는 실제로 파일을 옮기고 커밋한다. 옮기지 않고 지어낸 이력으로는 이름 추적이 실제로 붙어 있는지 확인할 수 없다.

원장은 임시 작업공간에 실제 사건 파일로 만든다. 승인만 있는 문서, 반려가 두 번 있은 문서, 아무 사건도 없는 문서를 따로 준비한다 — 경고가 나오는 조건과 나오지 않는 조건이 각각 여럿이라 한 문서로는 갈리지 않는다.

지점 시나리오는 저장소 없이 값만 넣고 돌린다. 모양에서 막히는 값들은 git을 부르기 전에 걸려야 하므로 git 호출을 관찰할 수 있게 감싸고, 거절된 값에 대해 호출 수가 0인지 본다. 이 확인이 없으면 "거절되더라"까지만 보고 그 전에 git이 이미 불렸는지는 모르게 된다.

한글 파일명 시나리오는 이 저장소의 실제 정본 문서 하나를 대상으로 돌린다. 합성 파일명으로는 이 저장소가 실제로 겪는 이스케이프를 재현하지 못한다.

접기 횟수와 후보 목록 생성 횟수는 해당 함수를 감싸 호출 수를 세어 확인한다. 시간으로 재면 기계에 따라 흔들린다.

## 통과 기준

- 시나리오가 모두 통과한다.
- 스냅숏 응답의 칸 목록에 이력과 차분이 하나도 없다.
- 모양에서 거절된 지점에 대해 git 호출 수가 0이다.
- 커밋을 못 찾은 답과 같은 커밋일 때의 빈 차분이 서로 다른 값으로 구별된다.
- 한 이력 조회의 원장 접기 횟수가 1이다.
- 두 지점이 모두 리비전일 때 후보 목록 생성 횟수가 1이다.
- 세 비교 축의 차분 머리줄에 이스케이프된 파일명이 없다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-080#FN-001

#### 사전 조건

- git 저장소 안에 있는 임시 작업공간과 프로젝트 하나.
- 커밋이 여러 개 쌓인 문서, 이름이 바뀐 문서, 커밋이 없는 문서.
- 승인·제출·반려가 모두 있는 문서, 승인만 있는 문서, 사건이 없는 문서.
- 태스크가 연결된 문서와 연결되지 않은 문서.
- 한글 파일명을 가진 실제 정본 문서 하나.
- git 호출과 원장 접기와 후보 목록 생성을 셀 수 있는 감싸개.

#### 입력과 데이터

- 프로젝트 키와 문서 ID.
- 지점 값 — 64자리 16진수, 7자리, 40자리, 6자리, 41자리에서 63자리 사이, 16진수 밖 글자가 섞인 것, 빈 문자열, 대문자로 적은 것.
- 비교 축 이름 — 정해진 축 둘, 지점을 받는 축 하나, 그리고 목록에 없는 이름 하나.
- 커밋되지 않은 작업본의 리비전 하나와 저장소에 없는 커밋 해시 하나.

#### 실행 절차

1. 문서 벌마다 이력을 읽어 원장 세 종류와 커밋과 태스크와 경고 유무를 본다.
2. 이름이 바뀐 문서의 이력에서 커밋이 이름을 바꾼 자리 너머로 이어지는지 본다.
3. 같은 문서를 화면 경로와 명령줄 경로로 읽어 두 답을 견준다.
4. 스냅숏을 읽어 칸 목록에 이력과 차분이 있는지 본다.
5. 지점 값을 하나씩 넣어 종류와 거절을 가르고, 거절된 값에 대해 git 호출 수를 센다.
6. 두 지점을 골라 차분을 읽고, 성립하는 갈래와 성립하지 않는 갈래를 각각 확인한다.
7. 두 지점이 모두 리비전인 경우로 돌려 후보 목록 생성 횟수를 센다.
8. 한글 파일명 문서로 세 축을 모두 돌려 차분 머리줄을 본다.
9. 정해진 축에 지점을 함께 보내 그 축의 기준이 움직이지 않는지 본다.

#### 기대 결과

- 이력이 원장 세 종류와 커밋과 태스크를 한 답에 담고, 설명할 기록이 없는 문서에만 경고를 더한다.
- 스냅숏에 이력과 차분이 없다.
- 지점의 종류가 길이로 갈리고, 종류를 따로 받는 칸이 없다.
- 모양이 아닌 지점이 git 호출 전에 거절된다.
- 커밋을 못 찾은 답이 빈 차분과 다른 값으로 온다.
- 차분이 그 문서 파일로 좁혀 나온다.
- 세 축의 차분 머리줄이 사람이 읽을 수 있는 파일명을 보인다.

#### 오류와 취소

- 없는 문서는 찾지 못했다고 거절하고 서버 결함으로 내지 않는다.
- 빈 지점과 모양이 아닌 지점과 모르는 축은 부르는 쪽이 고칠 수 있는 거절이며, 무엇이어야 하는지를 함께 말한다.
- 커밋을 못 찾은 것은 거절이 아니라 답이다. 어느 지점을 못 찾았는지와 왜 커밋된 지점만 비교가 되는지를 낸다. 이 갈래를 거절로 다루면 실패다.
- git 이력을 읽지 못하는 저장소에서 이력 조회가 통째로 죽지 않는다. 커밋 줄만 비고 원장 줄은 선다.
- 취소할 것이 없다. 읽기만 하는 자리다.

#### 증거

- 이력 시험 파일의 원장 구역과 커밋 구역과 태스크 구역과 경고 구역.
- 이름 추적 시험 파일의 파일 이동 구역.
- 스냅숏 시험 파일의 칸 목록 확인 구역.
- 지점 해소 시험 파일의 길이별 구역과 git 호출 수 확인 구역.
- 두 지점 비교 시험 파일의 성립 구역과 미성립 구역과 후보 목록 횟수 구역.
- 파일명 시험 파일의 세 축 머리줄 확인 구역.

#### 수용 기준

- [ ] 원장 세 종류와 커밋과 태스크가 한 답에 실림을 확인한다.
- [ ] 경고가 나오는 조건과 나오지 않는 조건을 각각 확인한다.
- [ ] 스냅숏 칸 목록에 이력과 차분이 없음을 확인한다.
- [ ] 지점의 종류가 길이로만 갈리고 종류 칸이 없음을 확인한다.
- [ ] 거절된 지점에 대해 git 호출 수가 0임을 확인한다.
- [ ] 커밋을 못 찾은 답과 빈 차분이 다른 값임을 확인한다.
- [ ] 원장 접기 횟수와 후보 목록 생성 횟수가 각각 1임을 확인한다.
- [ ] 세 축의 차분 머리줄에 이스케이프된 파일명이 없음을 확인한다.
