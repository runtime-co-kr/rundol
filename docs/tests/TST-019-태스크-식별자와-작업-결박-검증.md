# 태스크 식별자와 작업 결박 검증

## 목적과 범위

태스크 식별자 축약과 저장 시점의 태스크 결박을 함께 검증한다. 축약은 결박의 전제이고 결박 시험은 축약된 식별자를 그대로 쓰므로 증거를 나누지 않는다. 문서 계약 평가 자체는 이 문서가 다루지 않는다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 식별자 생성과 형식 검사 | 문서 식별자와 같은 규칙 | 자동 |
| 통합 | 이관과 참조 갱신 | 전부 성공 또는 전부 보류 | 자동 |
| 통합 | 저장 시점 강제 | 두 축의 독립과 우회 기록 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| S-01 | 빈 프로젝트 | 태스크 생성 | 식별자가 문서와 같은 형식 | 높음 |
| S-02 | 옛 식별자 태스크와 참조 | 이관 | 수·상태 분포가 같고 참조가 새 식별자를 가리킴 | 높음 |
| S-03 | 충돌하는 이관 대상 | 이관 | 아무것도 바꾸지 않고 멈춤 | 높음 |
| S-04 | 거부 수준, 태스크 없음 | 저장 | 거부되고 작업 트리가 그대로 | 높음 |
| S-05 | 거부 수준, 진행 중 태스크 하나 | 저장 | 추론하고 고른 것을 출력 | 높음 |
| S-06 | 거부 수준, 진행 중 태스크 둘 | 저장 | 추론하지 않고 지정을 요구 | 높음 |
| S-07 | 거부 수준 | 사유와 함께 우회 저장 | 커밋에 사유가 남음 | 높음 |
| S-08 | 경고 수준 | 태스크 없이 저장 | 저장되고 진단이 남음 | 높음 |
| S-09 | 강제를 지나지 않은 커밋 | 검사 | 진단으로 드러남 | 중간 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 가독성 | 식별자를 사람이 옮겨 적을 수 있음 | — | 길이와 알파벳이 문서 식별자와 동일 |
| 무해성 | 기존 프로젝트 동작 불변 | 스칼라 강제 수준 프로젝트 | 변경 전후 저장 결과 대조 |

## 테스트 데이터와 환경

임시 워크스페이스에 프로젝트를 만들고 옛 형식 식별자를 가진 태스크와 그것을 가리키는 참조를 미리 넣는다. 강제 수준은 두 축을 따로 설정해 조합별로 확인한다. 우회 사유가 설정에 남지 않는지는 두 번째 저장에서 다시 요구되는지로 관찰한다. 시험이 끝나면 임시 워크스페이스를 지운다.

## 통과 기준

- [ ] S-01~S-09가 모두 통과한다.
- [ ] 강제를 껐을 때 S-04가 실패한다.
- [ ] 기존 태스크 스위트가 변경 없이 통과한다.

## 기능별 검증 계약

### TSK-03

#### 사전 조건

- 태스크 저장소가 유효하고 진행 중인 이관이 없다.

#### 입력과 데이터

- 옛 형식 식별자를 가진 태스크 집합과 그것을 가리키는 참조, 그리고 의도적으로 충돌하는 이관 대상 하나

#### 실행 절차

- 새 태스크를 만들어 식별자 형식을 확인하고, 이관을 수행해 태스크 수·상태 분포·참조를 대조하며, 충돌 상황에서 이관을 시도한다.

#### 기대 결과

- 새 식별자가 문서 식별자와 같은 형식이고, 이관 후 태스크 수와 상태 분포가 같으며, 참조가 모두 새 식별자를 가리킨다.

#### 오류와 취소

- 충돌이 발견되면 아무것도 바꾸지 않고 무엇이 충돌했는지 알린다. 이관 대상이 없으면 아무 일도 하지 않는다.

#### 증거

- 이관 전후의 태스크 목록과 상태 분포, 참조 갱신 결과, 충돌 시의 저장소 무변경 확인

#### 수용 기준

- S-01~S-03이 통과한다.

### TSK-04

#### 사전 조건

- 프로젝트에 태스크 저장소가 있고 두 강제 축의 수준이 정해져 있다.

#### 입력과 데이터

- 저장 대상 변경, 강제 수준 두 축의 조합, 지정한 태스크 식별자 또는 우회 사유, 진행 중인 태스크 집합

#### 실행 절차

- 거부 수준에서 태스크 없이·지정하고·추론되게·둘 이상일 때 각각 저장하고, 우회로 저장한 뒤 커밋을 읽으며, 경고 수준에서 같은 저장을 반복한다.

#### 기대 결과

- 거부 수준에서 근거 없는 저장은 거부되고 지정하면 저장되며, 진행 중 태스크가 하나면 추론하고 고른 것을 출력하고 둘 이상이면 지정을 요구한다. 우회 저장의 커밋에 사유가 남고, 경고 수준은 저장하되 진단을 남긴다.

#### 오류와 취소

- 지정한 태스크가 없거나 이 프로젝트의 것이 아니면 저장하지 않는다. 거부된 저장은 작업 트리를 바꾸지 않으므로 되돌릴 것이 없다.

#### 증거

- 각 조합의 저장 결과와 종료 상태, 커밋에 남은 태스크와 우회 사유, 경고 수준의 진단, 강제를 지나지 않은 커밋에 대한 검사 진단

#### 수용 기준

- S-04~S-09가 통과하고, 강제를 무력화했을 때 S-04가 실패한다.
