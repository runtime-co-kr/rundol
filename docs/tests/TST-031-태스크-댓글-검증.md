# 태스크 댓글 검증

## 목적과 범위

태스크 댓글의 작성·조회와 작성 주체 판정을 검증한다. 알림과 문서 댓글은 대상이 아니다.

특히 ADR-020이 정한 제약 — AI가 쓴 것이 승인 근거가 되지 않는다 — 이 선언이 아니라 값으로 지켜지는지를 본다. 선언만 있고 값이 없으면 다음에 그 값을 읽는 코드가 생길 때 아무도 막지 못한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 작성 주체 파생, 제출 계약, 정렬과 집계 | 개발 | 자동 |
| 통합 | `rdl task comment`·`rdl task comments`와 원장 조각 | 개발 | 자동 |

## 테스트 데이터와 환경

작업공간은 임시 디렉터리에 새로 만들고 끝나면 지운다. 개발자 기계에 붙은 작업공간에 기대면 CI에서 죽는다. Client 둘을 서로 다른 유형으로 등록해 자격이 실제로 갈리는지 본다.

정렬과 집계는 손으로 만든 이벤트 배열로 검증한다. 실제 작성으로는 같은 시각의 댓글 둘을 만들기 어렵고, 그 경우가 바로 두 세션이 동시에 쓸 때 생기는 것이다.

## 통과 기준

- 열두 시나리오가 모두 통과한다.
- 네 OS·Node 매트릭스에서 같은 결과가 나온다.

## 기능별 검증 계약

### CMT-01

#### 사전 조건

- 임시 작업공간에 프로젝트 하나와 태스크 하나가 있다.
- Client 둘이 각각 device와 agent로 등록되어 있다.

#### 입력과 데이터

- 시험 안에서 만든 태스크 식별자.
- 손으로 만든 이벤트 배열(정렬·집계용).

#### 실행 절차

1. 판정 함수를 직접 불러 주체 파생과 제출 계약을 확인한다.
2. 임시 작업공간을 만들고 Client 둘을 등록한다.
3. 두 Client로 각각 댓글을 남긴다.
4. 태스크 지정 조회와 미지정 조회를 실행한다.
5. 거절 경로를 하나씩 실행한다.

#### 기대 결과

- 사람 댓글의 자격이 참, 에이전트 댓글의 자격이 거짓이다.
- 조각 파일 수가 작성 Client 수와 같다.
- 조회 순서가 시각과 Client 식별자로 결정된다.
- 거절된 작성이 파일을 남기지 않는다.

#### 오류와 취소

- 계약 위반은 사유 코드를 갖는 예외다. 코드가 갈려야 호출자가 다르게 다룰 수 있다.

#### 증거

- `test/comment.test.js`.
