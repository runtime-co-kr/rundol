# 핵심 기능 통합 검증

## 목적과 범위

이 문서는 Rundol의 사용자 흐름이 기존 Git 정본과 사용자 파일을 손상하지 않고 함께 동작하는지 검증한다. 테스트는 기능 존재 여부뿐 아니라 실패 후 byte·ref·commit 복구, 사람용 출력과 JSON의 의미 일치, 사람과 AI 클라이언트의 동일 정책 해석을 증명해야 한다.

검증 범위는 다음과 같다.

- 로컬·원격 Rundol 상태 발견과 `rdl init` action 분류
- 기존 프로젝트 자동 attach, 다중 프로젝트 선택과 누락 worktree 복구
- guided·비대화형 문서 profile과 `project.md` documentProfile schema
- required·recommended·onDemand·disabled 정책 검사
- canonical 문서 경로, legacy 진단·migration과 rollback
- 프로젝트 헌장, 정규 문서, 실제 파일명 link와 책임 구조
- 태스크, 완료 조건, shard, Client, lease와 projection
- Workspace 선행 sync, fast-forward·merge·pending conflict와 해결
- Board 조회·쓰기 API, revision 충돌, rollback과 보안 header
- 설치·doctor·skill·Obsidian·action·package·release gate

최우선 위험은 기존 원격 프로젝트를 신규 상태로 오인하는 것, 제품 branch 오염, profile drift, 문서 중복 정본, migration 부분 반영, 원격 변경 유실, stale revision 덮어쓰기와 credential·문서 본문 로그 유출이다.

외부 Git hosting 자체의 가용성·backup, 실제 AI provider의 응답 품질·비용, Obsidian third-party plugin, 공개 다중 사용자 Board와 조직별 문서 내용의 최종 승인 판단은 직접 검증 범위에서 제외한다.

## 테스트 원칙

1. 각 수용 기준은 최소 하나의 자동 시나리오 또는 명시적인 수동 증거를 가진다.
2. mutation 시나리오는 작업 전 ref, HEAD, file hash와 remote ref를 기록한다.
3. 실패 기대 시나리오는 단순한 exit code 외에 변경이 없었음을 증명한다.
4. remote 없음, remote ref 없음과 인증·DNS·TLS 실패를 별도 fixture로 구분한다.
5. 사람용 출력과 JSON 결과는 같은 action·project·diagnostic 의미를 가져야 한다.
6. 비대화형 테스트는 stdin을 닫아 의도하지 않은 prompt 대기를 탐지한다.
7. OS·시간·파일 열거 순서에 의존하는 값은 canonical 정렬 또는 injectable clock으로 통제한다.
8. 실제 credential·개인정보·상용 provider는 테스트 데이터로 사용하지 않는다.

## 테스트 데이터와 환경

- 모든 mutation test는 임시 directory와 local bare Git remote를 사용한다.
- 원격 단일·다중·누락 ref·분기 fixture는 같은 seed generator로 결정적으로 생성한다.
- 인증·DNS·TLS 분류는 실제 비밀 없이 synthetic stderr 또는 접근 제한 local endpoint를 사용한다.
- profile fixture는 profile, trait와 override 순열 및 전체 document type 집합을 포함한다.
- migration fixture는 root·legacy·canonical 문서, filename Wiki link, heading·block link, duplicate ID와 target collision을 포함한다.
- clock 의존 lease와 event는 injectable fixed clock 또는 명시적 허용 오차를 사용한다.
- token·credential·문서 유출 검사는 실제 비밀 대신 검색 가능한 marker를 주입한다.
- 설치 test는 임시 npm cache·prefix와 별도 AI client home을 사용한다.
- browser test는 ephemeral loopback port를 사용하고 `finally`에서 server를 종료한다.
- 외부 network, public registry와 상용 AI provider를 기본 회귀 test의 필수 의존성으로 두지 않는다.
- benchmark 증거에는 OS, CPU, memory, storage, Node·Git version, dataset size와 반복 횟수를 기록한다.

| 목적 | 명령 | 필수 증거 |

CI 증거는 source commit, branch·tag, runtime matrix, 명령, 시작·종료 시각, exit code와 artifact checksum을 포함한다. 실패 로그에는 credential, guided 자유 입력과 문서 본문을 포함하지 않는다.

## 현재 검증 공백

- 현재 `rdl init`은 기존 로컬 Workspace에서 `already-connected`를 반환하지 않고 오류를 내며, 원격 단일·다중 프로젝트를 자동 분류하는 통합 bootstrap state machine이 없다.
- 현재 init과 attach는 별도 구현이므로 discovery snapshot과 action JSON 계약을 공유하지 않는다.
- 현재 project.md에는 documentProfile schema가 없고 guided·profile·trait·override CLI와 policy validator가 없다.
- 현재 `rdl doc create`는 PRD·ARC·GLS를 `docs/` root에 생성하며 canonical path migration과 rollback 구현이 없다.
- 현재 structure audit는 canonical 경로 이탈을 migration 대상으로 보고하지 않는다.
- 문서 번호 예약은 remote Workspace sync·push에 의존하므로 offline ID 생성과 다중 Client 충돌 회피 경계의 추가 검증이 필요하다.
- 현재 CI는 전체 Windows·macOS·Linux 및 최소 runtime matrix를 증명하지 않는다.
- Board 접근성은 정적 string assertion 중심이며 실제 browser·screen reader 증거가 부족하다.
- 대량 문서 migration, 1만 task·lease event와 장시간 sync watch benchmark·soak suite가 없다.
- Board request 크기 한계와 허용 문서 본문 크기가 일치하지 않는다.
