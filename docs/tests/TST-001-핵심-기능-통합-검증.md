# 핵심 기능 통합 검증

## 목적과 범위

이 문서는 런돌의 핵심 사용자 흐름이 일반 파일과 Git 정본을 손상하지 않고 함께 동작하는지 검증한다. 검증 범위는 다음과 같다.

- 새 Git 저장소의 Workspace·프로젝트 초기화와 원격 프로젝트 연결·복구
- 프로젝트 헌장, 정규 문서, Wiki link와 책임 구조의 strict validation
- 태스크 생성·상태·완료 조건·샤드 저장·projection·migration
- Workspace 선행 sync, fast-forward·merge·충돌 기록과 해결
- Board 조회·쓰기 API, revision 충돌·원본 rollback·보안 header
- Client Registry와 문서 soft lease event replay
- 설치·doctor·skill·Obsidian·action·token integration
- package boundary, version·CHANGELOG·tag와 tarball 설치 release gate

검증의 최우선 위험은 제품 branch 오염, 기존 ref·원격 변경 유실, 실패한 쓰기의 부분 반영, 오래된 revision의 덮어쓰기, credential·본문의 로그 유출과 재현 불가능한 package 설치다.

다음은 이 문서의 직접 실행 범위에서 제외한다.

- 외부 Git hosting 서비스 자체의 가용성·권한 정책·backup
- 실제 상용 AI provider 응답 품질과 비용 청구 정확성
- Obsidian binary와 third-party plugin 동작
- 인터넷에 공개된 다중 사용자 Board와 강한 distributed lock
- 조직별 문서 내용의 사업 타당성·최종 승인 판단

## 테스트 데이터와 환경

- 모든 mutation test는 `mkdtemp`로 만든 임시 directory와 local bare Git remote를 사용한다.
- 정적·조회 test는 `test/fixtures/workspace`의 비식별 가상 프로젝트·MEMBER·STAKEHOLDER·task 데이터를 사용한다.
- clock 의존 lease·timestamp test는 허용 오차를 최소화하거나 injectable fixed clock으로 보완한다.
- remote failure는 실제 credential을 사용하지 않고 분류 가능한 synthetic stderr 또는 접근 제한 local fixture를 사용한다.
- token·PAT·본문 유출 검사는 실제 비밀 대신 검색 가능한 marker를 주입한다.
- install test는 임시 npm cache·prefix와 별도 Codex·Claude·Copilot home을 사용한다.
- browser test는 ephemeral loopback port를 사용하고 완료 시 server를 반드시 close한다.
- test가 만든 worktree·remote·package·skill·log는 `finally`에서 정리한다. 실패 분석이 필요할 때만 명시적 keep 환경 변수로 경로를 보존한다.
- 외부 network, public registry와 상용 AI provider를 기본 회귀 test의 필수 의존성으로 두지 않는다.
- 성능 결과에는 OS, CPU, memory, storage, Node·Git version, dataset size와 반복 횟수를 함께 기록한다.

## 실행과 증거

| 목적 | 명령 | 필수 증거 |
|---|---|---|
| 핵심 회귀 | `npm test` | 종료 코드 0, suite별 passed output |
| package 경계 | `npm run test:packages` | package name·dependency·entrypoint 검사 통과 |
| 실제 설치 | `npm run test:install` | 5개 tarball, 통합·개별 executable version과 doctor 결과 |
| version 계약 | `npm run version:check` | 현재 version과 선택 tag 일치 |
| release gate | `npm run release:check` | version·전체 test·install test 모두 통과 |
| 실제 프로젝트 | `node bin/rdl.js check --project rundol --strict --json` | errors 0, warnings 0, document·task count |

CI 증거는 source commit, branch 또는 tag, runtime matrix, 명령, 시작·종료 시각, exit code와 test artifact checksum을 포함해야 한다. 실패 log에는 credential, prompt와 문서 본문을 포함하지 않는다.

## 알려진 검증 공백

- 현재 source test는 주요 Node component와 Windows local 환경에서 실행되지만, 문서에 정의한 전체 OS·최소 runtime matrix 증거는 CI 설정으로 추가 확인해야 한다.
- Board의 360~1440px 시각 회귀와 screen reader 흐름은 정적 UI assertion만으로 충분하지 않아 browser 기반 접근성 test가 필요하다.
- API document validator는 512KiB를 검사하지만 공통 request parser가 64KiB를 먼저 제한한다. `REQ-005` 목표와 `API-001` 현행 계약의 정합성 해결 후 boundary test를 갱신해야 한다.
- 1만 entity·10만 debug event benchmark와 장시간 sync watch soak test는 현재 기본 `npm test`와 분리된 성능 suite가 필요하다.
- 실제 사설 registry·폐쇄망 반입·기업 proxy는 환경별 acceptance runbook과 증거가 필요하다.
