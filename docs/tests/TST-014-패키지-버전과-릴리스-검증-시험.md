## 테스트 데이터와 환경

현재 저장소 manifest와 CHANGELOG, 임시 staging/package/npm cache/prefix를 사용한다. CLI package는 pack 전에 build하고 내부 의존성은 앞서 만든 로컬 tarball 경로로 치환한다. 임시 파일은 종료 시 삭제한다.

## 통과 기준

- `npm run version:check`, `node test/release.test.js`, `node test/packages.test.js`, `npm run test:install`이 모두 종료 코드 0이다.
- CI와 release workflow가 검사 선행, matrix, OIDC, 게시 순서와 skip 조건을 유지한다.

## 기능별 검증 계약

### REL-01

#### 사전 조건

- 모든 package manifest, CHANGELOG, build script, npm과 테스트용 쓰기 가능한 임시 prefix가 존재한다.

#### 입력과 데이터

- 유효/무효 SemVer 표본, 현재 `0.22.2` 계열 manifest, 일치/불일치 tag, 6개 workspace package와 5개 설치 tarball을 사용한다.

#### 실행 절차

- version/release/package 테스트를 실행하고 의존 순서대로 package를 pack한 뒤 통합 tarball을 설치해 CLI·doctor·check를 호출한다.

#### 기대 결과

- 모든 버전·이름·의존성·CHANGELOG·tag가 일치하고 설치된 세 실행 파일이 루트 version을 출력하며 doctor/check errors가 0이다.

#### 오류와 취소

- 어느 issue, build, pack, install, CLI, test 실패도 release check를 실패시킨다. publish 단계는 선행 검증 실패 시 실행되지 않는다.

#### 증거

- version check issues/result, release/packages/install 테스트 로그, 생성 tarball 수, CLI version 출력과 GitHub Actions 실행 로그.

#### 수용 기준

- REQ-024의 SemVer, manifest 경계, 실제 설치, CI matrix, trusted publishing과 의존 게시 순서를 모두 검증한다.
