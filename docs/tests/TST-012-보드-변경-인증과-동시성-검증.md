# 보드 변경 인증과 동시성 검증

## 목적과 범위

BOP-02의 모든 비-GET 요청 token 검증과 태스크·문서·계약의 낙관적 동시성, 입력 오류의 비파괴 처리를 검증한다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| HTTP 통합 | Board 변경 endpoint와 공통 인증 | 프로젝트 책임자 | 자동 |
| 저장 통합 | 태스크·문서·계약 revision 전이 | 프로젝트 책임자 | 자동 |
| 경계 | JSON 파싱과 64KiB 제한 | 프로젝트 책임자 | 자동 보강 대상 |

| 품질 속성 | 목표 | 환경 | 측정 방법 |

## 테스트 데이터와 환경

임시 crm Workspace, 고정 token `workspace-token`, 생성 태스크, `project:crm` 문서와 revision 1 계약을 사용한다. 각 변경 전 현재 엔터티를 GET하고 테스트 종료 시 서버와 임시 저장소를 정리한다.

## 통과 기준

- `node test/board.test.js`와 `node test/board-workspace.test.js`가 종료 코드 0이다.
- 400·403·409 경로가 기대 status와 current payload를 반환하고 실패 요청 뒤 상태가 보존된다.

## 기능별 검증 계약

### BOP-02

#### 사전 조건

- token이 고정된 loopback Board와 revision을 가진 태스크·문서·계약이 준비된다.

#### 입력과 데이터

- 올바른/잘못된 token, 현재/과거/누락 baseRevision, 빈/잘못된/초과 JSON과 MEMBER-999를 사용한다.

#### 실행 절차

- 현재 엔터티를 조회하고 정상 변경을 한 번 수행한 뒤 같은 baseRevision으로 재요청한다. 인증·입력 경계 요청은 별도로 전송한다.

#### 기대 결과

- 인증·입력 검증을 통과한 최신 변경만 적용되고 stale 요청은 409와 최신 current를 반환한다.

#### 오류와 취소

- 400·403·409와 body parse/size 오류는 도메인 저장 함수를 적용하지 않는다. 연결 중단도 부분 요청을 반영하지 않는다.

#### 증거

- Board 통합 테스트 로그, HTTP status와 JSON error/current, 변경 전후 revision 및 파일 내용.

#### 수용 기준

- REQ-022의 토큰, 입력 제한, 책임자 검증, 낙관적 동시성과 오류 비파괴 기준을 자동 검증한다.
