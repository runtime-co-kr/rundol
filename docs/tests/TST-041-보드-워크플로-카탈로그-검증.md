# 보드 워크플로 카탈로그 검증

## 목적과 범위

스냅숏이 그 프로젝트에 실제로 걸린 워크플로를 싣는지, 노드 라벨과 전환이 정의에 적힌 대로 오는지, 선언 없음과 빈 목록이 값으로 갈리는지, 배정 없음과 읽기 실패가 갈리는지, 그리고 워크플로 revision이 정의 변경에만 반응하는지를 검증한다.

정의를 고치는 조작과 그 저장 흐름, 전환을 밟는 판정, 스냅숏 응답의 전송 규약은 검증하지 않는다.

## 테스트 데이터와 환경

정의는 시험 안에서 값으로 만들되, 정의 일치 시나리오만 이 저장소의 실제 워크플로 정의를 입력으로 쓴다. 합성 정의로는 상속 세 층이 실제로 겹치는 모양을 만들지 못한다.

읽기 실패 시나리오는 정의 파일을 읽을 수 없는 상태를 만들어 돌린다. 그 시나리오의 통과 기준은 카탈로그가 비지 않는 것과 스냅숏이 세워지는 것 둘이며, 둘 중 하나만 참이면 실패다 — 비면 고칠 자리로 가는 길이 사라지고, 스냅숏이 안 서면 화면 전체가 설정 파일 하나에 인질이 된다.

화면 시나리오는 카탈로그를 값으로 넣고 그린 결과를 본다. 서버를 함께 띄우지 않는 이유는 그리는 규칙이 카탈로그 하나에만 달려 있기 때문이다.

## 통과 기준

- 시나리오가 모두 통과한다.
- 이 저장소의 실제 정의로 만든 카탈로그가 정의 파일과 어긋나지 않는다.
- 선언 없음과 빈 목록이, 그리고 배정 없음과 읽기 실패가 각각 다른 값과 다른 말로 나온다.
- 화면 코드에 상태 이름 리터럴이 하나도 없다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-069#FN-001

#### 사전 조건

- 워크플로 정의와 배정 표가 상속을 거친 상태로 주어진다.
- 상속 층 시나리오는 세 층을 모두 준비한다.
- 읽기 실패 시나리오는 정의를 읽을 수 없는 상태를 준비한다.

#### 입력과 데이터

- 프로젝트 키와 대상 종류와 항목 유형.
- 상속을 거친 워크플로 정의와 배정 표, 그리고 각 층의 출처.
- 스텝 목록과 그 파생 목록.
- 화면 시나리오를 위한 카탈로그 값 — 전환이 실린 것, 자리가 빈 것, 빈 목록인 것 세 벌.

#### 실행 절차

1. 시나리오가 정한 정의와 배정을 만든다.
2. 대상 종류와 항목 유형으로 카탈로그를 만든다.
3. 스냅숏을 읽어 워크플로 칸과 revision을 받는다.
4. revision 시나리오는 정의만 고치거나 태스크만 고친 뒤 다시 읽어 두 revision을 견준다.
5. 화면 시나리오는 카탈로그를 값으로 넣고 그린 결과에서 상태 이름 리터럴과 편집 요소를 찾는다.

#### 기대 결과

- 카탈로그는 대상 종류와 노드 표와 전환 목록과 스텝 목록 넷과 출처를 갖는다.
- 노드 하나는 스텝·유효성·라벨·요구 필드를 갖는다.
- 전환 하나는 출발·도착·제목·승인 여부를 갖고 승인 사유를 갖지 않는다.
- 전환 자리가 빈 것과 빈 목록이 서로 다른 값이다.
- 진단 코드가 카탈로그에 없다.

#### 오류와 취소

- 정의를 읽지 못해도 스냅숏이 세워진다. 카탈로그는 내장으로 채우고 읽지 못했다는 사실을 함께 싣는다.
- 없는 노드를 가리키는 전환은 정의를 받는 자리가 거부한다. 없앤 노드를 가리키던 전환과 다르게 다룬다.
- 취소할 것이 없다.

#### 증거

- 카탈로그 생성 시험 파일의 배정 구역과 상속 구역.
- 스냅숏 시험 파일의 워크플로 칸 구역과 revision 구역.
- 화면 시험 파일의 그리기 구역과 상태 이름 검색 결과.

#### 수용 기준

- [ ] 배정으로 고른 워크플로가 실리고 배정이 없을 때만 내장으로 떨어진다.
- [ ] 라벨과 전환이 정의에 적힌 대로 실린다.
- [ ] 선언 없음과 빈 목록이 값으로 갈린다.
- [ ] 배정 없음과 읽기 실패가 화면에서 다른 말로 갈린다.
- [ ] 워크플로 revision이 정의 변경에만 반응한다.
- [ ] 화면 코드에 노드 이름 리터럴이 없고 편집 요소가 없다.
