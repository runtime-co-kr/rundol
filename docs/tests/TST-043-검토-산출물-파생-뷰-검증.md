# 검토 산출물 파생 뷰 검증

## 목적과 범위

파생 뷰가 합성 뷰와 같은 자리에 놓이는지, 그 자리가 형상 제외 목록에 먼저 들어가는지, 파일이 정본이 아님을 스스로 밝히는지, 앞머리가 옵시디언이 읽는 평면 값과 태그를 갖는지, 본문 변경 판정이 생성 시각에 흔들리지 않는지, 그리고 무엇보다 **내보내기 전후로 정본 문서의 바이트와 리비전이 그대로인지**를 검증한다.

마지막 항목이 이 검증의 중심이다. 승인 감사를 문서에 쓰면 그 쓰기가 리비전을 바꿔 방금 한 승인을 낡게 만들고, 그 자기모순을 피하려고 파생 뷰라는 길을 골랐다. 파생 뷰가 정본을 한 바이트라도 건드리면 그 길을 고른 이유가 사라진다.

산출물의 내용과 판정은 검증하지 않는다. TST-042가 갖는다. 옵시디언이 이 파일을 어떻게 그리는지도 검증하지 않는다 — 볼트가 읽는 형식으로 놓는 데까지가 이 요구의 경계다.

## 테스트 데이터와 환경

작업공간과 프로젝트는 시험 안에서 만든다. 볼트 루트는 그 프로젝트의 루트이고, 형상 제외 목록은 시나리오마다 다른 초기 상태로 둔다 — 없는 것, 있고 줄이 없는 것, 있고 줄이 이미 있는 것, 마지막 줄에 개행이 없는 것 넷이다.

산출물은 값으로 만들어 넣는다. 이 검증의 대상은 값이 아니라 놓기이므로 값을 만드는 경로를 함께 돌리면 시험이 두 요구에 걸치고, 그러면 값 쪽이 바뀔 때마다 자리 시험이 함께 깨진다. 값은 생성 시각과 셈만 다른 여러 벌을 둔다 — 같은 본문에 다른 시각, 다른 본문에 같은 시각, 검토 대기 0건, 파일 경로가 없는 항목을 가진 것.

정본 불변 시나리오는 문서 몇 건을 실제로 커밋해 둔 프로젝트에서 돌린다. 전 문서의 바이트 해시를 내보내기 전후로 모아 견주고, 문서 상태 조회 결과도 함께 견준다. 바이트만 보면 통과하지만 리비전 판정이 바뀌는 경우를 잡지 못하므로 둘 다 본다.

부분 쓰기 시나리오는 쓰기 도중의 디렉터리 목록을 관찰한다. 대상 이름이 나타나는 순간 그 내용이 완성본이어야 한다.

문서 검사 시나리오는 파생 파일을 놓기 전과 놓은 뒤의 검사 결과를 견준다. 문서 수와 진단 수가 둘 다 그대로여야 한다.

시험이 만든 작업공간은 시험이 끝나면 지운다. 개인정보는 쓰지 않는다.

## 통과 기준

- 시나리오가 모두 통과한다.
- 내보내기 전후로 정본 문서의 바이트가 같고 문서 상태 조회의 답도 같다.
- 형상 제외 목록 손보기가 파일 놓기보다 먼저 일어나 파생 파일이 한 번도 형상에 노출되지 않는다.
- 파일이 정본이 아님을 스스로 밝히고, 앞머리가 평면 값과 태그만 갖는다.
- 본문 변경 판정이 생성 시각의 변화를 바뀜으로 세지 않는다.
- 본문이 같아도 파일이 다시 쓰여 생성 시각이 갱신된다.
- 문서 검사가 이 파일을 문서로 세지 않는다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-071#FN-001

#### 사전 조건

- 작업공간과 프로젝트가 준비되고 볼트 루트에 쓸 수 있다.
- 형상 제외 목록의 초기 상태 네 가지를 각각 준비한다.
- 정본 불변 시나리오는 문서 몇 건이 커밋되어 있고 그중 하나가 승인된 프로젝트를 준비한다.
- 산출물 값 여러 벌을 준비한다. 같은 본문에 다른 시각, 다른 본문에 같은 시각, 검토 대기 0건, 파일 경로가 없는 항목을 가진 것.
- 합성 뷰 파일이 이미 놓인 디렉터리 상태를 하나 준비한다.

#### 입력과 데이터

- 작업공간 시작 경로.
- 산출물 값과 그것에서 만든 마크다운 한 장.
- 형상 제외 목록의 초기 내용.
- 파생 디렉터리의 초기 상태. 없음, 비어 있음, 합성 뷰가 있음, 같은 이름의 파일이 이미 있음.

#### 실행 절차

1. 시나리오가 정한 작업공간과 제외 목록과 디렉터리 상태를 세운다.
2. 정본 불변 시나리오는 먼저 전 문서의 바이트 해시와 문서 상태 조회 결과를 모아 둔다.
3. 산출물 값과 마크다운을 넘겨 내보낸다.
4. 결과 값의 자리와 두 판정을 본다.
5. 놓인 파일의 앞머리와 첫 문단과 본문을 읽는다.
6. 제외 목록의 내용과 형상 상태를 본다.
7. 정본 불변 시나리오는 해시와 문서 상태 조회 결과를 다시 모아 앞의 것과 견준다.
8. 변경 판정 시나리오는 값만 바꿔 다시 내보내고 두 결과를 견준다.
9. 검사 시나리오는 문서 검사를 돌려 문서 수와 진단을 파일이 없을 때와 견준다.

#### 기대 결과

- 파일이 합성 뷰와 같은 디렉터리에 다른 이름으로 놓인다.
- 제외 목록에 파생 디렉터리 줄이 있고, 이번에 넣었는지 여부가 결과에 실린다.
- 앞머리에 생성 판·뷰 이름·제목·프로젝트·생성 시각·낡음 수·미승인 수·태그가 있고 이력 구조가 없다.
- 본문 첫 문단이 정본이 아니며 덮어써진다고 밝힌다.
- 그 아래 본문이 넘겨받은 마크다운과 같다.
- 문서 참조가 볼트 상대 경로에서 확장자를 뗀 링크이며, 경로를 모르면 식별자만 남는다.
- 본문 변경 판정이 앞머리를 뺀 비교의 결과이며 생성 시각에 흔들리지 않는다.
- 내보내기 전후로 정본 문서의 바이트와 문서 상태 조회의 답이 같다.
- 원장에 사건이 쌓이지 않는다.
- 문서 검사의 문서 수와 진단이 파일 유무에 관계없이 같다.

#### 오류와 취소

- 프로젝트를 고르지 못하면 거부하고 파일을 놓지 않는다. 어느 볼트인지 모르는 채로 놓으면 남의 볼트에 남의 값이 남는다.
- 디렉터리를 만들지 못하거나 파일을 쓰지 못하면 그 사실을 그대로 낸다. 조용히 넘어가면 사람은 오래된 파일을 오늘 것으로 읽는다.
- 제외 목록을 고치지 못하는 경우도 실패로 다룬다. 목록 없이 파일만 놓이면 파생이 형상 관리에 노출된다.
- 취소할 것이 없다. 제자리로 옮기기 전에 그만두면 임시 파일만 남고 읽는 쪽은 아무 변화도 보지 못한다.

#### 증거

- 자리 시험 파일의 디렉터리 구역과 제외 목록 구역.
- 파일 내용 시험 파일의 앞머리 구역과 고지 문단 구역과 링크 구역.
- 변경 판정 시험 파일의 시각 구역과 본문 구역.
- 정본 불변 시험이 남긴 내보내기 전후의 문서 해시 목록과 문서 상태 조회 결과.
- 형상 상태 확인 결과.
- 문서 검사 결과 두 벌.

#### 수용 기준

- [ ] 파일이 합성 뷰와 같은 자리에 겹치지 않는 이름으로 놓인다.
- [ ] 제외 목록 손보기가 파일 놓기보다 먼저 끝난다.
- [ ] 파일이 정본이 아니며 덮어써진다고 스스로 밝힌다.
- [ ] 앞머리가 평면 값과 태그만 갖고 이력 구조를 갖지 않는다.
- [ ] 본문 변경 판정이 생성 시각에 흔들리지 않는다.
- [ ] 본문이 같아도 파일이 다시 쓰이고 생성 시각이 갱신된다.
- [ ] 내보내기 전후로 정본 문서 바이트와 문서 상태 조회의 답이 같다.
- [ ] 원장에 사건이 쌓이지 않는다.
- [ ] 문서 검사가 이 파일을 문서로 세지 않는다.
