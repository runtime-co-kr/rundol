# 정책 층 상속과 병합 검증

## 목적과 범위

세 계층이 순서대로 합쳐지는지, 목록이 합쳐지지 않고 통째로 덮이는지, 명시한 값과 상속받은 값이 구분되는지를 검증한다. 각 계층 파일의 형태 판정은 검증하지 않는다 — 그것은 이 판정의 사전조건이다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 병합 함수 | 개발 | 자동 |
| 통합 | 두 계층 설정을 둔 작업공간에서의 조회 결과 | 개발 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| RDLPOLICYMERGE01 | 세 계층 모두 값을 가짐 | 병합한다 | 프로젝트 값이 최종이고 출처가 프로젝트로 나온다 | 높음 |
| RDLPOLICYMERGE02 | 프로젝트 파일이 없음 | 병합한다 | 작업공간 값이 최종이고 출처가 작업공간으로 나온다 | 높음 |
| RDLPOLICYMERGE03 | 프로젝트가 항목의 한 필드만 선언 | 병합한다 | 그 필드만 덮이고 나머지는 상위 값이 남는다 | 높음 |
| RDLPOLICYMERGE04 | 작업공간 목록이 셋, 프로젝트 목록이 하나 | 병합한다 | 최종 목록의 길이가 하나다 | 높음 |
| RDLPOLICYMERGE13 | 작업공간 맵에 키 둘, 프로젝트가 새 키 하나를 더함 | 병합한다 | 최종 맵에 키가 셋 있다 | 높음 |
| RDLPOLICYMERGE14 | 프로젝트가 상속받은 키를 파일에서 뺌 | 병합한다 | 그 키가 상위 값으로 그대로 남는다 | 높음 |
| RDLPOLICYMERGE15 | 프로젝트가 상속받은 키에 사용 안 함을 명시 | 병합한다 | 키가 결과에 남고 사용 안 함으로 표시되며 출처가 프로젝트다 | 높음 |
| RDLPOLICYMERGE16 | 한 키에만 사용 안 함을 명시 | 병합한다 | 같은 맵의 다른 키에 표식이 번지지 않는다 | 높음 |
| RDLPOLICYMERGE05 | 프로젝트가 상위와 같은 값을 명시 | 상위 값을 바꾸고 다시 병합한다 | 프로젝트 값이 그대로 유지된다 | 높음 |
| RDLPOLICYMERGE06 | 프로젝트가 값을 선언하지 않음 | 상위 값을 바꾸고 다시 병합한다 | 최종 값이 함께 바뀐다 | 높음 |
| RDLPOLICYMERGE07 | 상위 객체를 두 프로젝트에 병합 | 두 번 병합한다 | 상위 객체가 변형되지 않고 두 결과가 서로 독립이다 | 중간 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 결정성 | 같은 세 입력이면 같은 결과 | 로컬 | 반복 호출 결과 비교 |
| 하위 호환 | 표시 필드만 있는 설정의 병합 결과가 변경 전후로 같다 | 로컬과 통합 검사 매트릭스 | 변경 전 결과를 고정값으로 두고 대조 |
| 판정 순수성 | 파일을 직접 읽지 않고 값으로 받는다 | 로컬 | 전이 의존 검사 |

## 테스트 데이터와 환경

계층별 설정 객체는 시험 안에서 값으로 만든다. 파일을 거치지 않아도 되는 시나리오는 파일을 만들지 않는다 — 병합은 순수 판정이고, 파일을 끼우면 무엇이 깨졌는지가 흐려진다. 통합 수준 시나리오만 임시 작업공간을 쓰고 끝나면 지운다.

## 통과 기준

- 열한 시나리오가 모두 통과한다.
- 상위 객체가 병합으로 변형되지 않는다.
- 맵 그룹과 목록형 필드가 각각 자기 규칙으로 합쳐진다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### PLC-02

#### 사전 조건

- 계층별 설정 객체가 이미 형태 판정을 통과한 상태로 주어진다.
- 그룹별 필드 목록에 어떤 필드가 목록형인지가 담겨 있다.

#### 입력과 데이터

- 내장 기본값 객체 하나와 작업공간 객체와 프로젝트 객체. 뒤의 둘은 없을 수 있다.
- 목록형 필드를 최소 하나 포함한 그룹과, 키가 둘 이상인 맵 그룹 하나.
- 사용 안 함 표식을 붙일 상속 키 하나와, 표식이 번지는지 볼 이웃 키 하나.

#### 실행 절차

1. 시나리오가 정한 계층별 객체를 만든다.
2. 병합을 호출한다.
3. 합쳐진 객체와 계층별 원본과 출처 정보를 받는다.
4. 상위 값을 바꾸는 시나리오는 상위 객체를 새로 만들어 다시 병합한다.

#### 기대 결과

- 합쳐진 값이 가장 아래 계층이 선언한 값과 같다.
- 목록의 길이가 하위 계층이 선언한 길이와 같다.
- 출처 정보가 값마다 계층 이름을 담는다.
- 명시한 값과 상속받은 값이 서로 다르게 표시된다.

#### 오류와 취소

- 그룹이나 필드가 목록에 없으면 예외. 다만 이 상황은 사전조건 위반이므로 방어적 검사다.
- 취소 지점은 없다.

#### 증거

- 병합 시험 파일의 계층 우선순위 구역과 목록 덮기 구역.

#### 수용 기준

- [ ] 필드 단위 덮기와 목록 통째 덮기가 함께 성립한다.
- [ ] 출처 정보가 값마다 계층을 지목한다.
- [ ] 상위 객체가 병합 뒤에도 그대로다.
