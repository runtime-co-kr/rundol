# 정책 층 값의 저장 형태 검증

## 목적과 범위

정책 필드가 표시 필드와 형제로 저장되는지, 허용 목록 밖의 필드가 거부되는지, 판수 규칙과 식별자 형식이 지켜지는지를 검증한다. 어떤 값이 어느 층인지의 분류는 검증하지 않는다 — 그것은 결정이 정하는 것이고 이 판정의 입력이다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 설정 정규화 함수 | 개발 | 자동 |
| 통합 | 설정을 읽는 명령의 종료 코드와 메시지 | 개발 | 자동 |

## 시나리오

| ID | 사전조건 | 실행 | 기대 결과 | 우선순위 |
|---|---|---|---|---|
| RDLPOLICYSTORE01 | 판수 2 파일에 허용된 정책 필드가 있음 | 설정을 읽는다 | 그 값이 정책 값으로 채택되고 표시 값과 구분되어 나온다 | 높음 |
| RDLPOLICYSTORE02 | 판수 1 파일에 표시 필드만 있음 | 설정을 읽는다 | 정상 파싱되고 이 변경 이전과 같은 결과가 나온다 | 높음 |
| RDLPOLICYSTORE03 | 판수 1 파일에 정책 필드가 있음 | 설정을 읽는다 | 거부되고 판수를 올리라는 안내가 나온다 | 높음 |
| RDLPOLICYSTORE04 | 허용 목록에 없는 필드가 있음 | 설정을 읽는다 | 거부되고 파일 경로와 키 경로가 메시지에 담긴다 | 높음 |
| RDLPOLICYSTORE05 | 저장값에 한글 표시 문구가 들어 있음 | 설정을 읽는다 | 거부되고 식별자 형식을 알린다 | 중간 |
| RDLPOLICYSTORE06 | 표시 필드와 정책 필드가 한 항목에 함께 있음 | 설정을 읽는다 | 둘이 결과에서 나뉘어 담긴다 | 중간 |

## 비기능 검증

| 품질 속성 | 목표 | 환경 | 측정 방법 |
|---|---|---|---|
| 하위 호환 | 기존 판수 1 설정의 읽기 결과가 변경 전후로 같다 | 로컬과 통합 검사 매트릭스 | 변경 전 결과를 고정값으로 두고 대조 |
| 결정성 | 같은 파일 내용이면 같은 결과 | 로컬 | 반복 호출 결과 비교 |
| 판정 순수성 | 다른 파일을 읽지 않는다 | 로컬 | 전이 의존 검사 |

## 테스트 데이터와 환경

설정 파일은 시험 안에서 만든다. 작업공간은 임시 디렉터리에 새로 만들고 끝나면 지운다 — 개발자 기계에 붙은 작업공간에 기대면 통합 검사에서 죽는다. 허용 필드 목록은 코드에서 가져와 쓰고 시험이 자기 목록을 다시 적지 않는다. 다시 적으면 목록이 바뀔 때 시험만 통과하고 실제가 어긋난다.

## 통과 기준

- 여섯 시나리오가 모두 통과한다.
- 판수 1 설정에 대한 결과가 변경 이전과 같다.
- 네 운영체제와 실행기 조합에서 같은 결과가 나온다.

## 기능별 검증 계약

### REQ-055#FN-001

#### 사전 조건

- 임시 작업공간에 프로젝트 하나가 있다.
- 그룹별 허용 필드 목록이 코드에서 읽힌다.

#### 입력과 데이터

- 시나리오마다 다르게 구성한 설정 파일 하나의 내용.
- 판수는 시나리오가 정한다.

#### 실행 절차

1. 임시 디렉터리에 작업공간과 프로젝트를 만든다.
2. 시나리오가 정한 내용으로 설정 파일을 쓴다.
3. 설정을 읽는 경로를 호출한다.
4. 결과 객체 또는 예외 메시지를 받는다.

#### 기대 결과

- 허용된 정책 필드는 결과에서 표시 필드와 다른 자리에 담긴다.
- 거부는 예외로 나오며 메시지에 파일 경로와 키 경로가 있다.
- 판수 위반과 알 수 없는 필드와 식별자 형식 위반이 서로 다른 메시지로 구분된다.

#### 오류와 취소

- 거부는 첫 위반에서 멈춘다. 위반 목록을 모으지 않는다.
- 취소 지점은 없다.

#### 증거

- 설정 정규화 시험 파일의 정책 필드 구역.

#### 수용 기준

- [ ] 허용 목록 밖의 키가 파일과 키 경로를 지목해 거부된다.
- [ ] 판수 1 설정이 변경 전과 같은 결과를 낸다.
- [ ] 표시 필드와 정책 필드가 결과에서 구분된다.
