# 작업 할당 발급 검증

## 목적과 범위

[[REQ-048-작업-할당-발급|REQ-048]]이 정의한 WRK-01의 발급 경로를 검증한다. 검증 대상은 필수 항목 판정, 미선언 기능 ID 거부, 수정 가능 경로 겹침 거부, 절차 다이제스트 고정, 워커 종류 무관성, 원격 없는 발급, 그리고 발급·거부·닫힘 사건의 기록이다.

보고 제출과 검수 판정은 대상이 아니다. 워커 어댑터가 자식 프로세스를 어떻게 띄우고 끝내는지도 대상이 아니다. 이 문서는 명세만 담으며 실행 결과는 검증 태스크가 나른다.

## 테스트 수준

| 수준 | 대상 | 책임 | 자동화 여부 |
|---|---|---|---|
| 단위 | 필수 항목 판정과 경로 겹침 판정의 순수 함수 | 구현·검증 담당 | 자동 |
| 통합 | 발급 명령이 원장에 남기는 사건과 반환값 | 구현·검증 담당 | 자동 |
| 시나리오 | 사람 워커와 에이전트 워커에게 같은 할당이 전달되는 경로 | 구현·검증 담당 | 자동 |
| 환경 | 원격 차단 상태의 발급 | 구현·검증 담당 | 자동 |

## 시나리오

| S02 | 기능 ID 목록만 빈 입력이 있다 | 할당을 발급한다 | 발급이 거부되고 응답의 누락 항목 목록이 기능 ID를 지목한다 | high |
| S03 | 정규 문서에 선언되지 않은 기능 ID를 담은 입력이 있다 | 할당을 발급한다 | 발급이 거부되고 응답이 해당 기능 ID를 지목한다 | high |

## 테스트 데이터와 환경

격리된 임시 작업공간에 프로젝트 하나를 만들고, WRK 계열 기능 ID를 선언한 정규 문서를 fixture로 둔다. 개인정보는 쓰지 않으며 워커 식별자는 고정된 더미 값을 사용한다. 외부 서비스 의존은 없고, 원격 차단 시나리오는 remote 미설정 저장소로 대신한다. 각 시나리오는 자기 임시 작업공간을 만들고 종료 시 지운다.

## 통과 기준

- 우선순위 high 시나리오가 모두 통과한다.
- 거부 경로(S02·S03·S04·S06·S13)가 모두 구분되는 사유 코드를 반환하며, 어느 하나도 침묵하지 않는다.
- 결정성 시나리오(S07·S09)가 통과해 절차 고정이 실제로 작동함을 보인다.
- 발급·거부·닫힘 사건이 원장에 남는 것을 S01·S11·S14에서 확인한다.

## 기능별 검증 계약

### WRK-01

#### 사전 조건

- 격리된 임시 작업공간에 프로젝트가 연결되어 있다.
- WRK 계열 기능 ID를 선언한 정규 문서가 fixture로 존재한다.
- 해석 가능한 절차 하나와 해석 불가능한 절차 하나가 준비되어 있다.
- 열린 할당이 없는 상태에서 각 시나리오가 시작한다.

#### 입력과 데이터

- 필수 항목 여덟 가지를 모두 채운 기준 입력 하나.
- 기준 입력에서 항목 하나씩을 뺀 변형 입력들.
- 수정 가능 경로가 겹치는 입력 쌍과 겹치지 않는 입력 쌍.
- 담당 워커만 사람과 에이전트로 다른 입력 쌍.
- 미선언 기능 ID를 담은 입력과 해석 불가 절차를 담은 입력.

#### 실행 절차

1. 임시 작업공간을 만들고 fixture 문서를 배치한다.
2. 기준 입력으로 발급해 식별자와 절차 다이제스트를 받는다.
3. 변형 입력들로 차례로 발급을 시도하고 각 거부 응답을 수집한다.
4. 절차 본문을 바꾼 뒤 이미 발급된 할당을 다시 읽는다.
5. 원격이 없는 저장소에서 기준 입력으로 발급한다.
6. 열린 할당을 사유와 함께 취소하고 같은 경로로 다시 발급한다.
7. 원장에서 발급·거부·닫힘 사건을 읽어 대조한다.
8. 임시 작업공간을 지운다.

#### 기대 결과

- 기준 입력은 할당 식별자와 절차 다이제스트를 반환한다.
- 누락·미선언·겹침·절차 고정 실패가 각각 다른 사유 코드로 거부된다.
- 절차 본문 변경 후에도 발급된 할당의 다이제스트가 그대로다.
- 담당 워커만 다른 두 할당의 본문이 담당 워커 항목을 빼면 같다.
- 원격 없는 환경에서 발급이 성공한다.
- 취소 후 같은 경로로 새 할당이 발급된다.

#### 오류와 취소

- 거부는 실패가 아니라 정의된 응답이므로, 각 거부가 사유 코드와 지목 대상을 함께 반환하는지 확인한다.
- 필수 항목이 둘 이상 비면 모두 열거되는지 확인하고, 첫 항목에서 멈추지 않는지 본다.
- 거부된 발급이 어떤 원장 상태도 바꾸지 않았는지 확인한다. 부분 발급이 남으면 실패로 판정한다.
- 취소된 할당이 다시 열리지 않는지 확인한다.
- 취소가 기존 보고 기록을 지우지 않는지 확인한다.

#### 증거

- 시나리오별 반환값과 사유 코드를 담은 실행 로그.
- 발급 전후의 원장 사건 목록과 그 차이.
- S09 반복 실행의 본문 바이트 비교 결과.
- 네트워크 차단 환경 실행 기록.
- 실행 결과는 이 문서가 아니라 검증 태스크의 판정과 증거로 남긴다.

#### 수용 기준

- 우선순위 high 시나리오가 전부 통과한다.
- 다섯 가지 거부 경로가 서로 구분되는 사유 코드를 반환한다.
- 절차 다이제스트가 절차 본문 변경에 영향받지 않는다.
- 담당 워커 종류가 할당 본문을 바꾸지 않는다.
- 거부된 발급이 원장에 부분 상태를 남기지 않는다.
- 발급·거부·닫힘이 각각 원장 사건으로 확인된다.
