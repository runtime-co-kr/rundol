# 로컬 보드 협업 인터페이스

## 공통 계약

- Base URL은 실행 중인 Board의 `http://127.0.0.1:<port>`이며 외부 interface에 bind하지 않는다.
- API request와 response는 UTF-8 JSON을 사용한다.
- 모든 JSON response는 `Cache-Control: no-store`와 `X-Content-Type-Options: nosniff`를 포함한다.
- GET은 세션 token 없이 조회할 수 있다. GET 이외 method는 실행 시 생성된 값을 `X-Rundol-Token` header로 전달해야 한다.
- 변경 API는 운영체제 파일 권한과 Git 권한을 그대로 사용한다. Client ID와 임대는 인증·권한 수단이 아니다.
- entity의 `revision`은 내용 기반 낙관적 동시성 token이다. 수정 대상 API는 최신 조회의 값을 `baseRevision`으로 요구한다.
- path의 project key, task ID, document ID와 Client ID는 URL encoding 후 전달한다.

## 엔드포인트

### Workspace와 프로젝트 조회

| Method | Path | 목적 | 주요 응답 |
|---|---|---|---|
| GET | `/api/overview` | Workspace 전체 프로젝트와 태스크 집계 | `schemaVersion`, `projects`, `totals` |
| GET | `/api/projects` | 등록 프로젝트 목록 | project summary 배열 |
| GET | `/api/projects/:key` | 단일 프로젝트 요약 | key, name, 상태별 task count |
| GET | `/api/projects/:key/board-snapshot` | UI 통합 snapshot | 영역별 revision, documents, tasks, attention, people, clients, leases, sync |

- 인증/권한: 로컬 조회, token 불필요
- 멱등성: safe·멱등
- 정렬: 프로젝트는 Registry의 canonical 순서, snapshot 내부 entity는 각 store의 결정적 순서를 사용한다.

### 태스크 조회와 변경

| Method | Path | 목적 | 인증 | 성공 |
|---|---|---|---|---|
| GET | `/api/projects/:key/tasks` | 검색·filter·pagination 목록 | 없음 | `200` |
| GET | `/api/projects/:key/tasks/:taskId` | 단일 태스크 조회 | 없음 | `200` |
| POST | `/api/projects/:key/tasks` | 태스크 생성 | token | `201` |
| POST | `/api/projects/:key/tasks/:taskId` | 태스크 수정 | token + revision | `200` |

조회 query:

| 필드 | 위치 | 타입 | 필수 | 검증 규칙 |
|---|---|---|---|---|
| `q` | query | string | 아니요 | ID·title·summary의 대소문자 무시 부분 검색 |
| `owner` | query | MEMBER ID | 아니요 | 정확히 일치 |
| `priority` | query | enum | 아니요 | `high`, `mid`, `low` |
| `status` | query | enum | 아니요 | `todo`, `doing`, `waiting`, `review`, `done` |
| `offset` | query | integer | 아니요 | 기본 0, 음수는 0으로 정규화 |
| `limit` | query | integer | 아니요 | 기본 100, 최소 1, 최대 500 |

생성·수정 request:

| 필드 | 위치 | 타입 | 필수 | 검증 규칙 |
|---|---|---|---|---|
| `baseRevision` | body | string | 수정만 | 현재 entity revision과 같아야 함 |
| `title` | body | string | 생성 | 비어 있지 않음, 최대 1,000자 |
| `summary` | body | string | 아니요 | 최대 1,000자 |
| `status` | body | enum | 아니요 | 허용 상태만 사용 |
| `priority` | body | enum | 아니요 | `high`, `mid`, `low` |
| `owner` | body | string 또는 null | 아니요 | 등록 MEMBER ID |
| `reviewers` | body | string[] | 아니요 | 등록 MEMBER ID 목록 |
| `stakeholders` | body | string[] | 아니요 | 등록 STAKEHOLDER ID 목록 |
| `links`, `deps`, `externalRefs` | body | string[] | 아니요 | 배열이며 빈 값 제거 |
| `acceptanceCriteria` | body | object | 생성 | 하나 이상, key는 `AC-[A-Z0-9]+`, 각 text 필수 |

### 문서 조회와 본문 변경

| Method | Path | 목적 | 인증 | 성공 |
|---|---|---|---|---|
| GET | `/api/projects/:key/documents` | 문서 목록과 metadata 조회 | 없음 | `200` |
| GET | `/api/projects/:key/documents/:documentId` | 단일 문서·본문 조회 | 없음 | `200` |
| POST | `/api/projects/:key/documents/:documentId` | frontmatter를 보존한 본문 교체 | token + revision | `200` |

#### 요청

| 필드 | 위치 | 타입 | 필수 | 검증 규칙 |
|---|---|---|---|---|
| `baseRevision` | body | string | 예 | 현재 document revision과 같아야 함 |
| `body` | body | string | 예 | Markdown 본문, 프로젝트 root 내부의 표준 문서만 수정 |

저장 순서:

1. document와 revision을 다시 조회한다.
2. 원본 frontmatter byte를 보존해 임시 파일에 새 본문을 쓴다.
3. 원자적 rename 후 프로젝트 전체 strict 검사를 실행한다.
4. 실패하면 원본 file을 복원하고 오류를 반환한다.
5. 성공하면 최신 document entity와 revision을 반환한다.

### Client와 임대

| Method | Path | 목적 | 인증 | 성공 |
|---|---|---|---|---|
| GET | `/api/clients` | Workspace Client 목록 | 없음 | `200` |
| POST | `/api/clients` | Client 등록 | token | `201` |
| POST | `/api/clients/:clientId/enable` | Client 활성화 | token | `200` |
| POST | `/api/clients/:clientId/disable` | Client 비활성화 | token | `200` |
| GET | `/api/projects/:key/leases` | 유효 문서 임대 목록 | 없음 | `200` |
| POST | `/api/projects/:key/leases/:documentId/acquire` | 소프트 임대 획득 | token | `200` |
| POST | `/api/projects/:key/leases/:documentId/renew` | 소프트 임대 갱신 | token | `200` |
| POST | `/api/projects/:key/leases/:documentId/release` | 소프트 임대 해제 | token | `200` |

Client 등록 body는 `id`, `name`, `type`, `owner`를 사용하며 type은 `device|agent|service`다. 임대 변경 body는 `clientId`가 필수다. 임대의 상세 상태·만료 규칙은 `REQ-006`을 정본으로 사용한다.

### Refresh와 Sync

| Method | Path | 목적 | 인증 | 성공 |
|---|---|---|---|---|
| GET | `/api/projects/:key/sync` | HEAD, upstream, ahead·behind, dirty·conflict 조회 | 없음 | `200` |
| POST | `/api/projects/:key/refresh` | 로컬 projection 갱신과 strict 검사 | token | `200` |
| POST | `/api/projects/:key/sync` | `origin`에 save·fetch·merge·검증·push | token + Git 권한 | `200` |

sync API는 remote와 push 여부를 request로 선택하지 않고 현재 `origin`, push true로 실행한다. 세밀한 remote·`--no-push` 제어는 CLI를 사용한다.

## 응답

| 상태/코드 | 본문 | 의미 | 호출자 대응 |
|---|---|---|---|
| `200 OK` | 조회 entity 또는 변경 결과 | 요청 성공 | 반환 revision으로 local state 갱신 |
| `201 Created` | 생성된 Client 또는 태스크 | 생성 성공 | ID·commit 저장 후 snapshot 재조회 |
| `400 Bad Request` | `{ "error": "..." }` | JSON·필드·업무 검증 실패 | 입력 수정 후 재요청, 자동 반복 금지 |
| `403 Forbidden` | `{ "error": "유효하지 않은 로컬 세션입니다." }` | token 누락·불일치 | 현재 Board page의 token으로 다시 시작 |
| `404 Not Found` | `{ "error": "..." }` | endpoint 또는 entity 없음 | Registry·ID·URL encoding 확인 |
| `409 Conflict` | `{ "error": "...", "current": "<entity>" }` | base revision 불일치 | current를 표시하고 사용자 변경을 재적용할지 결정 |
| `500 Internal Server Error` | `{ "error": "..." }` | 파일·Git·예상 밖 실행 실패 | 재시도 전 작업 트리·진단 확인 |

## 오류 계약

| 오류 코드 | 조건 | 재시도 가능 | 사용자 노출 문구 |
|---|---|---|---|
| `HTTP-400-JSON` | request body가 올바른 JSON이 아님 | 입력 수정 후 | 올바른 JSON 요청이 아닙니다. |
| `HTTP-400-SIZE` | JSON request body가 64KiB 초과 | 축소 후 | 요청 본문은 64KB를 넘을 수 없습니다. |
| `HTTP-400-INPUT` | 필수 필드·enum·책임 참조·strict 검증 실패 | 입력 수정 후 | server의 구체적 validation message |
| `HTTP-403-SESSION` | `X-Rundol-Token` 누락·불일치 | 올바른 token으로 | 유효하지 않은 로컬 세션입니다. |
| `HTTP-404-ROUTE` | 지원하지 않는 method·path | URL 수정 후 | 경로를 찾지 못했습니다. |
| `HTTP-404-ENTITY` | project·document·task 없음 | 최신 목록 확인 후 | 엔티티를 찾지 못했습니다. |
| `HTTP-409-REVISION` | document·task가 조회 이후 변경됨 | merge 판단 후 | 최신 revision을 확인하세요. |
| `HTTP-500-STORAGE` | file·Git·sync 작업 실패 | 원인 해소 후 | 민감정보를 제외한 내부 오류 message |

현재 wire response에는 안정적인 machine error code field가 없고 HTTP status와 한국어 `error` 문자열만 있다. 위 `HTTP-*` 식별자는 이 문서의 계약 분류이며 response field가 아니다. 향후 code field를 추가할 때 기존 `error` field를 유지한다.

## 호환성과 버전

- API는 현재 별도 URL version을 갖지 않고 설치된 Rundol package version을 따른다.
- 기존 response field 추가는 하위 호환으로 처리하며 호출자는 알 수 없는 field를 무시해야 한다.
- 기존 field 삭제·type 변경, endpoint 의미 변경과 status code 변경은 호환성 파괴로 분류하고 새 major 또는 1.0 이전 migration을 제공한다.
- alias 성격의 `/api/tasks`, `/api/revision`, `/api/collaboration` endpoint는 기존 단일 프로젝트 UI 호환용이다. 신규 호출자는 `/api/projects/:key/*`를 사용한다.
- endpoint 폐기 시 최소 한 release cycle 동안 CHANGELOG·응답 warning 또는 문서로 대체 경로를 안내한다.
- entity revision은 opaque token이며 호출자가 hash 알고리즘이나 길이에 의존해서는 안 된다.

## 제약

- 전체 JSON request body 제한은 64KiB다. 문서 편집 함수의 별도 512KiB guard보다 transport 제한이 먼저 적용되므로 현재 API의 실질적인 document body 한도는 JSON overhead를 제외하고 64KiB 미만이다. `REQ-005`의 512KB 목표를 충족하려면 streaming 또는 endpoint별 body limit 변경이 필요하다.
- document body는 frontmatter를 제외한 Markdown이며 API가 frontmatter 교체를 허용하지 않는다.
- task 목록의 요청당 최대 반환 건수는 500개다.
- 별도 rate limit은 없지만 localhost 단일 process와 file·Git 작업의 직렬 비용을 전제로 한다.
- Board session token은 local process 경계의 쓰기 방지 수단이며 다중 사용자 host의 강한 인증을 제공하지 않는다.
- UI asset에는 CSP `default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`와 frame 차단을 적용한다.
- sync POST는 network와 Git credential에 따라 장시간 실행될 수 있으며 현재 비동기 job·cancel API를 제공하지 않는다.
- response error는 내부 경로 또는 Git detail을 포함할 수 있으므로 remote 공개 API로 노출해서는 안 된다.
