# 런돌 프로젝트 용어집

## 표기 원칙

- 제품명은 한국어 문장과 제목에서 `런돌`, package·command·고유 UI label에서는 `Rundol` 또는 실제 code를 사용한다.
- 사용자 문서의 첫 등장에서는 필요한 경우 한국어 설명 뒤에 영문 기술어를 병기한다.
- `Workspace`, `Board`, `Client`, `Lease`, `Member`는 런돌의 명시적 domain 개념일 때 대문자로 표기한다.
- Git과 HTTP의 고유 용어, file path, command, enum과 ID는 번역으로 바꾸지 않고 code style로 표기한다.
- 같은 개념에 `작업`, `과제`, `이슈`를 혼용하지 않고 런돌 canonical entity는 `태스크`로 쓴다.

## 제품과 저장 용어

| 용어 | 정의 | 사용 예 | 사용하지 않을 표현 |
|---|---|---|---|
| 런돌 | Git 저장소 안에서 문서·태스크·책임·동기화를 관리하는 로컬 우선 거버넌스 도구 | 런돌 프로젝트를 초기화한다. | 런돌 서버, 중앙 SaaS |
| Workspace | 하나의 제품 저장소에 연결된 프로젝트 등록과 Client·Lease 공유 경계 | Workspace를 먼저 동기화한다. | 워크스페이스 DB, 제품 프로젝트 |
| 프로젝트 | 독립된 헌장, 문서와 태스크를 소유하는 거버넌스 단위 | `rundol` 프로젝트의 strict 검사를 실행한다. | Git 저장소와 무조건 같은 단위 |
| 제품 브랜치 | 실제 source code와 제품 파일을 소유하는 기존 Git branch | 제품 브랜치에서 `projects/*`를 추적하지 않는다. | Workspace 브랜치 |
| Workspace 브랜치 | `rundol/workspace` ref가 가리키는 공유 설정 정본 branch | Workspace Registry를 저장한다. | main, project branch |
| 프로젝트 브랜치 | `rundol/<project-key>` ref가 가리키는 project 정본 branch | project 문서를 commit한다. | feature branch, 제품 브랜치 |
| Linked worktree | 동일 Git object store의 별도 branch를 물리 directory에 연결한 Git worktree | `projects/rundol/`에서 문서를 연다. | 단순 복사본, submodule |
| 정본 | 변경·검증·복구의 최종 기준이 되는 canonical file과 Git 이력 | Markdown file이 문서의 정본이다. | cache, snapshot |
| Projection | 정본에서 다시 생성할 수 있는 조회·호환용 파생 데이터 | task projection을 refresh한다. | 백업, 별도 정본 |
| Shard | 태스크를 Client와 segment별로 나눈 canonical JSON file | Client별 shard가 충돌 범위를 줄인다. | 임시 cache, DB partition |
| Segment | 한 shard 안에서 기본 500개 태스크를 묶는 번호 단위 | 다음 segment에 태스크를 저장한다. | page, branch |
| Registry | Workspace의 project·Client 등 공유 등록 정보 | Project Registration을 Registry에 추가한다. | npm registry와 혼용 |

## 문서와 업무 용어

| 용어 | 정의 | 사용 예 | 사용하지 않을 표현 |
|---|---|---|---|
| Artifact | PRD, 요구사항, 아키텍처처럼 ID와 표준 metadata를 가진 거버넌스 문서 | artifact related link를 검증한다. | 일반 source file 전체 |
| Frontmatter | Markdown 시작의 YAML metadata block | frontmatter의 owner를 확인한다. | header, 본문 metadata |
| Project Charter | 역할, Member, Stakeholder와 운영 원칙을 담은 `project.md` | 헌장에서 책임자를 정의한다. | PRD, Workspace manifest |
| 태스크 | 구현·검토·운영 작업과 완료 조건을 가진 실행 단위 | 태스크를 review로 전환한다. | 이슈, 티켓, 할 일 혼용 |
| 완료 조건 | 태스크가 완료됐다고 판정하기 위해 모두 충족해야 하는 검증 가능한 기준 | 모든 완료 조건을 체크한다. | 완료 정의와 무분별한 혼용 |
| Dependency | 선행 또는 연관 task 사이의 실행 의존 관계 | 미완료 dependency가 done을 막는다. | 문서 related link |
| Blocker | task 진행을 현재 막는 구체적 사유 | 인증 권한을 blocker로 기록한다. | 일반 위험, 장기 과제 |
| Related Link | artifact 간 추적 관계를 나타내는 내부 문서 link | REQ에서 PRD를 related로 연결한다. | task dependency |
| Needs Attention | 검증·검토·동기화 등 사용자의 조치가 필요한 파생 항목 | 홈에서 Needs Attention을 확인한다. | 모든 알림, 단순 정보 |
| Draft | 작성·검토 중이며 승인된 기준선이 아닌 문서 상태 | draft 요구사항을 검토한다. | 미저장 파일 |

## 협업과 동시성 용어

| 용어 | 정의 | 사용 예 | 사용하지 않을 표현 |
|---|---|---|---|
| Role | 책임 범위를 정의하는 추상 역할 | Engineering Lead Role을 연결한다. | 사람 계정, 권한 token |
| Member | 프로젝트 안에서 owner·reviewer가 될 수 있는 등록된 사람 또는 업무 주체 | `MEMBER-001`을 owner로 지정한다. | Client, 로그인 사용자와 동일시 |
| Stakeholder | 결과에 관심·영향이 있으나 task 수행자와 구분되는 참여 주체 | 승인 대상 Stakeholder를 연결한다. | 모든 Member |
| Client | device, agent 또는 service 작업 출처를 나타내는 Workspace entity | Client별 task shard를 사용한다. | 인증 계정, Member |
| Lease | 특정 Client가 문서를 편집 중임을 나타내는 만료 가능한 소프트 임대 | 문서 Lease를 갱신한다. | 영구 lock, 접근 권한 |
| Revision | entity 내용에서 계산한 불투명한 낙관적 동시성 token | base revision이 다르면 `409`를 반환한다. | Git commit과 동일시 |
| Base Revision | 변경 요청이 읽었던 entity revision | 최신 base revision으로 저장한다. | branch base, merge base |
| Stale | 읽은 이후 대상이 바뀌어 revision이 최신이 아닌 상태 | stale 편집을 덮어쓰지 않는다. | 무조건 오래된 file |
| Pending Conflict | 자동 병합하지 못해 명시적 판단을 기다리는 보존된 충돌 기록 | pending 충돌에서 ours와 theirs를 비교한다. | 임시 오류, 삭제 가능한 cache |

## 검증과 운영 용어

| 용어 | 정의 | 사용 예 | 사용하지 않을 표현 |
|---|---|---|---|
| Strict 검사 | metadata, 구조, 책임과 link를 엄격 규칙으로 검증하는 품질 gate | 저장 전에 `rdl check --strict`를 실행한다. | unit test 전체, lint와 동일시 |
| Save | 검증된 local 변경을 해당 Rundol branch commit으로 만드는 동작 | `rdl save`로 문서를 저장한다. | remote push와 동일시 |
| Sync | Workspace를 먼저 처리하고 project save·fetch·merge·검증·선택적 push를 수행하는 동작 | `rdl sync --project rundol`을 실행한다. | 단순 pull, 강제 덮어쓰기 |
| Refresh | canonical file에서 local projection과 index를 다시 만드는 동작 | 외부 편집 뒤 refresh한다. | remote fetch |
| Attach | 기존 Rundol ref와 Workspace를 현재 clone의 worktree에 연결하는 동작 | 새 clone에서 attach한다. | 새 project 초기화 |
| Doctor | runtime, package, PATH, skill, Workspace와 선택 Git URL을 진단하는 명령 | 설치 후 doctor를 실행한다. | 자동 복구 명령 |
| Clean Install | 현재 npm prefix의 Rundol package와 stale launcher만 정리하고 공식 package를 다시 설치하는 절차 | PATH 손상 후 clean install한다. | 사용자 Workspace 삭제 |
| Local-first | 핵심 생성·편집·검증이 network 없이 local canonical file에서 가능한 특성 | offline에서도 strict 검사를 수행한다. | 원격 동기화 불필요 |
| Smoke Test | 배포물을 실제 설치한 뒤 version, doctor와 최소 기능을 확인하는 빠른 검증 | tag 이후 설치 smoke test를 수행한다. | 전체 회귀 test |
| Rollback | 검증된 이전 실행 version 또는 보존된 정본으로 운영을 회복하는 절차 | package를 이전 version으로 설치한다. | Git 이력 강제 삭제 |

## 혼동 방지 규칙

- `Client`와 `Member`: Client는 작업 출처, Member는 책임 주체다. 둘을 인증 계정으로 간주하지 않는다.
- `Revision`과 `Commit`: revision은 entity 내용 token, commit은 branch 전체 변경 이력이다.
- `Save`와 `Sync`: save는 local commit, sync는 remote fetch·merge·검증과 기본 push까지 포함한다.
- `Refresh`와 `Sync`: refresh는 local projection 재생성이고 remote network 작업이 아니다.
- `Lease`와 `Lock`: Lease는 만료되는 협업 신호이며 file 접근을 강제로 차단하지 않는다.
- `Projection`과 `정본`: projection은 언제든 삭제·재생성 가능하며 복구 기준으로 단독 사용하지 않는다.
- `Workspace`와 `프로젝트`: Workspace는 여러 project 등록과 공유 협업 상태를 소유하고 project는 자체 문서·task를 소유한다.
- `오류`와 `경고`: 오류는 저장·동기화를 막고, 경고는 조치가 필요하지만 계약에 따라 진행 가능할 수 있다.
